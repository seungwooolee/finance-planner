## 1. 해결할 사용자 문제와 범위

가상 사회초년생이 주거자금을 준비하다 소득 감소를 겪는 사례를 **입력 → 진단 → 세 계획 비교 → 이번 달 행동 → 상황 변화 후 재계산 → 부족 안내·변경 후보**로 연결한다. 질문은 기본 결과에 필요한 만큼 먼저 묻고, 지급일·투자·변경 허용은 해당 결과에 필요할 때 확장한다.

현재 Next.js/FastAPI/Decimal 구조를 재생성하지 않는다. 기존 엔진의 일정 소득·지출, 보증금 반환, 보호자산 제외와 고정 정답을 유지한다. PORTMEW 계산을 기존 단일 계획 함수에 조용히 덮어쓰지 않는다. 기존 화면 구성과 투자 기능이 있는 작업 브랜치는 개발 checkout에서 추가 확인한다.

## 4. 고정 정답과 방지 조건

[representative-case.json](../../data/portmew/representative-case.json)은 앱 요청이 아닌 개발용 자료다. 모든 금액은 정수 원 문자열이고, 반복 기간의 월별 기대 배정은 고정 정답에서 전개했다. 미래 납입은 SIMULATED, 고객 허용은 예시이며 실제 동의가 아니다.

필수 방지 조건은 POL-FIN-1.2 FIN-31~44와 보고서 제11절 PV-01~30을 사용한다. 생활비1450000으로 이중 감축, 목표 총납입700000에 기존200000 재가산, 자산 목적 초과배정, 과거 이력 덮어쓰기, 월 대사만으로 목표 성공 표시, 날짜 미확인 상태의 안전 판정, 미동의 목표 변경, 오래된 미리보기 채택을 차단한다. 유효 입력의 자금 부족은422가 아니고, 내부 계산 불일치는 고객 입력 오류가 아니다.

기존78개 pytest/14개 Playwright는 과거 문서의 기록이며 이번 실행 결과가 아니다. 새 테스트는 제품 엔진/API를 호출하고, 기대값을 같은 구현에서 생성하지 않는다. fixture 자체 검산을 앱 통과 근거로 대신하지 않는다.

## 6. 구현에서 남길 근거

입력·정책·출처·계획·목표 버전, 실행자, 실행 시각, 검사 명령·결과, 미실시 이유를 기록한다. AIQC-01은 사람이 실제 검토한 기록, AI의 별도 계산, 실제 앱 시험, 전문가 검토를 구분한다. 예상 효과나 수행하지 않은 채택을 완료로 표시하지 않는다.

LS는 신형 OPEN API 선정까지 완료됐다. 실제 응답·공표시각·수집시각·이용권한·비용 확인 후 연결한다. P1~P5는 자기보고 임시 표시, score=null이다. 최종 배분·적합성·세율 미검증을 기본 진단 전체의 중단 사유로 삼지 않는다.
