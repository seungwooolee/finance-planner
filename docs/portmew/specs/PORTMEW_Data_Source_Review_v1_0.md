# PORTMEW 데이터 공급원 검토안 v1.2

작성일: 2026-11-02\
상태: **LS OPEN API를 1차 공급사로 사용자 선정 완료 / 실제 연동·품질·권한·비용은 확인 전**\
목적: 재무계획과 연결된 투자제안에 사용할 자료·API를 비교하고, 실제 채택 전에 확인할 조건을 정한다.

공식 공개 문서와 공지를 조사했다. API 키를 사용한 실제 호출, 지연·장애 성능 측정, 유료 견적, 공급사별 외부 서비스 이용 승인은 아직 확인하지 않았다. 이 문서의 후보 선정은 최종 도입 확정과 다르다.

## 0. 현행 결정 — 2026-11-02

사용자 지시 ‘좋아 그럼 ls로 해서 재무계산하기 전에 모든 데이터 총 정리해자’에 따라 **LS증권 신형 OPEN API를 1차 시세·ETF 구성조회 공급사로 선정**한다. 이전 공급사 비교는 선정 근거·대안 이력이며, 결정을 다시 기다리는 상태가 아니다.

선정은 개발 기준 공급사에 대한 결정이다. API 키 발급·실제 접속·대표 종목 응답·ETF 구성 범위·성능·외부 서비스 이용권한·비용까지 검증됐다는 뜻은 아니다. 키움·DB·한국투자·대신은 대안 이력으로 남기고 최초 구현은 LS 한 곳을 기준으로 정리한다.

전체 데이터의 현행 통합 기준은 [데이터·설계 인계서 제17절](https://chatgpt.com/library?file_id=libfile_86565dc77ae48191beb12fbb8026ee71&account_id=personal)이다. 고객 필드·금액/날짜·정책·결과·계산 시작 조건을 한곳에 연결했다.

## 1. 원천 구성과 선정 이력

1. **시세·ETF 구성 조회의 개발 기준 공급사는 LS OPEN API다.** 다른 증권사 비교는 대안 이력으로 보존한다.
2. LS의 REST·WebSocket 및 ETF 구성조회 기능을 현행 설계에 연결한다. 신형 OPEN API를 사용하며 설치형 xingAPI와 혼동하지 않는다. LS 선정은 공개 문서상 기능 적합성과 사용자 결정에 따른 것이며 실측 안정성·최저비용 순위가 아니다.
3. **국내 기업 재무·공시는 OpenDART를 우선 원천으로 검토한다.** 증권사 가공 재무·투자의견은 필요한 경우 보조 자료로 비교한다.
4. **ETF 구성은 LS 조회 API를 우선 검증하고, 비용·운용방식·분배 조건은 운용사 공식 자료로 확인한다.** API에 ‘구성종목’이라는 이름이 있다고 실제 위험 노출 전체를 확인한 것으로 간주하지 않는다.
5. **거시·산업 자료는 ECOS·KOSIS**를 검토한다. 실시간 시세와 최신 발표 통계를 서로 다른 최신성 기준으로 관리한다.
6. 선정한 LS의 실제 사용 범위·시세 표시·계산 이용·저장·재배포 권한과 비용을 확인한다. 필요한 경우 KRX·코스콤의 계약 경로를 검토한다. 충족하지 못하면 대안 검토 사유를 남기며 공급사를 조용히 바꾸지 않는다.

이번에 상세 비교한 대상은 국내 상장 주식·ETF 관련 자료다. 일부 증권사는 해외주식 API도 제공하지만, 해외 개별기업의 공시·재무·상품 데이터까지 검증을 마친 것은 아니다. 투자 대상의 최종 범위를 이 문서로 임의 확정하지 않는다.

‘1차 검증 후보’는 무조건 무료·무제한·공개 서비스 사용 가능을 의미하지 않는다. 각 API 이용과 외부 고객 대상 서비스에 필요한 조건을 따로 확인한다.

대체 증권사가 있다는 점은 KIS 특정 API 종료 위험을 줄일 수 있다. 다른 증권사의 가공 재무가 동일한 상위 데이터 업체에 의존하는지도 확인해야 하며, 공급사 이름이 달라졌다는 이유로 독립된 원천이라고 가정하지 않는다.

## 6. 최신성·품질 처리 설계

이 절은 조사 결과를 바탕으로 한 **제안 설계**다. 제공사의 실시간 무오류 보장을 뜻하지 않는다.

### 6.1 공통으로 보관할 기준

| 구분 | 기록 |
| --- | --- |
| 출처·식별 | 공급사, 원문 URL/접수번호, 종목 식별자, 시장/거래소 |
| 시점 | 시세 관측시각, 재무 대상기간, 공시·발표시각, 수집시각, 마지막 최신성 확인시각을 각각 기록 |
| 의미 | 통화·단위, 연결/별도, 누적/분기, 수정주가 여부, 구성자료 유형·적용일 |
| 검증 | 원문 버전, 정정 관계, 누락·검증 결과, 데이터 지연 여부, 이용권한 상태 |

최신 데이터를 다시 받았더라도 원래 보고기간을 현재 날짜로 바꾸지 않는다. 계좌·시세 키는 서버에서 관리하며 고객 화면·공개 코드·대화에 노출하지 않는 구조로 정한다.

### 6.2 자료별 갱신

- **시세:** 허용된 실시간 구독을 유지하고 재연결·누락 여부를 점검한다. 휴장·무체결·정지와 장애를 구분한다. ‘실시간’ 표시의 지연 허용치는 실제 공급 조건과 시험 결과로 정한다.
- **공시·재무:** 공시 목록을 허용 범위 내에서 반복 확인하고, 제안 생성 전에 새 공시·정정 공시 존재 여부를 재확인한다. 공시 탐지부터 수집까지 걸리는 지연도 기록한다.
- **ETF:** 자료마다 구성 기준일·운용 조건 적용일을 검사한다. 설정 바스켓(Portfolio Deposit File)과 실제 보유자산·파생상품 위험 노출을 자동으로 동일시하지 않는다.
- **통계:** 최신 관측기간과 수정 이력을 확인한다. 산업의 월별 통계가 어제 수집됐다는 이유로 어제 산업 상황의 실시간 측정값이라고 설명하지 않는다.
- **재계산:** 새 자료가 어떤 기업·ETF·지표·제안에 영향을 주는지 연결해 해당 결과를 다시 계산한다. 기존 고객의 채택 계획을 자동으로 바꾸지 않고 수정 근거와 새 버전을 제시한다.

### 6.3 실패·불일치 시 처리

1. 최신성 확인 실패, 필수 값 누락, 단위·기간 불일치는 관련 분석·상품 제안을 보류하고 사유를 표시한다.
2. 이전 자료를 이력으로 보여줄 수 있는 경우에도 기준일과 현재 검증 실패 상태를 함께 표시한다. 이를 현재 최신 결과로 바꿔 부르지 않는다.
3. 구성자료가 일부만 확인된 ETF는 중복·집중 위험이 모두 검증됐다고 표시하지 않는다. 미확인 노출의 처리 정책이 준비되지 않았으면 해당 판단을 보류한다.
4. 비교 공급사 값이 다르면 거래소·KRX/NXT/통합 구분, 관측시각·거래 상태·수정 방식부터 대조한다. 단순 평균이나 무조건 한 공급사 우선으로 덮어쓰지 않는다.
5. 데이터 문제의 영향을 받지 않는 재무계획 결과까지 일괄 차단하지 않는다. 영향 범위별로 상태를 설명한다.
6. 정확하고 최신인 시세를 얻어도 배분 정책·적합성·기대수익률의 타당성이 자동 검증되는 것은 아니다. 기존 정책 검증 조건을 유지한다.

## 10. 증권사·시세 선택과 별도로 준비할 데이터 — v1.1 추가

## 11. 자료별 구체적인 수집·갱신 설계

### 11.1 기업 재무·공시

- 공시검색의 기간·회사 조건으로 새 보고서와 정정 여부를 확인하고, 관련 보고서 접수번호를 보관한다. 최종보고서 조회만 남겨 원래 보고서와 수정 이력을 지우지 않는다 [S16].
- 회사·사업연도·보고서·연결/별도·계정·대상기간을 함께 식별한다. 서로 다른 회사/기간/연결 범위의 숫자를 섞지 않는다 [S15].
- 누적 실적과 단독 분기를 구분한다. 차감으로 단독 분기를 구할 때는 동일한 회계 범위·통화·기간·정정 버전인지 확인한다.
- 회사별 계정명이 다르거나 필수 항목이 없으면 공시 원문을 확인하고 해당 지표를 보류한다. AI가 빈칸에 그럴듯한 숫자를 넣지 않는다.
- 보고서·통계의 공개 시점 이후에만 그 자료를 사용한 분석으로 기록한다. 과거 검증에서 당시 공개되지 않은 새 정정치·실적을 미리 알았던 것처럼 사용하지 않는다.

### 11.2 ETF·비용·분배

- 후보 상품별로 공식 문서 URL·문서 버전·적용일과 수집 경로를 등록한다. 국내 전 ETF의 자동화·이용권한을 일괄 확보했다고 가정하지 않는다.
- 구성조회 API의 응답이 실제 보유, 설정 바스켓, 지수 구성 중 무엇인지 확인한다. 합성·재간접·파생상품·현금의 미확인 노출을 표시한다.
- 펀드 내부에 이미 반영된 비용과 별도 청구 거래비용을 구분한다. 총수익 자료에 포함된 분배금이나 비용을 다시 더하고 빼지 않는다.
- 분배 공지의 금액·귀속 기준·지급일·통화를 별도 저장한다. 과거 분배율을 앞으로의 보장 현금소득으로 설명하지 않는다.
- 자동 제공 경로를 검증하지 못한 필수 항목은 확정 추천의 근거에서 빼거나 관련 결과를 보류한다. 날짜가 지난 수동 파일을 자동 최신 자료처럼 사용하지 않는다.

### 11.3 금리·환율·물가·산업 통계

초기 지표 후보는 한국은행 기준금리, 필요한 만기의 시장금리, 주요 통화의 대원화 참고 환율, 소비자물가, 고객이 관심을 둔 산업의 관련 생산·출하·재고 등이다. 모든 통계를 한꺼번에 수집하지 않는다.

- ECOS 세부 시계열 코드·항목 코드·주기·표시 단위는 공식 메타데이터와 실제 응답을 대조해 등록한다. 이번 조사에서 확인하지 못한 코드를 추측해 확정하지 않는다.
- KOSIS는 기관·통계표·분류·항목·주기·기간을 함께 지정한다. 동일 지표도 원계열/계절조정, 지수/증감률, 기준연도가 다르면 구분한다 [S28].
- 산업 지표는 산업분류와 기업의 사업구조를 연결한다. 기업 전체를 한 산업에 강제 배정하거나 고객이 선호한 산업이라는 이유로 평가를 올리지 않는다.
- 관측기간·원천 갱신일·수집일을 나눠 보관한다. 현재 공개된 최신 관측기간이 무엇인지 확인하고, 새 자료가 공개됐는데 미반영됐는지 구분한다.
- 100단위 외화 표시 등 환율의 분모 단위를 보관한다. 참고 환율로 평가한 원화 금액과 실제 환전 후 받을 금액을 구분한다 [S30].
- 과거 소비자물가 상승률은 미래 주거비 상승률이 아니다. 목표가 이미 미래 명목금액으로 입력됐다면 추가 물가를 자동으로 곱하지 않는다.

### 11.4 세금·계좌·서비스 정책

**공식 원문 수집·변경 탐지와 계산 규칙의 활성화는 다른 단계로 설계한다.**

1. 공식 출처와 조문·상품 조건을 수집하고 확인일을 남긴다.
2. 상품·계좌·거주자·과세연도·과세사건별 적용 조건과 유효기간을 표로 정리한다.
3. 필요한 입력·계산식·경계 사례를 검산하고 검토 근거를 남긴다.
4. 검증한 규칙만 해당 유효기간에 적용한다. 적용 가능 여부가 불명확하면 관련 세후 결과를 보류한다.
5. 규정 변경을 탐지하면 영향받는 규칙을 재검토한다. 새 발표·시행 예정·현재 시행·과거 적용을 구분한다.

여기서 새로운 세율이나 공제금액을 확정하지 않는다. 국세청 안내를 확인했더라도 개별 ETF·계좌의 모든 과세 규칙 검증이 끝난 것은 아니다. 현재는 필요한 규칙표의 구조와 공식 근거 경로를 준비한 상태다.

보호기간·배분 상한·스트레스·기대수익률도 정책 데이터로 관리한다. 최신 산업 뉴스나 최근 주가 상승률을 곧바로 고객별 기대수익률로 사용하지 않는다. 기본 재무계획의 수익 0% 비교와 투자 시뮬레이션의 가정을 명확히 구분한다.

| 기타 해외시장 | 해당 국가 공시기관·거래소·검증한 시장/기업 공급자 | 이번 조사에서 전체 국가의 자료를 확보했다고 주장하지 않음 |
| 실제 주거비·매물 추천 | 주거 지역·주택 조건·거래/임대 정보 및 권한 | 별도 기능으로 범위가 정해질 때 검토. 현재 주거 목표금액·필요일은 고객 입력으로 유지 |
| 은행·증권 계좌 자동연동 | 고객 동의·정당한 접근권한·계좌별 데이터·연동 계약 | 직접 입력을 보완하는 후속 경로. 시세용 API 키만으로 타 고객의 은행·증권 자산 전체를 가져올 수 있다고 가정하지 않음 |
| 유료 컨센서스·보고서 | 상품별 라이선스·작성일·추정 기준·보관/가공/외부 이용 범위 | 핵심 사실 원천을 먼저 마련하고 필요한 분석 공백을 확인한 뒤 비용 대비 채택 검토 |

SEC 공시의 빠른 갱신은 ‘기업의 현재 재무 상태가 초 단위로 측정된다’는 뜻이 아니다. 공개된 보고서의 재무기간과 공시일을 유지한다.

## 13. Codex에 전달할 데이터 준비 순서와 산출물

앞의 1~6은 설계 산출물이며, 이 문서에서 모든 표의 실제 값·API 응답·검산 예를 완성했다는 주장은 아니다. 코딩은 이후 Codex에서 진행한다.

데이터 등록부의 필수 열은 다음과 같다.

| 영역 | 필드 |
| --- | --- |
| 식별 | dataset_id, source_id, entity_id, 지원 시장·상품 |
| 출처 | 제공 기관, API/문서 경로, 원문·접수번호, 사용권한·조건 |
| 의미 | 필드명, 단위·통화, 보고기간/통계주기, 연결·조정·구성 기준 |

| 처리 | 표준화 규칙, 누락 처리, 검증 조건, 저장·재사용 조건 |
| 의존 | 해당 자료를 사용하는 계산·화면·정책, 변경 시 재계산 대상 |
| 확인 상태 | 문서 확인 / 실제 응답 확인 / 품질 확인 / 사용권한 확인을 별도 기록 |

현재 시점은 ‘필요 데이터·원천 후보·처리 규칙 정리’다. 실제 자료 파일 다운로드, 전체 ETF 목록 확정, 전 산업 지표 코드 등록, 유료 데이터 계약, 실제 API 시험 완료와 구분한다.

## 14. 필수 검증 사례 제안

다음은 설계에 포함할 **검증 조건**이며 실제 앱 시험 통과 기록이 아니다.

| 사례 | 기대 동작 |
| --- | --- |
| 소득 감소 | 고객이 입력한 새 소득으로 가용 재원을 다시 계산. 목표·생활비·허용 조정을 무단 변경하지 않음 |
| 재무 정정 | 원래 공시와 정정 공시를 연결하고 영향 지표를 새 버전으로 계산. 과거 결과는 보존 |
| 재무 기간 불일치 | 누적/단독 분기·연결/별도·통화가 맞지 않으면 잘못된 성장률·비율을 내지 않음 |
| 환율 분모 | 계산용 가정으로 100엔=940원일 때 10,000엔=94,000원. 이 값은 현재 환율 자료가 아님 |
| ETF 일부 구성만 확인 | 미확인 비중을 0으로 만들지 않고 집중도 검증 범위를 표시 |
| 분배·비용 중복 | 분배 재투자를 포함한 총수익과 별도 현금 분배를 중복 반영하지 않음 |
| 세금 규칙·취득가 미확인 | 세전 결과의 범위를 설명하고 확정 세후 금액을 생성하지 않음 |
| 통계 개정·수집 실패 | 자료 기준일과 확인 실패를 구분. 과거 발표치로 계산한 결과를 현재 최신 결과로 가장하지 않음 |
| 대표 사례 부록 | 고객 입력·자료 버전·계산 정책·수정 이유·검증 주체·실제 실행 증거를 재현 가능하게 연결 |
