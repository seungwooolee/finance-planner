## 1. 고객 경험의 공통 규칙

### 1.1 질문을 보여주는 순서

| 단계 | 화면 카드 | 제공되는 결과 |
| --- | --- | --- |
| 기본 현황 | C01 기준 → C02 자산 → C03 부채 → C04 생활 흐름 | A 자산·B 금융자산·현재 월 잉여금 |
| 목표 준비 | C05 목표 → C06 사용 가능 시점·준비금 → C07 보호자금 | C 목표 현황·필요 월 적립액 |
| 실행계획 | C08 기존 납입·월 여유금 → C09 조정 범위 → C10 지급일 | D 세 계획·P 목적별 배분 |
| 투자 상세 | C11 투자 선호·생활 영향 → C12 제외·산업 → C13 보유 상세 | I 선호·적합 범위·산업 / P 투자구성 |
| 선택 심화 | C14 세금·비용 | 지원 범위 내 세전/세후 비교 |
| 채택·점검 | C15 계획 선택 → C16 실제 실행 | X 이번 달 할 일·원안/실적/수정안 |

이는 최대 화면 묶음이며 16문항을 의미하지 않는다. 카드 안의 입력칸 수와 반복 내역 수는 별도로 센다. 이미 답한 같은 정보는 재질문하지 않고 수정 링크를 제공한다. C11~14는 기본 자산·목표 결과를 보기 위한 일괄 선행 조건이 아니다.

### 1.2 공통 선택지·형식

- 금액 입력칸은 ‘만원’ 또는 ‘원’을 명시한다. 만원 입력 300은 3,000,000원으로 정규화하고 확인 화면에 정확한 원 단위를 보여준다. API는 원 단위 십진 문자열이다.
- 없음은 **0원·KNOWN**, 모름은 **null·UNKNOWN**, 아직 묻지 않은 값은 **null·NOT_ASKED**다. ‘나중에 입력’은 null을 유지하고 omission_reason=LATER로 기록한다. 응답 거절은 omission_reason=DECLINED로 별도 보존한다.
- 금액칸은 0 이상이다. 순자산·월 잉여금·실제 손익의 음수는 계산 결과에서 허용한다.
- 다중선택의 ‘없음’, ‘잘 모르겠어요’는 다른 항목과 함께 선택할 수 없다. 관심 산업 0개 선택과 미응답은 상태로 구분한다.
- 필수란 해당 결과를 계산하는 데 필요하다는 뜻이다. 모름을 선택했다고 다른 현황까지 막지 않는다. 분석 범위처럼 기준 자체가 필요한 항목은 임시저장만 허용하고 결과를 확정하지 않는다.
- 구간형 기간을 정확한 날짜로 조용히 변환하지 않는다. 날짜를 모르면 기간 참고값만 저장한다.
- 고객에게 내부 상태 코드를 그대로 노출하지 않는다. ‘월 상환액을 확인하면 계산할 수 있어요’처럼 필요한 항목을 말한다.

### 1.3 식별자 계약

아래 UI-ID는 **화면 사양의 참조 ID**다. 기존 질문의 영속 Q-ID와 다르다. 코드의 실제 필드는 이전 인계서의 개념 경로와 매핑하되 기존 키를 강제 변경하지 않는다. 최신 활성 질문 원장을 대조하기 전에는 새 Q-ID를 선점하지 않는다.

보존할 연결: 구 Q12 하락 행동 / 통합 Q-045 loss_response, 구 Q33 생활영향 / 통합 Q-122, 구 Q15 부채 / 통합 Q-032, 구 Q35 상품 제외 / 통합 Q-123. 구 Q32 최대손실률은 신규 설문 비활성 방향이며 통합 Q-032 대출잔액은 삭제하지 않는다.

| FIN-20 | 신규 투자 후보액은 원장의 잔여·사용기간·보호·목표·지급일을 모두 확인한 범위만 | 투자 적합성 정책이 없으면 자금 후보와 최종 투자 가능 판단을 분리 |
| FIN-21 | 현재 보유 투자와 신규 투자 제안은 별도 | 보호부족이 있다고 기존 투자 잔액을 삭제하거나 자동 매도하지 않음 |
| FIN-22 | 불명확한 부채금리·비용·세금으로 최적 추가상환을 자동 생성하지 않음 | 고객 지정 추가상환 비교는 검증 가능한 비용 범위에서 별도 제공 |
| FIN-23 | 목표 수정은 원목표와 분리 | 날짜 연장·금액 축소는 허용 범위 안의 새 미리보기, 원목표 성공으로 표시 금지 |

### 4.3 세 계획의 정확한 순서

매 납입기간마다 최신 잔여 부족액과 남은 횟수로 재계산한다. 소득·생활비가 바뀌지 않는 정액 fixture에서도 마지막 회차와 충족 시점 때문에 월별 금액이 달라질 수 있다.

공통 선행 처리:

1. 실제 지급·계약상 의무·월 여유금·계좌 제한의 충돌을 확인한다.
2. 기존 납입 K를 목적별로 연결한다. 고정 목표 납입 g_fixed는 목표의 월 적립액 일부이며 g_req에 다시 더하지 않는다.
3. 고정 보호 납입도 p_req의 일부다. 추가 필요분은 max(0,p_req−p_fixed)다.
4. 다른 목적의 유지 납입을 k_other라고 하면, 월 예산에서 먼저 반영하고 남은 금액을 아래 순서로 배정한다. K>B이면 부족을 표시하고 기존 납입을 무단으로 줄이지 않는다.
5. 계약상 중단불가 저축의 초과액도 해당 월 재원에서 차감한다. 이 단순화 범위를 벗어나는 납입은 명시적으로 모델 확장·확인 필요 상태다.

| 계획 | 추가 배정의 순서 | 금액·반응 |
| --- | --- | --- |
| PORT-01 안정 우선안 | 기존 유지납입 → 남은 보호부족을 가능한 한 먼저 보충 → 남은 목표부족 추가 적립 → U | 보호를 p_req보다 빨리 채울 수 있음. 원목표 기한 충돌은 숨기지 않고 부족액 표시 |
| PORT-02 현재 생활 유지안 | 기존 유지납입 → 부족한 최소 보호보충액 → 생활비·월 여유금·다른 고정조건을 유지하며 목표의 필요액까지 추가배정 → 나머지는 U | 기존 납입만 유지한 현황과 분리. 목표 추가배정은 계획 미리보기이며 실제 이체·기존 계약 변경이 아님 |
| PORT-03 목표 달성 우선안 | 기존 유지납입 → 최소 보호보충 → 기한에 필요한 목표적립 → U | 부족하면 허용 지출감축만 필요한 만큼 적용. 허용한 기존 납입 조정은 별도 설명되는 변형안 |

현재 납입현황 BASELINE은 원본 응답 그대로 보존한다. PORT-02는 그 현황과 같은 생활비·의무상환·월 여유금·유지 납입을 사용하되, 미배정 여력에서 목표에 추가 배정할 수 있는 금액도 보여준다. 목표 배정은 g_req까지이며 무조건 잔액 전부를 넣지 않는다. 고객이 채택하기 전에는 실제 보유액이나 자동이체 설정을 바꾸지 않는다.

기존 납입이 모름이면 유지 의무 K를 확인한다. 없음이라고 확인한 경우 g_fixed=0으로 시작하되, 목표를 위해 새로 배정할 수 있는 여력까지 0으로 취급하지 않는다. 납입액 증가가 제한된 계약이면 추가배정을 별도 목표저축으로 구분한다. 같은 재원으로 다른 필수 목표·유지 납입을 침해하지 않는다.

### 4.4 대표 목표 한 건·고정 보호납입 없음의 검산 식

검산 사례의 단순화 범위: 고정 목표납입 g_fixed, 다른 유지납입 k_other, 보호 잔여 P, 목표 잔여 G, 고객 여유금 H, 감축한도 C. 모든 금액은 원 단위다. 아래 정액 식은 전체 일정모형을 대체하지 않는다.

| 계산 | 식 |
| --- | --- |
| 원래 월 잉여 | S=I−E−D |
| 원래 계획 예산 | B=max(0,S−H) |
| 목표 우선안 필요예산 | B_need=k_other+p_req+max(g_fixed,g_req) |
| 목표 우선안 감축액 | c=min(C,max(0,B_need−(S−H))) |
| 감축 후 예산 | B'=max(0,S+c−H) |
| 안정안 보호배정 | p=min(P,B−k_other−g_fixed) |
| 안정안 목표배정 | g=g_fixed+min(max(0,G−g_fixed),B−k_other−g_fixed−p) |
| 생활유지안 보호배정 | p=min(p_req,B−k_other−g_fixed) |
| 생활유지안 목표배정 | g=g_fixed+min(max(0,g_req−g_fixed),B−k_other−g_fixed−p) |
| 목표우선안 보호배정 | p=min(p_req,B'−k_other−g_fixed) |
| 목표우선안 목표배정 | g=g_fixed+min(max(0,g_req−g_fixed),B'−k_other−g_fixed−p) |
| 미배정 | U=적용예산−k_other−p−g |

음수 잔여 예산인 경우 위 min 식에 그대로 넣지 않는다. S+c<H 또는 K>적용예산이면 해당 고정조건이 실행불가이며, 대체 배정안을 가능한 원안으로 출력하지 않는다. 감축 전 적자가 있으면 먼저 그 적자와 월 여유금까지 충족해야 하므로 감축액 산정에 max(0,S−H)만 사용하는 오류를 피한다.

위 식의 g_fixed가 잔여 목표금보다 큰 마지막 회차에는 UI-08-03에서 확인한 종료 규칙을 적용한다. 초과 납입을 유지하면 초과분은 k_other의 미배정 저축으로 대사한다. 중단 확인 없이 그 돈을 신규 자유재원으로 바꾸지 않는다.

감축한도가 부족한 경우 보호 최소액을 우선 보충하고 남는 금액까지만 목표에 배정한다. 부족한 목표액은 유지하며 원목표의 기한 충족은 실패로 표시한다. 정책이 고객 허용 한도보다 더 줄이도록 계산하면 오류다.

### 4.5 날짜·상태·채택

| 정책 ID | 확정한 규칙 |
| --- | --- |
| FIN-24 | 월 합계와 별개로 실제 지급 시점의 사용가능 현금을 검증. 보호·목표에 묶인 돈을 자유현금으로 중복 사용하지 않음 |

원목표에 실패한 계획도 비교용으로 보여줄 수 있다. 이 경우 ‘기한 내 목표자금 부족’과 금액을 명시하고 ‘목표 달성 가능한 계획’으로 채택시키지 않는다. 고객이 부족을 인지해 목표를 바꾸면 수정 목표에 대한 새 계획을 만든다.

## 5. 가상 고객으로 정책 검산

### 5.1 기존 기준 사례 유지

개인 자산 2,000만원·부채 1,000만원·월소득 300만원·생활비 180만원·의무상환 30만원·필수생활비 120만원인 사례다. 현금에서 목표금 600만원, 보호금 900만원을 배정하면 장기자금 후보는 500만원이다. 보호 6개월은 이 사례의 고객 선택값이라는 가정이다.

순자산 1,000만원, 월 잉여 90만원, 보호목표 (120+30)×6=900만원이 각각 맞는다. 500만원은 최종 투자추천액이 아니며 정책·기간·지급일 검증을 거쳐야 한다.

### 5.2 세 계획을 비교할 새 사례

아래는 정책 차이를 확인하는 별도 fixture이며 실제 추천 사례가 아니다.

| 입력 | 가정 |

| 월 세후소득 I | 300만원 |
| 현재 준비금 원천 | 초기 현금 1,200만원 중 보호 600만원·목표 600만원으로 중복 없이 배정, 두 자금의 가용성은 확인됐다고 가정 |

| 월 여유금 H | 고객 확인 10만원 |

#### 첫 달의 배분

단위: 만원/월. 보호·목표 배정은 기존 납입을 포함한 총액이다.

| 항목 | 안정 우선안 | 현재 생활 유지안 | 목표 달성 우선안 |
| --- | ---: | ---: | ---: |
| 생활비 | 180 | 180 | 165 |
| 의무상환 | 30 | 30 | 30 |
| 월 잉여 | 90 | 90 | 105 |
| 별도 월 여유금 | 10 | 10 | 10 |
| 보호자금 적립 | 60 | 25 | 25 |
| 목표 적립 합계 | 20 | 55 | 70 |
| 그중 기존 목표 납입 | 20 | 20 | 20 |
| 미배정 | 0 | 0 | 0 |
| 실제 사용한 지출 감축 | 0 | 0 | 15 |
| 첫 달의 대사 | 60+20+10=90 | 25+55+10=90 | 25+70+10=105 |

목표 우선안은 20만원 전부를 줄이지 않는다. 부족한 월 예산 15만원만 줄이면 보호 25만원·목표 70만원·여유 10만원을 확보할 수 있다. 기존 목표 20만원은 70만원 안에 포함되므로 추가 20만원을 다시 차감하지 않는다.

#### 12회 납입 후

| 결과 | 안정 우선안 | 현재 생활 유지안 | 목표 달성 우선안 |
| --- | ---: | ---: | ---: |
| 보호금 추가 확보 | 300만원 | 300만원 | 300만원 |
| 목표 추가 확보 | 660만원 | 660만원 | 840만원 |
| 원목표 기한 부족액 | 180만원 | 180만원 | 0원 |
| 월 예산 누적 미배정 | 0원 | 0원 | 0원 |
| 원목표 기한 판정 | 부족 | 부족 | 0% 가정에서 충당 |

안정안은 첫 5회에 보호 60만원·목표 20만원, 이후 7회에 목표 80만원을 배정한다. 따라서 목표 추가 확보는 5×20+7×80=660만원이다. 첫 달의 20만원을 12개월 내내 고정하여 계산하면 안 된다.

수정 전의 현재 납입현황은 목표 월20만원·미배정 월35만원이다. 이 현황의 목표 부족액 600만원은 기록으로 남기고, PORT-02에는 같은 생활비에서 목표 월55만원을 배정하는 미리보기를 표시한다. 그 결과 12회 후 부족액은 180만원이다. 이를 실제 이체·납입 완료로 기록하거나 미배정420만원을 별도 수익으로 더하지 않는다.

세 안을 모두 ‘추천 성공’으로 만들지 않는다. 안정안은 보호금 확보가 빠르고, 생활유지안은 같은 생활비 안에서 최소 보호보충과 목표 적립을 병행하며, 목표우선안은 허용한 감축을 사용한다. 안정안과 생활유지안은 최종 부족액이 같아도 자금 확보 시점이 다르다. 투자수익률이나 위험등급으로 차이를 만들지 않는다.

### 5.3 감축 한도가 작은 경우

같은 고객이 월 10만원까지만 감축을 허용하면, 목표 우선안은 보호 25만원·목표 65만원·월 여유 10만원이 된다. 12회 목표 추가 확보는 780만원이고 원목표 부족액은 60만원이다. 더 줄이거나 목표를 축소했다고 가정하지 않는다. 원목표는 충당 실패 상태로 유지하고 허용 범위의 기간·금액 수정안을 따로 보여준다.

## 8. 외부 근거와 적용의 한계

- 미국 CFPB의 비상자금 안내는 필요한 금액이 개인 상황에 따라 다르고, 비상용 현금은 사용하기 쉬운 형태로 확보하는 것이 중요하다고 설명한다. 여기서는 고객별 목표와 가용성을 별도로 받는 설계 근거로 참고했다. [공식 안내](https://www.consumerfinance.gov/an-essential-guide-to-building-an-emergency-fund/), 2026-11-02 확인.
- 미국 워싱턴주 금융기관국의 안내는 개인의 소득·지출·가구에 따라 금액이 달라지며 3~6개월 기본생활비를 일반적인 참고 범위로 소개한다. 한국 고객의 적정 개월을 검증한 근거로 사용하지 않는다. [공식 안내](https://dfi.wa.gov/financial-education/information/importance-having-emergency-savings-account), 2026-11-02 확인.
- 3·6·12개월 버튼은 비교 입력을 돕는 제품 선택지다. 12개월을 특정 기관의 보편 권고라고 주장하지 않는다. 필수생활비+의무상환 기초, 세 계획의 배정 순서, 감축 최소화는 이번 제품의 명시적 설계 결정이다.

세율·상품 제공 권한·투자배분은 기존 기준서의 별도 검토 항목이다. 이 문서에서 새로운 세율이나 법적 면제 주장을 추가하지 않았다.

## 10. v1.1 수정·재검산 기록

수정 대상은 계획 비교의 공정성이다. 현재 고객이 실제 납입하는 BASELINE을 보존하고, 세 계획은 각각 같은 정보·생활비·고객 여유금에서 가능한 미리보기로 생성한다. 목표 적립에 사용할 수 있는 미배정 여력을 제외하여 PORT-02를 불리하게 보이게 하지 않는다.

| 구분 | 수정 전 v1.0 | 현행 v1.1 |
| --- | --- | --- |
| 현재 납입 현황 | PORT-02와 같은 의미로 처리 | 별도 BASELINE: 목표 월20만원·미배정 월35만원 유지 |
| PORT-02 첫 달 | 보호25·목표20·미배정35만원 | 보호25·목표55·미배정0만원, 생활비180만원·별도 여유10만원 동일 |
| PORT-02 12회 후 | 목표 부족600만원 | 목표 부족180만원 |
| 목표 우선안 | 감축15만원으로 목표 적립70만원 | 같은 결과 유지. 비교 차이는 실제 필요한 감축15만원 |
| 원본·실행 상태 | 초안·별도 검산 | 문서정책 수정·별도 재검산. 실제 이체·앱 재실행 완료 아님 |

수정 검산 FIX-01~27을 별도 계산으로 확인했다. 이 중 재무계획 검산은 새 PORT-02 첫 달·12회 후 부족액, 안정안·목표우선안과의 대사, 감축15만원·한도10만원일 때 부족60만원, 현재 납입현황 보존, 미확인 납입과 확인된0 구분, 고정 납입 유지, 목표 초과배정 방지, 0회 나눗셈 방지를 포함한다. 세 계획×12회의 36개 월 배분합도 확인했다. 투자분기 검산 범위는 현행 투자정책 문서 제16절에 연결한다. 이 수량은 서로 독립된 실증 검증 건수로 합산·홍보하지 않는다.

현재 상태: 설계 반영 및 독립 계산 확인 완료. 계산 경로는 AI가 수행한 별도 산술 확인이며, 사람·전문가의 독립 검증이나 실제 앱 테스트로 표시하지 않는다. Codex 구현 후 동일 입력·정책·기간으로 실행하여 APP_EXECUTED 근거를 별도 추가한다.

다음 우선 작업은 대표 고객 한 명의 입력→진단→계획 비교→실행·점검을 연결한 검산·시연 명세다. 상품·산업·세후 기능은 이 사례에 필요한 범위에서 확장한다.


## 11. POL-FIN-1.2 예방 검사·변경 재계산·대안 제시 — 현행 적용

2026-11-02 사용자 지시 ‘생각만하면 어캄 너가 적용시켜야제’에 따라 아래를 **개발 시 필수 적용할 계산·화면 계약**으로 반영한다. 기초 산식과 세 계획의 POL-FIN-1.1 배분 순서는 유지하고, 예방 검사·부족 탐지·대안 제시·채택 차단 조건을 추가한다. 제품 사양 반영과 별도 참조 검산을 완료한 것이며 실제 앱 구현·배포·계좌 변경 완료를 뜻하지 않는다.

기초 월 계획의 대사식은 I = 조정 생활비 E + 의무상환 D + H + 목적별 월 배정 + U다. 기존 납입은 목적별 월 배정 안에 한 번 포함한다. 기존 잔액의 목적 간 이동은 소득이 아니며 별도 잔액 원장에 기록한다. 복수 목표·추가상환·투자·비용을 지원하면 해당 항목을 월 배정/유출에 명시하고, 지원하지 않는 사건을 임의의0으로 숨기지 않는다.

### 11.2 검사의 실행 순서와 상태

1. 입력 형식·범위·단위·미확인·원천 ID·기간을 검사한다.
2. 지출·납입을 정규화하고 기준 지출·총 감축·현재 배정·유지 납입을 확인한다.
3. 이전 납입 이력/확인된 잔액과 변경 효력일을 고정한다. 모의와 실제 경로를 분리한다.
4. 같은 입력·제약·원천으로 세 계획과 설정된 상황 변화 경로의 남은 기간을 계산한다.
5. 월/잔액 원장·한도·기간·목표/보호·날짜별 현금을 검사한다.
6. 기본 결과와 변화 결과의 차이를 표시한다. 부족하면 원안을 보존하고 변경 후보를 만든다.
7. 필요한 확인과 적용 범위·버전을 다시 검사한 뒤 그 범위만 채택한다.

| 상황 | 응답·화면 | 차단 범위 |
| --- | --- | --- |
| 입력 형식·단위·중복 배정 위반 | 수정할 항목 안내 | 유효한 결과 확정 차단. 원문 임시저장과 구분 |
| 유효 입력의 음수 재원·목표 부족 | 계산값·부족액·INFEASIBLE 사유 표시 | 해당 충당 가능/실행 가능 주장 차단. 입력 오류로422 처리하지 않음 |
| 정상 입력에서 내부 원장 대사 실패 | 내부 검증 실패 기록·결과 확인 필요 | 잘못된 산출값·해설·채택 차단. 고객 입력 오류로 돌리지 않음 |
| 월 예산은 맞지만 날짜 정보 부족 | 월 예산 기준 결과 + 지급일 확인 필요 | 지급일 안전 주장 차단 |
| 현재 계획은 충당·가상 감소는 부족 | 두 결과를 각각 표시 | 가상 감소를 실제 발생으로 바꾸거나 현재 결과를 소급 실패 처리하지 않음 |
| 실제/고객 확인 소득이 변경됨 | 이력을 보존한 새 현행 미리보기 | 이전 버전 자동 채택·과거 이력 수정 금지 |
| 변경 허용 미확인/거절 | 확인 필요/변경 불가 표시 | 해당 후보의 채택 차단 |
| 설정된 감소 시나리오 없음 | 기본 결과 + 변화 점검 미실시 | 강건성·변화 대응 검증 완료 주장 차단 |

permission_status=NEEDS_PERMISSION 같은 표기는 제안 상태다. 기존 decision enum에는 NEEDS_INPUT과 CHANGE_PERMISSION_REQUIRED 등의 reason_code로 연결하며 실제 API의 enum을 확인 없이 파괴하지 않는다. validation_status·deadline_status·cash_timing_status·stress_status도 호환 확장/어댑터로 관리한다.

### 11.3 대안 후보와 원안 보존

후보마다 proposal_id, base_run_id, root_goal_id, parent_goal_version, proposed_changes, required_permissions, assumptions, expected_effects, permission_status, selected=false를 기록한다. 한 실행 경로에서 같은 목표의 활성 버전은 하나다. 원안과 후보는 비교 화면에 함께 보이되 자금·의무 합산에서는 동시에 활성화하지 않는다.

대표 사례의 소득 감소 후 목표 우선 경로는 원안대로 유지하면 보호45·주거450, 합계495만원 부족이다. 아래는 같은 사실에서 계산한 **고객 확인 필요 대안**이다.

| 후보 | 변경·가정 | 월 계획상 결과 | 적용 상태 |
| --- | --- | --- | --- |
| A 원안 유지 | 기존 목표 납입20, 원목표1,440·원기한 유지, 총감축20 | 보호855·주거990. 보호45·주거450 부족 | 부족 표시. 원목표 충당으로 채택 금지 |
| B 보호 우선·목표금 조정 | 남은9회 목표 유지납입20→15, 보호25·주거15. 목표금1,440→945 | 보호900·수정 주거목표945 충당. 원래 목표 대비495 부족은 계속 표시 | 두 변경 확인 필요. 자동 선택/실행 없음 |
| C 보호기한 유지·주거기한 연장 | 목표 유지납입20→15. 보호보충은 원래9회 안에 완료. 주거는 남은22회(기존9+추가13), 소득240 등 조건 지속 가정 | 보호900은2027-10-31까지, 주거1,440은2028-11-30 마지막 납입 후 충당. 사용일 예시2028-12-02 | 납입·기한 변경 확인 필요. 일별 지급·실제 영업일 미검증 |

후보 C는 보호를 채운 뒤 남은13회의 목표 납입을 잔여액·횟수에 맞춰 원 단위 재계산한다. 매달 무조건40을 넣는다고 고정하지 않는다. 원래 기한의 주거 잔액945에서 부족495를 추가12회×최대40=480으로는 채울 수 없으므로, 이 정액·월말 납입 모형에서는 추가13회가 필요하다. 실제 미래 소득·금리·비용·영업일을 보장하는 기한 예측이 아니다.

후보의 수치·허용=true는 검산용 조건으로만 사용할 수 있다. 고객의 실제 동의로 기록하지 않는다. 허용을 거절한 경우 그 항목을 바꾸는 후보를 적용하지 않고 남은 범위의 비교 또는 해결 불가를 안내한다.

### 11.5 적용·검산 이력

참조 계산으로 PV-01~PV-30 예방 조건을 확인하고 원안/소득 감소 6개 경로의 기존 결과를 재현했다. 검산 범위·기대값·원장·대안은 [재무계산 검산 보고서 제11절](https://chatgpt.com/library?file_id=libfile_0644a958156c8191b82a32108ddf1782&account_id=personal)에 연결한다.

현재 상태: 정책·조건부 화면·인계 명세 반영 완료, 별도 참조 검산 완료. 실제 앱 코딩·API·이체·실제 고객 동의·실제 지급일 안전 확인은 수행하지 않았다. Codex 구현 후 동일 입력·규칙으로 재현하고 근거를 별도 기록한다.
