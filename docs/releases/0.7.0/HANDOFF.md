## 변경

- OUT-05의 기존 월별 달력과 현금 보존식을 재사용해 금융자산 원금선·투자 내부 이동·목표 인출을 추가했다. Decimal 정수 원 문자열, 루트 금융자산만 합산, 부동산/보증금/중복 자식 제외. 미확인 분류와 급여공제 자산 누락은 보류한다.
- 같은 immutable run의 결과 JSON에 가정 버전/입력 hash/전망 hash/기본 설명을 저장한다. 비교 선택은 전망 참조를 함께 저장한다. 기존 저장/조회 API와 권한·오래된 입력 처리를 재사용하며 추가 DB 테이블은 없다.
- 기존 설명 계층의 허용 fact/claim에 종료월 원금선·누적 목표 인출을 연결했다. 모델은 기존 규칙대로 claim 선택만 가능하며 숫자·수익률·자유문장을 만들지 못한다. 실제 모델 호출은 하지 않았다.
- 최종 화면에 기존 SVG 방식의 원금선·목표 인출 차트, 정확한 원 단위 표, 기간·가정·비용/세금 한계, 저장 버전을 연결했다. 입력을 바꾸면 이전 차트/설명 표시를 유지하고 새 계산에서 함께 갱신된다. 구성 변경은 내부 배분이므로 무수익 총액에는 영향을 주지 않는다.
- 원금선은 과거 매입원가가 아니라 기준일 평가잔액부터 시작한다. 수익 포함 전망은 null/미지원, 무수익 가정 손익만 0이다. 기존 채택·월 기록·금융정책·상품 카탈로그는 변경하지 않았다.

## 남은 조건

1. 양수·음수 수익 시나리오는 승인된 산식·수익률/비용/세금/인플레이션 가정이 없다. 새 수익 정책을 확정한 뒤 별도 버전·독립 정답으로 구현해야 한다. 임의 수익률 입력이나 보장 문구로 완성 처리하지 않았다.
2. 가정 수정은 기존 입력 수정→새 계산 run을 사용한다. 기존 채택·월 기록을 자동 바꾸지 않는다. 과거 run에 새 전망 필드가 없으면 재계산 안내만 표시한다.
3. 금융자산 총액 전망은 급여공제 납입의 누락된 자산증가와 미확인 기타자산 분류가 해결되기 전 제공하지 않는다. 알려진 실제 0과 구분한다.
4. PR #38 선행 병합과 이후 통합 충돌 대조는 필요하다. 이번 PR은 #38 작업 브랜치를 기준으로 v0.7 변경만 검토 가능하게 만든다. 원격 병합·배포·운영 DB 변경은 수행하지 않는다.

`frontend/vercel.json`의 `codex/release-v0.7.0`을 false로 추가하고 기존 차단을 보존했다. Render 관리 API 읽기에서 `dion-api-review`의 연결 브랜치 `dion/integration-20261111`, `autoDeploy=no`, `previews.generation=off`, `pullRequestPreviewsEnabled=no`를 확인했다. 작업 브랜치만 푸시하며 배포 설정 변경·운영 DB·유료 모델 호출 없음.
