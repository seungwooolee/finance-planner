# v0.7.0 월별 금융자산 전망

최초 통합 BASE: `8fa586b1db82467082bb84472500b557b55e49e1`. 선택 저장 의존 BASE: PR #38 후속 `fee4d76`. 사용자 요청에 따라 #38 브라우저 오류를 해결한 뒤 `codex/release-v0.7.0`에서 진행한다. 원격 병합은 사용자가 수행한다.

## 계산 계약

기존 `projection.py`의 월별 현금·납입·목표 지급을 재사용한다. 새 수익률 정책은 도입하지 않는다. `DION-FINANCIAL-PROJECTION-1.0`은 무수익 원금선만 지원하며 양수/음수 수익 전망은 미지원이다.

- 기준일의 지분 반영된 루트 CASH/DEPOSIT/INVESTMENT/PENSION만 금융자산에 포함한다. 자식 내역은 다시 합산하지 않는다. REAL_ESTATE/RENTAL_DEPOSIT은 제외한다. OTHER 분류, 금액/지분/기준일 미확인, 급여공제 자산증가 누락이면 전체 전망을 보류한다.
- '원금선'은 과거 매입원가가 아니라 **기준일 금융자산 평가잔액 + 이후 순유입**이다. 기존 평가손익을 복원하지 않는다.
- 월말 금융자산 = 기준일 금융자산 + 누적(소득 + 외부 유입 − 생활비 − 원리금 − 외부 유출 − 목표 지급). 현금/투자 사이 납입은 내부 이동이므로 한 번 더 더하지 않는다. 별도로 월별 투자 이동액·목표 인출액을 제공한다.
- 기존 월말 현금 + 초기 비현금 금융자산 + 누적 비현금 기존납입/신규투자로 같은 값을 독립 대조한다. 계산은 Decimal 정수 원 문자열, precision 60, 추가 반올림 없음이다.
- 기간은 기존 평가일 이후 완전한 달 1~600개, 월말 표시다. 목표 지급일/납입일 선후 검사는 기존 달력을 따른다. 전체 일별 현금 안전성을 보장하지 않는다. 부동산 수익·보증금 반환·매각·차입은 추가하지 않는다.
- 명목 원화, 무수익/물가 0 명시 가정이다. 복리는 적용하지 않는다. 새 투자 비용·세금은 추정하지 않는다(확정 현금사건만 기존 모델에 반영). 수익 포함 전망 값은 null/미지원이며, 무수익 시나리오 손익 0과 미지원 수익 전망을 구분한다.
- 실패 월 이후는 생성하지 않는다. 부분 접두부와 실패 정보를 표시하며 최종 금액은 null이다. 미입력은 0으로 채우지 않는다.

## 결과·저장·설명

OUT-05의 각 후보에 `financial_projection`을 추가한다. 가정·버전·입력 hash·전망 hash와 설명을 저장 run에 그대로 보존한다. 기존 analysis 저장/조회 권한과 오래된 입력 표시를 재사용한다. 비교 선택에는 해당 전망 hash/가정 버전을 함께 저장한다. 신규 테이블/운영 migration은 없다. 과거 run에 필드가 없으면 재계산 안내만 하며 과거 결과를 덮어쓰지 않는다.

투자구성은 금융자산 내부 배분이므로 무수익 총액 선은 동일하다. FE는 선택 재무안의 엔진 행만 표시하고 수익을 계산하지 않는다. 선택한 구성은 별도 비교 초안이며 계획 채택·월 기록은 그대로다. 가정을 바꾸려면 입력 확인 후 새 run을 만든다.

AI는 기존 설명 계층의 허용 fact/claim만 사용한다. 전망 종료월 금액·목표 인출·무수익 가정을 같은 run에서 전달한다. 모델은 claim을 선택할 뿐 숫자/수익률/자유문장을 만들 수 없다. UI 기본 설명도 같은 엔진 전망에 묶인다. 실제 유료 모델 호출은 하지 않는다.

## 관련 검증

독립 기대값: 초기 금융 1000원(현금 600/투자 400), 부동산 5000원 제외. 첫 달 순유입 200원/목표 지급 100원/투자 내부이동 80원 → 금융 1100원, 현금 620원. 다음 달 순유입 0원/납입 0원/목표 0원 → 금융 1100원. 수익 0, 양수/음수 수익 설정은 거부/미지원. 알려진 0, 미확인, 부분 달력/급여공제, 월 경계와 중복 분류도 검사한다.

실제 SQLite run/선택 저장·복원/권한/오래된 입력, 설명 금액 변조 거부, 실제 결과→차트/표 일치·모바일·이전 결과 표시를 관련 검사로 확인한다. 기존 전체 검사와 고정 AI lock은 재작성하지 않는다.
