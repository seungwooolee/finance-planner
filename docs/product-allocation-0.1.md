# 상품 조건 필터와 월별 배분 검토 0.1

사용자 요청(2026-11-11)에 따라 조사 목록 → 상품/고객 조건 필터 → 기존 월 투자 후보의 상품별 배분 → FE 표시·저장 결과에 연결했다. 기존 배정정책 `DION-ALLOCATION-1.0`의 생활비·채무·기존 납입·목표·보호자금 계산과 투자/추가현금 30/48만원 고정 정답을 변경하지 않는다.

## 현재 운영 데이터

조사본 100행 중 공식 상품명·코드를 대조한 78개를 `backend/app/planning/product_catalog.json`에 넣었다. 원본 포함/제외 100행과 공식 출처는 `data/product-research-20261110.json`에 보존한다. 기준일 2026-11-10은 조사 자료에 기록된 날짜이며 이번 연결일은 2026-11-11이다.

**추천 검토 활성 상품은 0개다.** 78개는 상품별 위험·비용·현금화 등의 상세 검증이 없어 `recommendation_eligible:false`, `facts:null`이다. 서비스 위험 한도와 상품 목표 비중도 미확정이므로 `product_policy.json`의 상태는 `DRAFT`, 각 매핑/비중은 비어 있다. 연결 작업이 이 상태를 자동 승인하지 않는다. 따라서 실제 응답은 검토 보류 사유와 0원 배분·미배분 잔액을 반환한다. 성공 경로 테스트의 TEST01/TEST02는 합성 자료이며 실제 카탈로그에 넣지 않았다.

## 연결 경로와 버전

- 모듈: `backend/app/planning/product_allocation.py`, `DION-PRODUCT-REVIEW-0.1`.
- 기존 어댑터1.0/1.1 `run_question_v12`에서 요청한 `OUT-06`을 별도 소비자가 채운다. 투자 관련 원응답은 기존 산술 엔진 필드로 의미를 바꾸지 않는다. 원문·7개 상태·정의버전·원응답 SHA와 필드 출처를 보존한다.
- `/api/fe/v1/preview`, 인증된 `/api/be/v1/cases/{id}/question-analyses`, 기존 v2 분석 경로에서 같은 순수 함수를 사용한다. 새 금융계산 API나 DB 스키마를 추가하지 않는다. 분석 결과 JSON 안에 입력·월후보·상품 목록·정책의 SHA와 버전을 저장하므로 과거 결과 조회는 당시 결과를 반환한다.
- FE는 새 계산/서버 계산 요청에 `OUT-06`을 포함하고 상품 화면에서 실제 API 상태·금액·사유·공식 링크를 표시한다. 이전 저장 결과에 OUT-06이 없으면 현재 입력으로 재계산하도록 안내한다.
- 원래 코어의 `engine_version`/`engine_release` 및 두 월 후보의 `recommended_new_investment_krw:null`은 코어 계약대로 유지한다. 새 소비자 버전은 OUT-06의 `review_version`이다. 검토 통과는 법적 적합성 인증·최종 개인화 추천·계획 채택·거래를 뜻하지 않는다.

## 고객 입력과 필터

F15 자금을 월별 신규 투자 후보에 연결하려면 사용자의 별도 확인을 `DION-PRODUCT-CONFIRM-0.1`로 저장한다. 단일 자금이라는 이유만으로 현재 목돈과 월 납입 후보를 자동으로 합치지 않는다. 확인은 기존 confirmations 배열로 저장·복원한다.

개인 범위 한 명을 대상으로 현재 기준일·범위·질문 정의1.2·원응답 리비전을 확인한다. 가구 자금을 한 명의 투자 성향으로 배분하지 않는다.

| 질문 | 소비 내용 | 보류/제외 조건 |
| --- | --- | --- |
| F15 | 자금 1개의 사용 가능일·사용일 | 여러 자금과 월예산 간 매핑 없음, 날짜 미확인, 사용계획 없음은 무기한 투자로 취급하지 않음 |
| NEW-08 | 손실의 필수 지출 영향 | 영향 있음이면 이 자금 배분 보류 |
| F16 | 경험 상품·기간 | 경험 없음/기간 모순을 거절, 경험을 상품 이해도로 대체하지 않음 |
| NEW-10 | 최대 손실 원응답 | 모름이면 보류, 손실 원치 않으면 원금손실 가능 상품 제외 |

| D18 | 환율 변동 수용 | 환노출 상품은 명시 수용이 없으면 제외 |

위험등급은 **1이 가장 높고 6이 가장 낮다.** 서버의 검토된 `risk_floor_by_preference`, `risk_floor_by_loss_band`, `risk_floor_by_loss_response`를 모두 확인한 뒤 가장 보수적인 등급 경계를 적용한다. 현재 세 매핑은 비어 있으며, 나이·생활단계·경험만으로 점수나 비중을 만들지 않는다. 경험·손실 답변의 UNKNOWN/미입력/나중에/거절을 0으로 바꾸지 않는다.

상품은 식별만으로 통과하지 않는다. `facts`에는 위험등급·자산군·환노출·원금손실 가능성·복잡성·예금보호 여부·연 비용·현금화 조건·계좌 범위·최소 검토기간·검토일/유효기간·거래 가능 상태 및 **각 필드의 공식 HTTPS 근거**가 필요하다. 현재 계좌 범위는 `GENERAL_TAXABLE_ONLY`의 검토용 초안이며 ISA·연금 등 계좌 적합성으로 확대하지 않는다. 비용은 확정 수익이나 실거래 비용 차감으로 사용하지 않는다.

## 배분 규칙

1. OUT-05에서 계산된 각 방식·각 월의 `new_investment_krw`만 예산으로 받는다. 두 방식은 비교 대안이다. 합쳐서 두 번 쓸 수 있는 자금으로 표시하지 않는다. 월 예산이 부족한 실패 후보는 배분하지 않는다.
2. 비중은 서버 정책의 상품별 `target_bps`/`cap_bps`다. 정수 bps 0~10000, 코드 중복 없음, 목표≤상한, 전체 목표 합≤10000을 검증한다. 요청 JSON에서 정책·상품 활성 플래그를 전달할 수 없다.
3. 상품별 검토액 = `월 투자 후보 × 원래 목표 bps // 10000`. 정수 원의 정확한 계산이다. 탈락 상품의 비중과 원 미만 절사액은 미배분으로 남긴다. 통과 상품으로 비중을 다시 정규화하지 않는다.
4. 매월 자금 가용일·사용일까지의 최소 검토기간을 다시 검사한다. 전체 일별 달력과 영업일별 결제 잔고는 검증하지 않으므로 실거래 가능일·매수 수량을 산출하지 않는다.
5. 반드시 `배분 합계 + 미배분 잔액 = 원래 월 투자 후보`를 만족한다. 미배분 잔액을 기존 재무엔진의 현금 잔고나 추가현금 버킷에 자동 가산하지 않는다. 기존 원장의 투자 가정과 상품 배분 검토는 서로 다른 결과다.
6. FE의 부동산/보증금 원응답 보완 게이트가 OUT-05를 막으면 downstream OUT-06의 모든 배분도 0으로 만들고 미배분으로 돌린다. 미확인 예산을 이용한 상품 배분을 표시하지 않는다.

## 출력 상태와 제한

`OUT-06`은 필요한 고객 입력·오류 질문 ID, 상품별 제외 사유, 검토된 상품 수, 카탈로그/정책 버전·SHA, 방식·월별 원래 예산/배분/미배분을 반환한다. 월별 보류는 각 행의 `calc_state`/`reason_codes`로 남긴다. 상품 설정 오류는 해당 결과를 보류하며 관련 없는 현황 금액을 없애지 않는다.

현재 기능은 **제약을 확인한 월별 배분 검토 초안**이다. 기존 보유상품과의 기초자산 중복·발행사/섹터 집중 통합, 고객별 최종 투자 한도 확정, 상품별 설명 확인, 계좌 적합성, 실시간 가격·거래정지/상장폐지 갱신, 주문 수량·세금·실제 매매는 미완료다. 이런 기능을 완료한 추천으로 표시하지 않으며 최종 권장액은 null이다.

## 이번 검증

관련 pytest 125개 통과(신규 상품 소비자21개 포함), 변경 Python Ruff, FE 타입 검사·ESLint 통과. 마지막 필터 경계 보완 후 관련125개를 재실행해 통과했다. 브라우저 검사는 Chromium의 socket 생성이 실행 환경에서 차단되어 실행하지 못했다. 같은 범위의 E2E 기대값은 새 API에 맞춰 수정했으나 브라우저 통과로 기록하지 않는다. production 번들은 이 환경의 외부 의존성 링크 제한 때문에 `npm run build -- --webpack`으로 확인한다. Next → FastAPI 실제 HTTP 프록시에서도 78상품·월 후보30/48만원·0원 배분·전액 미배분과 `/dion` HTTP200을 확인했다. 전체 Core·전체 E2E·실계정/원격DB는 이번 파트 작업 범위에서 실행하지 않았다.

실행한 명령과 최종 결과는 `docs/development-log.md`의 2026-11-11 상품 연결 항목을 따른다.
