# 백엔드·질문·결과 개발 인계

기존 백엔드 사전 설계의 원응답 보존·수정 이력 원칙을 유지한다. 엔진은 계산과 연결표, 백엔드는 실제 저장·권한·동시성, 프론트는 질문·결과 표시를 맡는다. API/DB 모델을 엔진 안에 중복 구현하지 않았다.

## 다음 연결 작업

1. 백엔드가 현재 profile/snapshot 버전에 해당하는 응답을 읽고 실행 계약으로 명시 변환한다. 저장된 원문과 이전 revision을 덮어쓰지 않는다.
2. 범위·소유 동의·접근권한을 확인한 뒤 run_engine을 호출한다. 동일 계산을 화면에서 재구현하지 않는다.
3. 입력/정책/엔진 버전과 해시를 결과에 묶어 저장한다. 낡은 revision으로 계산된 결과를 새 입력의 결과로 보여주지 않는다.
4. OUT별 상태를 표시한다. 부분 금액을 완전한 순자산으로, 월 후보를 하루 단위 지급 가능성으로, 검토를 실제채택으로 바꾸지 않는다.
5. 목표 없음·부채 없음·해당 없음과 모름을 구분한다. 처음부터55개를 모두 묻지 않는다. 기존 확인값·목표·경제사건 ID를 재사용한다.
6. 이번 패키지의 가상 입력/독립 기대값을 API 계약 테스트로 연결한다. 권한·동시수정·저장복구·모바일 입력을 실제 앱에서 별도 검증한다.

## 변경 충돌 방지

질문 레지스트리와 본 계약을 먼저 수정하고 구현·고정 정답·버전을 함께 변경한다. v1.2 원문/시트는 이력으로 남겼으며 이 버전의 새 입력 의미를 v1.2 응답에 소급하지 않는다. 기존 API 요청 형식은 새 엔진 형식으로 자동 대체하지 않는다. 백엔드 작업 중인 원응답 저장 PoC나 프론트 디자인 파일을 이번 엔진으로 덮어쓰지 않는다.
