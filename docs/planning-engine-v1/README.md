# DION 재무엔진 v1.0

질문 원응답에서 현재 현황, 목표별 적립 달력, 두 재무안의 월별 후보, 확인 세금·연금·상속 결과까지 계산하는 독립 Python 엔진이다. 사용자 위임에 따라 중간 PoC 승인 단계를 생략하고 구현·검산했다. 기존 앱의 API·DB·화면 연결은 별도이며 이 버전은 실제 거래나 금융상품 추천을 수행하지 않는다.

## 실행

Python 3.12 이상에서 추가 패키지 없이 실행한다. 저장소 루트에서:

```bash
cd backend
python -m app.planning examples/planning/base_input.json --output result.json
python -m app.planning examples/planning/full_input.json --output full_result.json
```

함수 연결은 `from app.planning import run_engine; result = run_engine(document)`이다. 입력을 수정하지 않는 순수 함수다. 같은 입력은 같은 해시·결과를 반환한다. 입력·응답은 모두 JSON으로 직렬화할 수 있다. 오류를 상태로 반환하고 CLI는 잘못된 입력·내부 계산검사 실패에 종료코드 2를 사용한다. 입력 미완성·지원 밖·재원 부족은 JSON 상태를 읽어 구분한다.

## 이번 버전이 계산하는 것

- 같은 소유 범위·평가일의 자산, 부채, 순자산. 계좌 총액과 하위 보유상품을 중복 합산하지 않는다.
- 생활비 포함관계를 정규화한 월 흐름. 원리금과 기존 납입, 급여에서 이미 공제된 납입을 구분한다.
- 일시·반복 목표의 명시 지급일과 적립일. 각 지급일까지 부족하지 않도록 적립액을 원 단위로 계산한다.
- 보호자금·운영자금·목표·기존 납입을 반영한 안정 우선/투자 여력 두 월별 시나리오. 여러 목표의 최소액을 독립 계산한 후 합산한다.
- 확인된 세전/세후 수령액, 원천세·수수료·추가 납부세액과 납부일. 미래 사건은 같은 경제사건 ID로 1회 반영한다.
- 기존 연금 잔액·납입 참조, 공식 조회값 또는 명시 시나리오를 사용한 은퇴 후 월별 부족액. 연금 개시가 전망 기간에 들어오면 소득 경로와 포함관계를 확인한다.
- 이미 받은 상속의 기존 자산 참조, 확정 미래 수령과 미확정 가정의 구분. 개인 소유분의 명시 배분, 확인 상속세·비용의 현금 부족액.

수익·물가를 자동 추정하지 않는다. 현재는 명시한 미래 명목금액과 무수익 시나리오를 지원한다. 50/80%는 잔여 신규 납입예산의 비교용 템플릿이며 개인별 투자 적합성·상품 비중이 아니다. 비상자금 3개월·운영자금 1개월은 DION 서비스 정책이며 법정 기준이나 모든 고객의 최적값으로 설명하지 않는다.

## 구현하지 않은 범위

법정 세액·공제·국민연금액 자동산출, 개인화 상품/비중 추천, 자산매각·차입금 유입의 복합 원장, 목돈 투자안 자동생성, 일자별 전체 지급 가능성 검증, 채택·실거래·실적 저장은 구현하지 않았다. 월 합계가 맞아도 급여일 이전의 지급 가능성을 입증하지 않는다. 보호자금이나 부동산을 자동으로 처분해 적자를 메우지 않는다. 지원 밖 결과는 상세 질문 전에 안내한다.

현재 앱은 기존 Iteration 1 그대로다. Google 질문 시트·v1.2 원문은 보존했고 이 패키지의 v1.3-engine은 실행용 필드 계약과 질문 보완안이다. 새 폼/API에 연결하기 전에는 Google 시트가 자동 실행 폼이 되었다고 표시하지 않는다.
