# DEC-02 배정·두안 생성 검토 및 오프라인 검산 — 2026-11-10

현행 보완: A1·B1에 이어 남은 네 정책도 사용자 위임으로 DION-ALLOCATION-1.0에 확정했다. [중심 명세7.3절](../../financial-engine-spec.md)의 비교·이유·독립 정답을 따른다. 아래 “정책 미정”과 구버전 도구의 generation 게이트는 당시 한계로 보존한다. 새 allocation_rules.py는 별도의 월 후보만 생성하며 구버전 원장·고정정답은 변경하지 않았다. 전체 엔진·고객채택·앱 연결은 여전히 미완료다.

현재 상태는 **정책 미정 / 명시 후보의 산술검사 가능**이다. FIN-DATA-1.0 19.6~19.8과 FIN-MAP-1.0 20.5E·20.6·20.7을 재사용했다. 새 정책·새 앱 엔진을 승인하지 않았고 AI·DB·HTTP·계획채택은 연결하지 않았다.

## 이번에 구현한 작은 기능

`tools/funding_ledger.py`는 원천 자산 ID별 배정과 월 예산을 같은 사례·프로필·스냅샷·계획버전 아래 검사한다. 자산잔액·목적배정·월배분은 각각의 의미를 유지한다. 보호/목표 배정은 자산을 추가하지 않으며 동일 자산에 원천 ID를 두 번 붙이는 입력도 거절한다. 월 현금유지액과 두안의 배분벡터는 입력된 값을 검사할 뿐 생성하지 않는다.

| 검사 | 규칙·제공 결과 | 근거 |
| --- | --- | --- |
| 기존 잔액 배정 | 원천별 배정합≤배정가능액, 나머지는 명시 잔여. 초과액·음수 원값 보존 | 19.6 / E-01·05 / MX-21 |
| 가용 시점 | 사용일 이전 가용 여부, 비현금 원천의 현실화 확인. 미확인 매각·반환을 현금으로 자동 사용하지 않음 | 19.8 / D-02 / MX-15 |
| 월 원장 | S=세후소득−정규생활비−의무상환, W=S−유지기존납입−추가보호−추가목표−H | 19.7 / E-02·03 |
| 기존 납입 연결 | 같은 목표·목적·일정의 기존 납입만 총납입에서 빼 추가액 산정. 누락 연결·중복 참조 차단 | D-07 / MX-09 |
| 월 대사 | 유지납입+추가보호/목표+신규투자+H+미배정=S. 목표 미정은 조건부 금액으로 표시 | E-05 / MX-24 |
| 기간 중 현금 | 시간 원장의 기초금은 별도 금액을 재입력하지 않고 원천 CASH를 참조. 급여 전 상환 부족·당일 순서 미확인 구분 | F-01 / MX-26 |

| 생성 게이트 | 두 재무안 자동생성은 항상 NEEDS_POLICY, 추천=false·채택 미구현 | 20.7 / DEC-02 |

모든 금액은 원 단위 비음수 정수 문자열로 입력하고 Decimal로 계산한다. 음수 결과·부족액은 그대로 보존한다. 모름/null은 실제0과 다르며 해당 결과만 보류한다. float·쉼표·지수표기·NaN·Infinity 등을 거절한다. 정규 생활비와 원리금은 이 도구에 오기 전에 포함관계를 확인해야 한다. 원문 질문 답변을 이 도구 입력으로 자동 변환하지 않는다.

## 실행과 한계

인계 폴더 루트에서 실행한다.

```bash
python 12_CHECKS/build_contract_audit.py
python -m unittest discover -s 12_CHECKS -p 'test_contract_and_funding.py' -v
node 12_CHECKS/check_updated_files.cjs
```

개별 후보를 JSON으로 저장했다면 `python 09_UPDATED_FILES/tools/funding_ledger.py candidate.json`으로 검사한다. 입력 형식은 `12_CHECKS/funding_fixtures.json`의 한 사례 객체를 따른다. 질문40의 자동 어댑터가 아니며 SCENARIO·KRW만 허용한다.

현재 도구는 선택한 원천집합의 배정, 반복 월 예산, 단일 CASH 원천의 명시 사건 경로만 검사한다. 전체 고객 자산 완전성·모든 계좌 간 거래·기존 보유 전체 재구성·미래 원금/순자산·목표납입 달력 생성·상품·세금·변경권한 통합·채택버전·월간 실적 저장을 구현한 것이 아니다. 감축허용 함수는 독립 산술검사이며 후보 검증기에 권한정책 전체를 연결하지 않았다. 목적지급 사건의 원장 반영·이체 쌍·보호잔액의 시점별 유지검사는 실제 프로젝트와 정책 확인 후 이어갈 부분이다.

후속으로 GitHub `finance-planner` 고정커밋2baa2be548b949d5bfb67a46e81a1a721291ef39의 실제 코드·요청모델·기존 Decimal 유틸리티를 읽었다. 기존요청11필드/엔진10필드에는 월상환·기존납입·H·두안/원응답/계획버전 저장이 없다. DB도 확인한 소스에 미구현이다. ZIP 재업로드는 필요하지 않다. 다음은 이 차이를 잃지 않는 새 입력계약/어댑터이며 구버전엔진에 누락값0으로 연결하지 않는다. 앱 Core/E2E/Build는 실행하지 않았다.
