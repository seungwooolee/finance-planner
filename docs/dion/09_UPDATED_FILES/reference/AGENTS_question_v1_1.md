## 계산과 AI의 경계
- 프론트엔드는 입력과 표시, FastAPI는 검증, 독립 Python 엔진은 Decimal 계산을 담당한다. AI 설명은 추후 별도 계층이며 현재 코드에 추가하지 않는다.
- AI가 수치를 생성·덮어쓰거나 프론트엔드가 금융 결과를 임의 재계산하지 않는다. 표시 형식·좌표와 검증된 금액 유틸리티에 의한 기계적 비중환산은 계산엔진 정책판단과 구분한다. 세금·수익률·위험상한·대표상품을 임의 생성하지 않는다.
- 화면 금액은 만원, 내부/전송은 정수 원 단위 Decimal 또는 정확한 십진문자열이다. 실제0·모름·미입력·해당없음을 구분하며 float를 거쳐 정밀도를 잃지 않게 검증한다. 합계와 세부내역, 월배분과 보유잔액, 투자납입과 평가손익을 구분한다.
- 검증되지 않은 계산식을 임의 확정하지 않는다. **구현 회귀 테스트 통과와 재무 가정의 타당성 검토는 서로 다르다.** 기존 구현 선택과 사용자 명시 기준은 `docs/calculation-policy.md`에서 구분한다.
- 보증금은 현재 사용 가능한 현금이 아니다. 실제 반환 가능일·관련 채무·지분·목적 배정을 확인한다. 과거 Iteration1 검산의 목표월 반환 가정은 그 사례에만 적용하며 새 고객의 반환일·금액을 자동 추정하지 않는다. 보호자금·목표자금을 중복 배정하지 않는다.
- 계산 기준 변경 시 출처·대안·고정 정답·영향 범위를 문서화한 뒤 사용자 승인과 검증을 거친다. 기존 정답을 새 구현에 맞춰 조용히 바꾸지 않는다.

## 실행·이번 달 기록·버전
- 계획 초안/미리보기·고객 명시채택·실제 금융 실행을 구분한다. 실적은 채택 plan_id/version, 기록월, 기간·기준일·출처에 연결한다. 금액입력과 할일 완료를 별도 저장한다.
- 중간기록/월말마감, 실제0/미입력, 실제납입/평가손익, 월투자/일시금을 분리한다. 미입력은0으로 채우지 않으며 부분기록을 월전체 성과로 판정하지 않는다. 상황변화 재검토는 새초안으로 만들고 기존채택을 자동 변경하지 않는다.

## 점진적 개발 사이클
1. 작은 기능 하나를 정하고 입력·출력·계산 규칙·비범위·완료 조건을 기록한다. 미확정 사항은 미확정으로 남긴다.
2. 기존 구조를 활용해 구현하고 실제 실행한다.
3. 고정 정답과 비교하는 테스트 및 기존 기능의 회귀 테스트를 실행한다.
4. 오류를 수정한 뒤 관련 검사를 재실행한다. 새 변경이나 미해결 문제가 없으면 같은 검사를 불필요하게 반복하지 않는다.
5. 실행 명령·결과·제약·남은 문제를 개발 로그에 남기고 검증된 변경을 통합한다.

- 사용자 또는 다른 작업이 실행한 서버를 임의 종료하지 않는다. 포트·프로세스 소유를 확인하고 이번 작업에서 시작한 프로세스만 정리한다.

## ECC 사용 범위
- ECC는 이 프로젝트의 기존 지침과 명세에 맞춰 테스트 작성·코드 검토에 선별 활용한다.
- Decimal 재무 계산, API 계약, 기존 정답 기준을 유지한다.
- 검증은 `scripts/verify.ps1`의 `Core`·`E2E`·`Build` 모드를 사용한다. `Build`는 같은 checkout의 서버가 없는 조건에서 실행하며, 실행 중인 서버를 임의 종료하지 않는다.
- ECC 설정 예제 복사, 멀티 에이전트, 추가 MCP, 신규 검사 도구, 자동 포맷·반복 검사 훅은 이번 적용 범위에서 제외한다.
- 검증 결과는 실행 여부와 통과·실패·미실행 상태를 명시하고, 훅 활성화와 실제 실행 성공을 구분한다.

## 검증과 인계
- `scripts/verify.ps1 -Mode Core`: pytest, Ruff, pip check, TypeScript, ESLint.
- `-Mode Build`: production build. 해당 checkout의 서버가 실행 중이면 중단하고 별도 checkout 또는 사용자가 종료한 뒤 실행한다.
- `-Mode E2E -BrowserChannel msedge`: 이미 실행 중인 앱에 Playwright를 수행한다. 서버 시작·종료는 자동으로 하지 않는다.
- 문서만 바꾼 경우 관련 링크/명령과 `git diff --check`를 확인한다. 사용자가 회귀 검증을 요청하면 기존 전체 테스트를 실행한다.
- 실행하지 못한 검사는 이유와 이전 검증 기록을 구분해 적는다. 이전 통과 기록을 이번 실행 결과로 보고하지 않는다.
- README는 시작점, 명세는 계약, 계산 정책은 근거와 가정, 상태 문서는 현황, 개발 로그는 실행 이력으로 관리한다. 중복된 수식·계약을 여러 문서에서 별도로 고치지 않는다.
- 변경 파일, 실제 테스트 결과, 남은 문제, 다음 작은 기능을 보고한다. 허용된 변경만 Git에 기록하고 무관한 변경은 포함하지 않는다.
