# DION 포트폴리오 고객화면 프론트엔드 구현 명세 v1.0

2026-11-05 · 빠른진단 5개 화면 / 정밀점검 5개 화면 · Codex 구현 인계용

이 파일은 저장소의 `docs/design/PORTFOLIO_REPORT_FRONTEND.md`로 추가해 사용한다. 동등한 명세 위치가 있으면 그 위치에 연결해도 된다. **화면 구성·최소 입력·상태·상호작용·데이터 연결·검산 기대값**을 개발자가 구현할 수 있도록 정리한 문서다. 앱 코드 변경, 운영 투자정책 확정, 실상품 검증 완료를 의미하지 않는다.

## 0. 먼저 읽을 구현 지침

1. `AGENTS.md`, 현재 라우트·디자인 토큰·금액 유틸리티·상태관리·API 어댑터·테스트를 먼저 확인한다. 기존 프레임워크와 정상 기능을 유지하고 프로젝트 전체를 재작성하지 않는다.
2. 이 명세를 기준으로 **작동하는 프론트와 시연용 어댑터**를 구현한다. 금융정책이 미확정이어도 화면 이동·입력 보완·선택·비중 조절·초안 저장·상담창·내보내기 상태는 구현할 수 있다.
3. 실제 개인화 추천과 계획 채택은 서버의 검증·허용 상태를 따른다. 데모 비중과 금액을 운영 정책으로 승격하지 않는다.
4. 문서 그림을 통째로 배경 이미지로 넣지 않는다. 텍스트·표·카드·버튼은 DOM, 차트는 데이터 기반 SVG/차트 컴포넌트, 슬라이더는 실제 입력으로 구현한다.
5. 새 영속 Q-ID, 정책 ID, API 엔드포인트를 임의 확정하지 않는다. 아래 타입·경로·컴포넌트 이름은 **프론트 연결용 제안**이며 기존 계약에 어댑터로 연결한다.

## 2. 화면 이동과 공통 프레임

빠른진단과 정밀점검은 같은 고객정보를 이어 쓰는 진단 깊이다. 정밀점검에 진입할 때 처음부터 설문을 반복하지 않는다. 부족한 정보가 있어도 확인된 현황과 일반 투자정보는 제공한다.

### 2.1 제안 라우트

기존 라우터가 있으면 그 구조에 연결한다. `FE-Q*`, `FE-D*`는 이 파일의 화면 라벨이며 설문 Q-ID나 DB 키가 아니다.

| 화면 | 제안 경로 | 제목 |
| --- | --- | --- |
| FE-Q1 | `/quick/overview` | 내 재무현황과 금융자산 구성 |
| FE-Q2 | `/quick/plans` | 생활 안정과 투자 확대를 비교해요 |
| FE-Q3 | `/quick/investment` | 간이 투자 포트폴리오를 비교해요 |
| FE-Q4 | `/quick/products` | 투자상품 정보를 비교해요 |
| FE-Q5 | `/quick/actions` | 내 결과와 이번 달 행동 |
| FE-D1 | `/report/overview` | 내 자산과 목표까지의 기간 |
| FE-D2 | `/report/projection` | 두 재무관리 방식의 자산 변화 |
| FE-D3 | `/report/investment` | 내 투자성향과 세 가지 투자안 |
| FE-D4 | `/report/candidates` | 상품을 이해하고 비중을 직접 조절해요 |
| FE-D5 | `/report/actions` | 그래프로 정리하는 결과와 이번 달 행동 |
| 정보 보완 | 기존 입력 경로의 후속 입력 뷰 | 요청한 결과에 필요한 항목만 확인 |

기존 `/quick/flow`·`/quick/assets`는 Q1의 해당 섹션, `/quick/invest`는 Q3, `/quick/next`는 Q5로 연결할 수 있다. 실제 존재하는 경로를 확인한 뒤 별칭/리다이렉트를 추가하며 북마크와 저장된 결과를 깨뜨리지 않는다.

### 2.2 공통 결과 프레임

- 상단: 진단 모드와 `n/5`, 집계 범위(본인/가구), 기준일, 데모 여부, 현재/미리보기/채택 상태, `입력 내용 수정`.
- 본문: 핵심 문장 → 금액 카드 → 차트·비교표 → 근거·부족 정보 → 다음 행동.
- 하단: 이전/다음, 필요한 보완 버튼. 빠른진단 저장과 정밀점검 연결은 Q5에 배치한다.
- 우측 하단: 상담창 열기. 이동과 최소화 후에도 같은 결과의 대화를 이어간다.
- 직접 URL 진입도 동일한 보고서·선택 버전을 복원한다. 결과가 없으면 빈 숫자를 그리지 않고 입력/데모 진입을 안내한다.
- 뒤로가기·모드 변경만으로 기본 재무안/투자안을 다시 선택하지 않는다.

## 4. 데이터 계약과 금액 규칙

### 4.1 프론트와 계산의 책임

보호금 목표개월·위험 상한·기간별 허용 비중·실상품 추천·세금·미래 수익률은 서버/검증된 정책의 책임이다. 프론트는 확인된 결과를 표시하고 입력·선택·초안 변경을 전달한다. 정책이 없으면 아래 25/55/20 등의 예시를 운영 기본값으로 사용하지 않는다.

아래는 화면 요구를 설명하는 최소 View Model이다. 기존 필드·상태와 명시적 매핑을 만들며 기존 API를 이 타입으로 무조건 변경하지 않는다. 정의되지 않은 상태를 성공으로 취급하지 않는다.

```ts
type MoneyKrw = string; // 확정 표시 금액: 원 단위 정수 십진 문자열
type Mode = 'QUICK' | 'PRECISE';
type PlanKey = 'STABILITY_FIRST' | 'INVESTMENT_CAPACITY';
type OptionKey = 'A' | 'B' | 'C' | 'CUSTOM';
type ProfileType = 'P1' | 'P2' | 'P3' | 'P4' | 'P5';

type Fact<T> =
  | { state: 'KNOWN'; value: T; quality: 'CONFIRMED' | 'APPROXIMATE' }
  | { state: 'UNKNOWN' | 'NOT_ASKED' | 'NOT_APPLICABLE'; value: null };

type ResultStatus =
  | 'NEEDS_INPUT' | 'NEEDS_POLICY' | 'REVIEW_REQUIRED'
  | 'READY' | 'INFEASIBLE' | 'NOT_SUPPORTED';

interface ResultContext {
  reportId: string;
  mode: Mode;
  ownerScope: 'SELF' | 'HOUSEHOLD';
  evaluationDate: string; // ISO 날짜
  profileVersion: string;
  dataSnapshotId: string;
  policyVersion: string | null;
  draftVersion: string;
  requestKey: string; // 어느 입력·선택에 대응하는 응답인지 식별
  source: 'DEMO' | 'LIVE';
  fixtureId?: string;
}

interface MoneyMetric {
  label: string;
  amount: Fact<MoneyKrw>;
  resultStatus: ResultStatus;
  missingFields: string[];
  reason: string | null;
}

interface DonutSlice {
  id: string;
  label: string;
  amountKrw: MoneyKrw; // 검증된 비음수 값만 전달
  ratio: string;       // 예: '0.30'. 분모와 같은 스냅샷에서 계산
}

interface DonutVM {
  id: string;
  title: string;
  denominatorLabel: string;
  denominator: Fact<MoneyKrw>;
  status: 'READY' | 'PARTIAL' | 'EMPTY' | 'UNAVAILABLE';
  slices: DonutSlice[];
  note: string | null;
}

interface BudgetLine {
  key: 'LIVING' | 'DEBT' | 'GOAL' | 'BUFFER' | 'CASH'
     | 'EXISTING_INVESTMENT' | 'NEW_INVESTMENT';
  label: string;
  amount: Fact<MoneyKrw>;
}

interface PlanVM {
  key: PlanKey;
  title: string;
  budget: BudgetLine[];
  existingMonthlyInvestment: Fact<MoneyKrw>;
  newMonthlyInvestment: Fact<MoneyKrw>;
  totalMonthlyInvestment: Fact<MoneyKrw>;
  newLumpSumCap: Fact<MoneyKrw>;
  resultStatus: ResultStatus;
  reasons: string[];
}

interface AllocationRow {
  id: string;
  label: string;
  assetClass: 'EQUITY' | 'BOND' | 'CASH_EQUIVALENT' | 'OTHER';
  weightBps: number; // 10000=100%, 1%p 조작 단위=100bps
  locked: boolean;
}

interface AllocationVM {
  option: OptionKey;
  rows: AllocationRow[];
  newLumpSum: Fact<MoneyKrw>;
  newMonthlyContribution: Fact<MoneyKrw>;
  existingHoldings: Fact<MoneyKrw>;
  existingMonthlyContribution: Fact<MoneyKrw>;
  offerLevel: 'DIRECTION_PREVIEW' | 'PERSONALIZED_PROPOSAL';
  resultStatus: ResultStatus;
  reasons: string[];
}

interface ProjectionPoint {
  date: string;
  monthIndex: number;
  totalFinancialAssets: Fact<MoneyKrw>;
  cashAndDeposits: Fact<MoneyKrw>;
  investmentAssets: Fact<MoneyKrw>;
}

interface ProjectionVM {
  contextKey: string;
  assumptionLabel: string;
  comparisonValid: boolean;
  series: { plan: PlanKey; points: ProjectionPoint[] }[];
  status: ResultStatus;
}

interface Capabilities {
  canSaveDraft: boolean;
  canExportSnapshot: boolean;
  canRequestPersonalization: boolean;
  canAdopt: boolean; // 서버 최신 검증 필요. 데모는 항상 false
  canChat: boolean;
}

interface GoalVM {
  state: 'CONFIRMED' | 'NONE' | 'UNKNOWN';
  name: string | null;
  target: Fact<MoneyKrw>;
  assigned: Fact<MoneyKrw>;
  shortfall: Fact<MoneyKrw>;
  monthlyRequired: Fact<MoneyKrw>;
  dueDate: Fact<string>;
  progressRatio: Fact<string>;
}

interface OverviewVM {
  monthlyNetIncome: MoneyMetric;
  livingExpenses: MoneyMetric;
  debtPayment: MoneyMetric;
  existingMonthlyInvestment: MoneyMetric;
  basicBalance: MoneyMetric;
  financialAssets: MoneyMetric;
  totalAssets: MoneyMetric;
  netAssets: MoneyMetric;
  financialInvestmentRatio: Fact<string>;
  monthlyFlowDonut: DonutVM;
  financialAssetsDonut: DonutVM;
  totalAssetsDonut: DonutVM;
  reservations: { id: string; label: string; amount: Fact<MoneyKrw> }[];
}

interface SourceRef {
  name: string;
  url: string | null;
  dataAsOf: Fact<string>;
  fetchedAt: string | null;
  priceAsOf: Fact<string>;
  delayLabel: string | null;
}

interface ProductVM {
  id: string;
  contextKey: string;
  name: string;
  isFictional: boolean;
  assetClass: AllocationRow['assetClass'];
  role: string;
  reasons: string[];
  risks: string[];
  details: { label: string; value: Fact<string>; unit: string | null }[];
  sources: SourceRef[];
  informationStatus: 'LOADING' | 'AVAILABLE' | 'PARTIAL' | 'STALE' | 'ERROR' | 'NOT_SUPPORTED';
  suitabilityStatus: ResultStatus;
}

interface TaxReviewItem {
  id: string;
  label: string;
  status: 'ELIGIBLE' | 'NEEDS_INPUT' | 'NOT_APPLICABLE';
  requirements: string[];
  taxYear: Fact<string>;
  benefitKrw: Fact<MoneyKrw>;
  sources: SourceRef[];
}

interface PeerComparisonVM {
  ownRatio: Fact<string>;
  benchmarkRatio: Fact<string>;
  cohortLabel: string | null;
  populationScope: string | null;
  assetScope: string | null;
  statisticMethod: string | null;
  sampleDescription: string | null;
  surveyPeriod: string | null;
  source: SourceRef | null;
  status: 'AVAILABLE' | 'UNAVAILABLE' | 'INCOMPARABLE';
  reason: string | null;
}

interface ActionVM {
  id: string;
  label: string;
  contextKey: string;
  plannedAmount: Fact<MoneyKrw>;
  actualAmount: Fact<MoneyKrw>;
  actualDate: Fact<string>;
  completion: 'OPEN' | 'DONE';
}

interface ReportVM {
  context: ResultContext;
  lifecycle: 'CURRENT' | 'DRAFT' | 'ADOPTED' | 'STALE';
  selection: { plan: PlanKey | null; option: OptionKey | null };
  overview: OverviewVM;
  goal: GoalVM;
  plans: PlanVM[];
  projection: ProjectionVM;
  preference: { type: Fact<ProfileType>; rawText: Fact<string> };
  investmentOptions: AllocationVM[];
  selectedAllocation: AllocationVM | null;
  baseAllocationForComparison: AllocationVM | null;
  products: ProductVM[];
  taxReviews: TaxReviewItem[];
  peerComparison: PeerComparisonVM;
  actions: ActionVM[];
  capabilities: Capabilities;
  notices: { code: string; message: string; affectedViews: string[] }[];
}
```

타입만으로 검증이 완료되는 것은 아니다. 어댑터 진입점에서 금액 문자열 형식, 상태/값 일치, 날짜, 합계와 비중 범위를 검증한다. 기존 서버의 `ALLOWED` 등을 무조건 `READY`로 변환하지 않는다. 차트의 READY는 그 차트를 그릴 데이터가 있다는 뜻이며 추천·채택 가능과 다르다.

### 4.2 금액과 누락

- 입력·요약 표시는 만원, 내부는 KRW 문자열. `300만원="3000000"`, `1만원="10000"`, 실제0은 `"0"`이다. 기존의 엄밀한 환산 유틸리티를 재사용한다.
- `null`, 미입력, 모름, 해당 없음, 실제0을 구분한다. `Number(null)`·`value || 0`으로 변환하지 않는다.
- 추정·반올림 표시는 `약`을 붙이고 상세에서 정확한 원 금액을 보여준다. 표시 반올림으로 원본 금액을 바꾸지 않는다.
- 상환잔액·배정 원금은 비음수로 검증하되, 기초 차액·순자산은 음수일 수 있다. 음수 지표를 양수로 바꾸지 않고 카드/세로 비교로 표시한다.
- 그래프 좌표로 바꿀 때만 검증된 값을 표시용 number로 변환한다. 금액 저장·금융 판단에는 부동소수점을 사용하지 않는다.
- 비율·금액·원본의 기준시점을 맞춘다. 분모0은 0%가 아니라 미계산/대상 없음이다.
- 신규 투자금 안의 현금성 상품과 별도 생활보호·운영·목표 자금은 서로 다른 구분이다.

## 5. 최소 입력과 기존 응답 재사용

### 5.1 월평균 세후소득

고객 문구: **“월평균 세후소득은 얼마인가요?”**

급여·사업/프리랜서·부업·임대·연금·이자/배당 등 선택 기간의 실제 세후소득 합계÷개월 수를 사용한다. 사업 매출·대출·본인 계좌이체·자산매각대금은 소득으로 더하지 않는다.

금액 상태, 최근3/6/12개월 또는 다른 기간, 시작/종료일, 일회성 포함 여부, 본인/가구 집계 범위를 보존한다. 일회성 금액을 미래 반복소득으로 자동 적용하지 않는다. 구 `monthly_take_home_pay_krw`는 이름만 바꿔 총소득으로 이관하지 않는다. 원문·정의 버전을 남기고 전체 세후소득인지 재확인한다.

### 6.2 상태별 표시

- READY: 비음수 항목·합계·분모 검증 후 그린다.
- PARTIAL: 총액과 확인된 내역이 모두 있을 때만 차이를 `미분류`로 표시할 수 있다. 미분류를 독립적인 투자재원으로 쓰지 않는다. 내역이 총액보다 크면 불일치 안내 후 도넛을 보류한다.
- EMPTY: 확인된 총액0. 빈 윤곽과 `보유 금융자산이 없어요` 등을 보여주며 임의 구성비를 만들지 않는다.
- UNAVAILABLE: 총액/분모 미확인. 금액·비율은 대시, 필요한 보완 CTA를 표시한다.
- 월 지출이 소득을 초과하면 소득·지출의 **세로 막대**와 부족액으로 전환한다. 음수를 도넛에 넣지 않는다.
- 목표 확보액이 필요액을 초과하면 실제 비율·초과액은 문구로 유지하고 링은100%까지만 채운다. 나머지 조각을 음수로 만들지 않으며 초과금을 자동 투자·회수·재배정하지 않는다.
- 선그래프의 미확인 시점은 결측으로 두며0으로 바꾸거나 임의 보간하지 않는다. 비교 가정이 다르면 비교 불가 이유를 표시한다.

### 6.3 라벨·색·대안

도넛 중앙에는 대상과 분모, 범례에는 항목·금액·비율을 표시한다. 항목이 많으면 표시용 `기타`로 묶되 완전한 상세표·원본을 남긴다. 표시용 묶음을 저장 배분의 변경으로 사용하지 않는다.

같은 자산군은 모든 화면에서 같은 색을 사용한다. 예: 주식형 `#087F77`, 채권형 `#426CCD`, 투자 내 현금성 `#D8AF50`, 미분류 회색. 관리안의 선 색·점선은 자산군 범례와 구분한다. 라벨·선 패턴을 함께 사용한다.

차트와 표는 같은 배열에서 만든다. 접근 가능한 제목·요약과 펼칠 수 있는 데이터표를 제공한다. D2에서 삭제한 잔액 반복 표를 기본 화면으로 되살리지 않고, 선그래프의 접근성 상세표를 필요할 때 여는 방식으로 제공한다.

## 7. 화면별 구현 — 빠른진단

아래 숫자는 추가 답변까지 포함한 **FAST-DEMO-02**의 값이다. 실제 고객에게 고정 표시하지 않는다.

### FE-Q1: 내 재무현황과 금융자산 구성

주문구: **“이번 달 돈의 흐름과 보유 금융자산을 한눈에 봐요.”**

표시 순서:

1. 월평균 세후소득300, 생활비160/월 상환20, 유지할 기존 월 투자40.
2. 기초 차액80, 금융자산2,000, 현재 금융투자 비중30%.
3. **월소득 흐름 도넛 + 현재 금융자산 도넛**. 각각160/20/40/80과1,400/600.
4. 간단한 자산 내역, 생활/운영/목표용으로 구분한 돈, 총자산/순자산 확인 상태.
5. 차액80은 목표·현금 여유 배정 전이며 전액 신규 투자금이 아니라는 설명.

동작: `자산 금액 수정`은 F06 보완, `다음 · 두 관리 방식 비교`는 Q2. 상단 수정도 같은 원응답을 편집한다.

누락 분기: 상환액 모름이면 생활비 외 차액까지만 보여주고80 등 후속 금액은 만들지 않는다. 내역 부족이면 총액·보완 안내를 유지한다. 보증금 미확인으로 총자산/순자산이 없어도 금융자산은 제공한다.

### FE-Q2: 생활 안정과 투자 확대를 비교해요

주문구: **“현금 여유를 더 쌓을지, 허용한 범위에서 신규 투자를 늘릴지 골라요.”**

1. 생활 안정/투자 확대의 **월 예산 도넛 두 개**.
2. 같은 순서의 비교표: 생활비·상환·목표·여유금·현금 적립·월 투자 합계(기존+신규)·신규 일시 상한.
3. 초기2,000에서 같은 조건으로 출발하는 **두 안의 통합 선그래프**.
4. 차이의 원인, 선택에 따른 행동/부담, 소득 감소 시 부족과 재계산 CTA.

| 항목(만원) | 생활 안정 우선 | 투자 여력 확대 |
| --- | ---: | ---: |
| 생활비 | 160 | 150 |
| 월 상환 | 20 | 20 |
| 목표 적립 | 20 | 20 |
| 별도 여유금 | 20 | 20 |
| 현금 적립 | 40 | 20 |
| 기존 투자 납입 유지 | 40 | 40 |
| 신규 월 투자 | 0 | 30 |
| 월 금융투자 합계(별도 표시, 재합산 금지) | 40 | 70 |
| 소득 전액 배정 합계 | 300 | 300 |
| 신규 일시 투자 한도 | 0 | 400 |

일시400은 기존 자산 안의 이동이다. 12개월 합계 차이120은 생활비10×12 때문이다. 상한과 검증 후 최종 배정액을 구분한다. 소득240에서 원래 확대 예산300을 유지하면 월60 부족으로, 실행 가능한 안으로 표시하지 않는다.

안을 선택하면 DRAFT만 갱신한다. Q3~Q5의 신규 재원·구성·후보·행동도 같은 선택을 사용한다. 생활비 조정 미동의 시 확대안이 성립했다고 표시하지 말고 조정 확인을 연다.

### FE-Q3: 간이 투자 포트폴리오를 비교해요

주문구: **“투자 구성의 차이를 보고, 내 조건에 맞는 범위를 확인해요.”**

1. 자기보고 투자선호. 미확인 시 설명과 확인 CTA. 나이로 P3 등을 채우지 않는다.
2. `방향 미리보기`와 `개인화 제안`의 범위·현재 확인 상태.
3. A/B/C 도넛 세 개와 구성·일시/신규 월 환산·이유·위험 비교표.
4. 기존 보유600·유지 월40은 별도이며 신규400·신규 월30만 배분한다는 설명.
5. `내 조건 확인하기`, `선택한 구성 · 상품 정보 보기`.

실제 방향 미리보기는 일반 구성·위험을 제공한다. 고객별 배정 금액·비중·후보는 입력과 정책·상품 검증 후 표시한다. 데모에서 환산을 보여줄 때는 **가상 사례의 공통 구성 예시 환산**임을 명시하고 추천 완료·채택을 활성화하지 않는다.

빠른진단 안정안은 신규 일시0·신규 월0이므로 추가 투자금 도넛을 숨기고 기존 월40 유지와 구성 개념을 보여준다. 0분모를 억지 비율로 만들거나 기존40을 신규40으로 재제안하지 않는다.

### FE-Q4: 투자상품 정보를 비교해요

주문구: **“각 구성에 어떤 상품군이 들어가는지 이해해요.”**

1. 주식형/채권형/현금성 상품군의 역할·확인 이유·위험 비교.
2. 펼침 상세: 구조·기초자산·운용 방식·원금손실·비용 구분·통화·유동성·결제/출금 시점.
3. 공식 자료의 기준일·조회일, 시세 시점·지연, 출처.
4. 일반 정보 비교와 개인화 후보의 구분, 부족한 확인 항목.
5. 보유·가입요건이 확인된 경우만 계좌를 간단히 안내. 구체적 절세액은 검증 후.

데모 ETF A/B/C는 가상이다. 실종목·시세·수익률·보수 수치를 만들지 않는다. 조회 실패 시 미조회와 출처/시점을 표시하고0% 비용으로 채우지 않는다. 서버용 API 키를 브라우저에 두지 않는다.

상품을 펼치는 것만으로 안의 선택·비중을 변경하지 않는다. 후보는 해당 선택 버전에 연결한다. 개인화 확인 전에도 일반 상품정보는 볼 수 있다.

### FE-Q5: 내 결과와 이번 달 행동

1. 선택 관리안·투자 구성·검토 상태.
2. **목표 준비 도넛 + 선택한 신규 투자 구성 도넛**.
3. 목표 확보·부족·날짜·월 적립, 신규 일시 상한, 신규 월+기존 월, 월 예산 합계.
4. 이번 달 행동1~3개. 데모는 목표 돈 구분, 생활비10 조정 확인, 신규 투자 조건 확인.
5. 다음 점검, `이 초안 저장` / `다음 점검 기록` / `정밀점검 이어가기`, 상담창.

목표40%는400/1,000, 투자 구성40/40/20은 신규400 안의 배분이다. 같은40을 같은 지표처럼 다루지 않는다. 신규 월30의12/12/6과 유지 월40을 분리한다. 행동 완료 체크만으로 자산·목표잔액을 바꾸지 않는다.

## 9. 비중 조절 동작 명세

### 9.1 편집 단위와 고정 값

UI는0~100%,1%p 단위. 내부 비중은 정수basis point(10000=100%). 합계10000·비음수·각 행 범위를 지킨다. 금융정책의 상한은 별도 서버 검증을 따른다.

- 선택된 **신규 일시금·신규 월 납입**만 편집한다.
- 원금·보호액·목표액·기존 보유·유지할 기존 월 납입은 비중 조작으로 바꾸지 않는다.
- 기본 구성을 복제해 `allocationDraft`를 만든다. 수동 수정 후에는 `CUSTOM · 직접 조정`으로 표시한다.
- 잠금은 비중을 고정하는 UI이며 기존 보유 매도를 허용하는 기능이 아니다.

### 9.2 잔여와 잠금

1. 주식/채권 등을 조절하면 잠금이 풀린 현금성 행에 차이를 반영한다.
2. 잔여 현금성 비중이 음수가 되면 적용하지 않고 가능한 범위를 안내한다. 다른 행을 몰래 정규화하지 않는다.
3. 전체 잠금 시 `조절하려면 상품의 잠금을 풀어주세요.`.
4. **구현 보완:** 현금성 행 자체를 직접 편집하거나 현금성 행이 잠겨 있으면, 차이를 받을 다른 미잠금 행을 고객이 명시 선택하도록 한다. 선택이 없으면 적용하지 않는다. 다른 상품을 자동 매도·비례 재배분하지 않는다.
5. 편집 행과 차이를 받을 행을 한 번에 갱신한다. 어느 한 행이 범위를 벗어나면 이전 유효값으로 유지하고 이유를 표시한다.
6. 숫자 입력 중 빈칸·소수·범위 밖 값은 임시 문자열로 보관한다. 확정 시 검증하며 차트·저장 비중으로 전파하지 않는다.

기본40/40/20 → 주식45 조작 시45/40/15 → 채권35 조작 시45/35/20으로 원본의 직접 조정 예시를 재현한다.

### 9.3 원 단위 배정과 반올림

표시용 기계적 배분 환산은 공유 금액 유틸리티로 가능하다. 금융 적합성·최적 비중 판단과는 별개다. 기존 유틸리티가 없으면 일시금과 신규 월액을 **각각** 다음으로 환산한다.

1. 원금은 비음수 정수 KRW, 비중은 합계10000 정수로 취급한다.
2. `원금 × weightBps ÷ 10000`의 정수부를 행별 배정한다.
3. 남은1원 단위를 나머지가 큰 순서로 지급한다. 동률이면 안정적인 행ID 순서로 처리한다.
4. 각 재원별 배정합이 원금과 같은지 확인한다.

클라이언트 환산은 `미리보기`이며 서버·공통 계산 확정값을 덮지 않는다. 원금 미확인 시 금액을 만들지 않고 구성 개념만 보여준다. 실제 개인화와 채택은 서버 검증이 필요하다.

### 9.4 재검증과 전파

- 수정마다 `draftVersion`을 갱신하고 해당 구성·배정·요약을 같은 버전으로 전파한다.
- 조작 종료/짧은debounce 후 기존 계약의 어댑터를 통해 재검증한다.
- 이전 전망·상품 이유·세금 결과는 STALE/재확인 중으로 둔다. 프론트가 금융 전망을 임의 재계산하지 않는다.
- 수익/세금/비용0 데모에서는 비중 변경으로 금융자산 합계가 늘지 않는다. 다른 수익 가정 등이 연결되면 같은 조건의 재계산 응답을 기다린다.
- 합계100%여도 보호·목표·사용일·기존 노출·제외·상품·정책 위반이면 채택하지 못한다.
- 기본 구성 복원은 편집 잠금을 풀고 원래 기본 비중으로 되돌리는 동작을 제안한다. 변경이 사라짐을 안내하며 별도 채택본은 건드리지 않는다.

## 10. 상품·절세·또래 비교

### 10.1 상품정보 상태

`LOADING / AVAILABLE / PARTIAL / STALE / ERROR / NOT_SUPPORTED`와 같은 자료 상태를 개인 적합성 상태와 분리한다. 자료 조회 성공은 개인화 추천 성공이 아니다.

상품별 식별자·실제/가상 여부·자산군·역할·이유·위험·비용 종류/값/조건·현금화 조건·자료 출처/기준일/조회일·시세 시점/지연을 연결한다. 허용 지연과 이용 범위는 공급 계약을 따르며 임의로 ‘실시간’이라고 표시하지 않는다.

고객 연결 이유는 해당 선택 버전·보유·사용일에 근거한 확인 결과만 사용한다. 연결 근거가 없으면 일반 설명을 보여주고 AI 추정을 확정 근거로 만들지 않는다.

### 10.2 절세

ISA, 연금저축·IRP, 월세·청약, 기타 실제 보유자산을 펼침 패널로 표시한다. 상태는 `적용 가능 / 추가 확인 필요 / 해당 없음`. 소득·계좌·주거·기존 납입·결정세액·귀속연도 등 부족 시 절세액을 만들지 않는다.

**월평균 세후소득과 공제 판단에 필요한 총급여/과세정보는 별개다.** 월평균 세후소득×12를 총급여로 자동 변환하지 않는다. 고정 세율·공제액을 프론트에 하드코딩하지 않는다.

### 10.3 20대 비교

- 지표: 현재 금융투자상품 평가액÷같은 범위 금융자산. 보증금·실물자산은 이 분모에서 제외한다.
- 개인20~29세, 본인/가구, 상품 범위, 조사기간, 표본, 산식, 출처, 확인일을 대조한 자료만 사용한다.
- 개인 비율의 평균과 집계액의 비율, 참여율과 보유 비중, 가구주 나이와 개인 나이를 혼용하지 않는다.
- 현재 투자비중30%와 신규 자금 안의 주식비중40%를 비교하지 않는다.

## 11. 상태·선택·저장·통신

### 11.1 분리할 상태

| 축 | 예 | 의미 |
| --- | --- | --- |
| 화면 통신 | loading / success / error | 데이터 가져오기 상태 |
| 값 | KNOWN / UNKNOWN / NOT_ASKED / NOT_APPLICABLE | 항목별 정보 유무 |
| 계산/추천 | READY / NEEDS_INPUT / NEEDS_POLICY / REVIEW_REQUIRED / INFEASIBLE | 결과 성립·검증 |
| 계획 버전 | CURRENT / DRAFT / ADOPTED / STALE | 수정·채택·기준 변경 |
| 제공 범위 | DIRECTION_PREVIEW / PERSONALIZED_PROPOSAL | 일반 이해/개인화 |

이들을 하나의 `isReady`로 합치지 않는다. 정책 미확인으로 페이지 전체를 비우지 않고 성립하는 현황·일반 정보는 표시한다.

### 11.2 선택과 저장

- 카드 클릭은 DRAFT 선택이며 채택 계획 전환이 아니다.
- B를 기본 표시하는 데모는 시나리오 설정에 한정한다. 실제 고객의 미선택을 무조건B로 채우지 않는다.
- `초안 저장`은 원응답·선택·비중·문맥 버전을 저장한다. 성공 응답 전 저장 완료로 표시하지 않는다.
- `계획 채택`은 최신 검증과 `canAdopt`를 재확인하고 변경·범위를 보여준 뒤 명시 확인한다. 이중 클릭과 버전 충돌을 처리하고 기존 API가 지원하면 멱등 키를 사용한다.
- 데모는 `canAdopt=false`. 데모 저장은 가상 사례임을 표시하고 실고객을 덮지 않는다.
- 저장API가 없으면 메모리/세션 등의 임시 보관임을 명시한다. 영속 저장 성공을 가짜로 표시하거나 고객정보를 무조건localStorage에 저장하지 않는다.

### 11.3 오래된 응답

응답마다 어느 입력·선택에 대응하는지 문맥 키를 연결한다. 입력 변경 시 의존 결과를 STALE로 표시하며 이전 값은 과거 조건으로 조회할 수 있다.

늦게 도착한 이전 응답이 최신 숫자·후보·이유·비중을 덮지 못하게 한다. 요청 중단 기능과 별도로 응답 키를 확인한다. 재시도 때문에 원응답을 초기화하지 않는다.

백엔드 미연결 시 `ReportRepository` 등의 어댑터에 `getReport / previewSelection / validateAllocation / saveDraft / exportSnapshot / getConversation / sendMessage` 중 필요한 기능을 정의하고 기존 구현 또는 명시 모형을 주입한다. URL을 추정해 새 엔드포인트를 이미 존재하는 것처럼 만들지 않는다.

## 12. 상담창

- 닫힌 버튼 → 홈(대화 이어가기/이전 대화) → 대화. 최소화·닫기 → 다시 버튼.
- 닫기·화면 이동으로 대화를 지우지 않는다. 다른 고객/데모와 대화를 섞지 않는다.
- 메시지에 당시 `reportId / draftVersion / plan / option / dataSnapshotId`를 연결한다.
- 구 버전 답변은 이전 조건의 설명임을 표시한다. 새 조건의 답변인 것처럼 자동 표시하지 않는다.
- 전송 중·실패·재시도·이용 불가·대화 없음 상태를 구현한다. 대화 실패로 계산 결과를 훼손하지 않는다.
- 대화에서 제안한 입력/계획 변경은 차이를 보여주고 고객 확인 후 적용·재계산한다. 문장을 읽은 것만으로 자금·비중을 변경하지 않는다.
- 모바일은 대화상자/하단 패널 등으로 구성하되 포커스·ESC·닫은 후 원래 버튼 복귀를 처리한다. 기본 CTA를 가리지 않는다.
- 모형 응답은 모형임을 알리고 실제AI 연결·실행 성공으로 표시하지 않는다.

## 13. PDF·점검·실적

- PDF는 현재 선택의 같은 스냅샷, 모드, 기준일, 초안/채택, 데모, 가정, 출처, 미확인 항목을 포함한다.
- 저장된 과거본과 미저장 편집본을 섞지 않는다. 편집 중 내보내기는 `미리보기`다.
- PDF 내보내기로 새 계산/자료 조회를 임의 실행하지 않는다. 비중과 배정액을 서로 다른 버전에서 가져오지 않는다.
- 인쇄에서는 버튼을 빼고 범례·표·보류 상태를 유지한다. 차트와 표가 잘리지 않게 하고 긴 표는 머리글을 반복한다.
- 기존 PDF 생성이 없으면 인쇄 전용 보기+브라우저 인쇄/PDF 저장을 제공하고 실제 동작에 맞게 이름을 붙인다. 미구현 다운로드의 성공을 가짜로 반환하지 않는다.
- 실제 기록은 계획과 별도 `{실제액, 발생일, 확인 상태}`로 보관한다. 완료 체크만으로 원장·잔액을 갱신하지 않는다.
- 다음 점검은 원안·이번 기간 실제·차이·수정안을 같은 기간으로 비교한다. 가상 한 달 후 시연과 실제 경과를 구분한다.

## 14. 반응형·시각·접근성

원본의 정보 순서를 유지하면서 이후 선택한 디자인을 적용한다. 종이 문서의 작은 글씨·큰 여백을 그대로 웹에 옮기지 않는다.

- 모바일<768px: 1열, 좌우16px, 카드 내부20px. PC≥1024px: 본문 최대1200px, 두 관리안2열·세 투자안3열. 태블릿은 내용에 따라1~2열.
- 본문16px·보조14px·제목24~32px·주금액28~36px·줄높이1.5를 시작점으로 삼는다. 이미 합의한 토큰이 있으면 우선한다.
- 기존 폰트 자산을 확인하고 없으면system-ui 등으로 대체한다. 미설치 폰트를 전제하지 않는다.
- 배경·카드·버튼·본문색은 기존 UI·UX 준비안 토큰을 이어 쓸 수 있다. 새로운 브랜드 색상 확정은 아니다.
- 금액은tabular numerals. 긴 상품명·큰 금액·URL을 줄바꿈하며 페이지 전체 가로 스크롤을 만들지 않는다.
- 모바일 비교표는 같은 항목·순서의 세로 비교 카드로 바꿀 수 있다. 상세표만 영역 내 스크롤을 허용한다.
- 선택은 색+라벨/아이콘. 차트는 색 외 라벨·패턴을 제공한다. 입력마다label·단위·오류 설명을 연결한다.
- 슬라이더는 키보드·숫자 입력을 함께 지원한다. 주요 터치44px 이상, 포커스 표시,200% 확대를 확인한다.
- 본문 대비4.5:1·주요 UI3:1을 확인 목표로 삼는다. 인증 완료라는 뜻은 아니다.
- reduced-motion을 존중한다. 차트 애니메이션을 투자 성과처럼 연출하지 않는다.
