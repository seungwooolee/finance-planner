# dion 설계 인계 요약
작성 2026-11-09 · 원천 스냅샷 2026-11-04
이번 묶음은 계정 간 재무엔진 설계 인계용이다. 원본 문서·질문 파일·앱은 수정하지 않았다.

## 제품·작업 범위
재무 현황·목표 준비·두 관리 방식·투자 구성·실행/사후 점검을 연결하는 웹 서비스다.
- STABILITY_FIRST: 생활 안정 우선안.
- INVESTMENT_CAPACITY: 투자 여력 확대안.
- 현재 상태는 비교 입력. 이전 PORT-01~03은 역사적 식별자다.
- P1~P5 자기보고 선호와 세 투자 구성 개념은 별도다.
이번 작업은 핵심 재무엔진의 설계 보완이다. UI 제작·주문·송금·실상품 조사·전체 서비스 구현은 별도다.

## 이미 있는 것
- 데이터 원칙 FIN-DATA-1.0: 금액·기준일·누락·원장·이력.
- 연결 명세 FIN-MAP-1.0: 입력27묶음·계산/판단45개·설계 질문37라벨.
- 수용 사례39개와 그중34개 사례의 산술 부분 확인 기록.
이는 문서에 기록된 과거 검산이다. 이번 패키지 작성에서 앱 테스트를 재실행하지 않았다.

## 남은 핵심
DEC-02: 보호 설정, 추가 현금 유지, 목표·기존 납입·투자의 배정 순서 및 두 안의 생성 규칙.
예산 상한까지의 산술과 어떤 배분을 제안할지의 정책을 분리한다.
예: 월잔여120만원·선택 목표납입34·H20이면 상한66만원.
생활안정안 투자40·현금26이라는 선택은 추가 정책이다. 확대안도 고객 허용 변경과 제약 안에서 생성한다.
목표 최소 납입333,334원과 선택 납입340,000원을 구분한다.

## 현재 상태의 한계
- 질문 라벨·선택지 이관과 실제 API·DB·프런트엔드 연결은 검증 완료가 아니다.
- 투자배분 ALLOC-0.2는 실험용·미활성. PREF-0.2 score=null.
- 상품 검증·세금/비용·LS 실제 연동·사용권한·운영 상태는 이 묶음으로 완료 처리하지 않는다.
- 0% 수익·비용은 가상 비교 조건이다. 실제 비용·세금이0이라는 뜻이 아니다.
- 실제 계정 잔여 사용량·API 키·실제 고객 데이터는 담지 않았다.

## 최신 흐름의 주의점
질문 파일은 기본11개에 부동산·부채 조건부 상세0~2개를 붙여 최대13개로 설명한다.
인계서의 ‘11개’는 기본 카드 수다. 고객이 답하는 실제 입력 부담과 조건부 상세 수를 별도 집계한다.
소득은 월평균 세후소득으로 통일하되 원문·기준기간·일회성 포함 상태를 보존한다.
DIRECTION_PREVIEW는 일반 구성 설명이고 개인화 추천과 다르다. 자세한 원문은05 파일을 따른다.

## 읽기 비용 줄이기
먼저02·05를 읽고 오늘 변경할 항목을 좁힌다.
03·04·질문 파일·06은 해당 부분만 확인한다.
optional 전체 문서와 발췌본을 처음부터 모두 중복 읽지 않는다.
출력은 변경 명세와 검산 중심으로 작성하고 새 기획서·장식용 파일을 늘리지 않는다.
