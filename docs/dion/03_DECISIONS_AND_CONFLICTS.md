# 확정한 방향과 남은 충돌

## 2026-11-10 현행 보완 — 배정정책1.0

사용자의 “남은 네 가지 배정정책의 비교안을 만들고 확정해줘” 위임으로 보호최소·H·동시부족·두안 신규예산 템플릿을 확정했다. 현행은 [확장 명세7.3절](../financial-engine-spec.md)의 DION-ALLOCATION-1.0이다. 세금·연금·상속 포함도 앞선 사용자 결정으로 반영됐다. 아래 연금제외/DEC-02 미정 문구는 당시 이력이며 현행을 덮어쓰지 않는다. 투자 적합성·계좌/상품·법령 규칙·앱 연결 완료를 뜻하지 않는다.

## 2026-11-10 대조 보완 — 정책 승인 아님

질문40 전수 연결은 `09_UPDATED_FILES/DION_Question_Contract_Audit.json`에 기록했다. 기존47 Q-ID의 부분참조와, 후속 GitHub 고정 소스에서 기존 요청필드11개의 존재를 확인했다. 현행질문9개에 부분참고할 수 있지만 새40 어댑터·DB·enum 이관은 미구현/미확인이다. 원문304선택지와 기존60 ID는 보존했다.

- F03: 질문 `income_amount_status` / 선택지 `amount_status`.
- D19: 질문 `product_understanding_self_report` / 선택지 `product_understanding`.
- D20-1: `account_presence` 잔존그룹과 `tax_account_presence` 병존.
- F08: 보증금 존재 선택지 잔존그룹과 NEW-09의 같은 의미 그룹 병존.
- F04: 대출/저축 포함 여부·포함액 요구에 비해 제안필드·선택지 계약 부족.
- 보험·연금 제외와 시트의 연금/IRP 문구 충돌은 미해결 유지.
- 채무 상세의 월원리금≤잔액은 최신시트 검토대기 규칙으로 보존했다. 원리금의 이자·비용 포함 의미 및 FIN-DATA의 원금 초과상환 검사와 함께 재무타당성 검토 필요. 조용히 완화하거나 운영 규칙으로 승인하지 않았다.

DEC-02의 배정 우선순위·보호 최소·H/추가현금·두안 생성은 계속 미정이다. `DION_DEC02_REVIEW.md`의 명시 후보 검산 통과는 정책승인/권한검사/채택 가능 판정이 아니다.

## 사용자 확정 — 다시 처음부터 묻지 않을 것

- 브랜드: dion(디온), 워드마크dion. 과거LifePath AI/PORTMEW는이력이다.
- 투자중심의쉽고빠른재무컨설팅. 직장인한정아님. 사회초년생·신혼기·출산/양육기·자녀학령기·자녀독립기·은퇴기의6구분을기본맥락으로하고실제목표를따로확인한다.
- 재무설계6단계: 관계/범위·정보이용안내 → 정보/목표 → 분석/평가 → 제안/선택 → 실행지원 → 모니터링/재설계. 단계수와화면수는같을필요없음.
- 개발순서0~5: 방향/MVP → 결과설계 → 필수데이터/질문 → 엔진/안전규칙 → 프론트·백엔드·DB수직통합 → AI/검증/배포.
- 재무계획2안으로투자가능재원을정함: 생활안정우선 / 투자여력확대. 자기보고성향5단계와투자구성3유형은별개. 조건에맞는기본구성1개,‘다른구성보기’에서허용대안비교. 부적합구성은제한하고이유설명.
- 첫화면은현재자산정리와제안구성/이유요약. 화면3금융자산에서투자구성상세. ETF만이아닌예적금·주식·채권·ETF·펀드등대표상품을다룸. 실상품전체순위비교보다는역할·적합가능성·조건을설명.
- 기존보유금융자산도재구성에고려. 전체현황기준으로판단하되신규자금부터조정,필요한기존자산변경만검토. 부동산은기본유지,미확정매각/보증금반환을가용현금으로쓰지않음.
- 보험·연금은MVP진단/추천/재구성제외결정. 기본화면에는매도/교체관련긴설명보다핵심계획을두고상세/AI질문에서설명.
- 국내상장상품우선. 해외노출은ETF/인덱스펀드범위로검토. 직접해외개별주식·선물옵션등확정지원으로확대하지않음.
- 수치/검증은결정적재무엔진. AI는검증결과설명·필요한질문·문맥이해보조. AI문장을읽었다고자금/비중/계획을자동변경하지않음.
- 구성비도넛,기간변화선,금액비교필요시세로막대. 기존프론트명세는가로막대그래프금지. 슬라이더는입력UI라별개.
- 새문서/수정산출물은재무설계공모전Drive폴더에모으는사용자선호. 계정권한없으면오프라인수정본을먼저만들고원본변경을완료로표시하지않음.

## 숫자 예시는 고객을 구분해야 함

**FAST-DEMO-02 (목표가 정해진 사례)**
- 소득300 / 생활150 / 대출20 / 목표20 / 기존투자40 / 신규투자30 / 비상20 / 추가현금20 =300만원.
- 기존투자보유600만원. 신규일시투자상한400만원. 주거목표용400만원과혼동하지않음.

**UI-INV-01 (별도 정밀 예시)**
- 기존월납입0,목표금액/목표배정미확정. 금융자산2000=현금1400+기존투자600.
- 보호840+운영160을별도자산에서유지,신규일시상한400.
- 확대월배분150생활+20상환+20여유+110투자=300만원이라는별도조건.
- 45/35/20%는직접조정데모,운영권장정책아님.

110자체가산술오류는아니다. Stitch일부정밀화면에서‘기존월40별도유지’와‘신규110’을동시에표시해혼합오류가생긴다. 목표20까지유지하면월배분이60만원초과한다. 다른fixture라면화면에식별자와전제를명시하고,같은고객이라면그입력으로다시계산해야한다.
