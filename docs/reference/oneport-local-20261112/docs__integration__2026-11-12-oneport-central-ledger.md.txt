## 중앙 원장 구현

`backend/migrations/be/003_oneport_ledger.sql`은 **로컬 임시 DB에서만 적용**했다. 별도 dion_oneport 스키마에 budgets/calls/aliases를 만들고 PUBLIC 접근을 회수한다. 새 migration 전체를 운영에 적용하지 않는다. 003 SHA256 `fb4df93328342133389a0b5b2ac595a0d259d165b88554369602971e9c81ac04`.

`app/explanation/oneport_postgres.py`는 연결별 transaction·scope 행 잠금과 alias/operation transaction 잠금으로 직렬화한다. 메모리/한 호스트 파일 공유를 전제로 하지 않는다.

| 기존 의미 | 중앙 구현 |
| --- | --- |
| operation/alias/fingerprint | 해시 생성식 유지, PK/FK·해시 형식 제약, 같은 alias의 다른 fingerprint는 충돌 |
| 같은 request_key·모델 변경 | 원래 operation에 연결하고 새 paid 요청을 만들지 않음 |
| 예산·최대 호출 수 | scope 잠금 아래 전체 charge/호출 수 합산. 같은 scope의 cap 변경은 충돌 |
| 요청 전 예약 | PENDING·별칭 commit이 끝난 다음 dispatch |
| 응답/비용 불명확 | PENDING/FAILED와 예약 보존.0 처리·만료·재생성 없음 |
| 비용 정밀도 | NUMERIC↔Decimal. 보고액이 낮아도 기존 예약 유지, 높으면 반영 |
| 성공 재사용 | 검증된 ID 선택·정제 telemetry를 저장하고 현재 검증기로 다시 검사 |
| DB 장애 | 호출 전 실패. SQLite fallback·자동 DDL 없음 |

DB 작업은 asyncio.to_thread에서 실행하며 lock_timeout2초/statement_timeout5초를 둔다. 취소/중단 때 남은 예약은 자동 해제하지 않는다. `/readyz`의 명시 DB 검사에는 중앙 스키마/필수 권한/PUBLIC 검사를 연결했다. 시작 시에는 설정 검사만 한다. 전체 보안 감사·관리형 DB HA·실제 청구 정합성 검증을 대신하지 않는다.

## 활성화와 기존 기록 이관

기본 설정은 계속 SQLite/UNCONFIRMED/생성 비활성이다. 중앙 원장 선택은 기존 DION_DB_* 설정과 다음 명시 설정을 사용한다. 운영 환경은 변경하지 않았다.

```dotenv
DION_ONEPORT_LEDGER_BACKEND=postgresql
DION_ONEPORT_LEDGER_SCOPE=MULTI_HOST
DION_ONEPORT_POSTGRES_CUTOVER_CONFIRMED=false
```

전환 순서: 모든 기존 호출자 중지 → 모든 원장의 PENDING/실패/비용 기록 확보 → 운영003 별도 승인·적용 → 계획 검토·명시 import → 건수/상태/비용/별칭 대조 → 준비 검사 → cutover 선언. 기록이 전혀 없던 경우도 근거를 남긴다. **선언은 이관 완료 증거나 유료 호출 승인이 아니다.** 기존 key/model·예산·만료·고객정보 전송 gate도 계속 적용한다.

```powershell
# backend. 계획은 PG/AI에 연결하지 않고 source도 변경하지 않는다.
python -m app.explanation.oneport_cutover C:/absolute/old-receipts.sqlite3
# 출력의 논리 snapshot SHA 검토 후 승인된 대상 환경에서만 별도 실행.
python -m app.explanation.oneport_cutover C:/absolute/old-receipts.sqlite3 --apply --source-sha256 REVIEWED_SHA --confirm-old-callers-stopped
```

import는 SQLite BEGIN IMMEDIATE 아래 읽고 PG 한 transaction으로 정확한 charge/state/draft/telemetry/alias를 보존한다. 같은 기록은 재적용 가능하며 충돌/원본 변경은 전체 rollback한다. 원본은 삭제/갱신하지 않는다. 현재 importer는 한 승인 budget_scope만 받으며 다른 scope가 섞이면 생략/추측하지 않고 중단한다. 여러 scope/출처의 실제 전환은 승인 한도와 원본별 추가 이관 계획이 필요하다. CLI 설정은 현재 프로세스 환경에서 읽으며 `.env`를 자동 복사/로드하지 않는다.

복귀 시 provider 비활성·코드 복귀를 우선하고 모든 원장을 보존한다. 테이블 DROP·예약 삭제·예전 SQLite로 무검증 복귀는 중복 비용 위험이 있어 자동화하지 않았다.

## 실제 검사·미실행

[PostgreSQL 공식 Windows 안내](https://www.postgresql.org/download/windows/)가 연결하는 [EDB archive](https://www.enterprisedb.com/download-postgresql-binaries)의 PostgreSQL17.12를 별도 도구 폴더에 풀고 127.0.0.1:55439 임시 클러스터만 실행했다. 시스템 서비스/기존 서버를 변경하지 않았다. archive의 로컬 SHA256 기록은 `a2cd8a774389347b70be7748ac4a37ef43cb6ee539c5fc3e85ae264b15e4a04c`이며 vendor 서명 검증이라고 표현하지 않는다. 테스트는 새 UUID DB만 생성/정리한다.

새 작업본 backend에서 AI 작업본의 기존 `.venv/Scripts/python.exe`를 사용했다.

```powershell
$env:DION_TEST_PG_PORT='55439'
python -m pytest tests/be/test_oneport_postgres.py tests/be/test_oneport.py tests/be/test_readiness.py tests/be/test_migration_plan.py -q
# 86 passed, 63.25s: 중앙PG17 + 기존OnePort54 + readiness13 + migration2.
python -m pytest tests/be/test_oneport_central_config.py -q
# 신규 차단/준비 연결6 passed, 1.17s.
python -m pytest tests/be/test_oneport_postgres.py -k receipt_header_failure -q
# 리뷰에서 저장 예외가 일반 ValueError에 먼저 잡히던 분류 순서 보완. 신규1 passed, 3.84s.
```

고유 **93개 통과**, 단일93개 실행은 아니다. 독립 연결의 동일 operation/alias 경합, 서로 다른 operation의 예산·호출 한도, 별도 앱 프로세스 재개, 미확정/정확한 비용, 모의 dispatch1회, 성공/PENDING 이관·충돌 rollback, schema 누락/노출, cutover 차단을 포함한다. 실제 다중 원격 호스트 장애/관리형 DB 재시작은 미실행이다.

Ruff 최초 fixture import 경고는 명시 재사용으로1회 수정했고 변경 Python 검사 통과. 전체 Core/Build/FE E2E·실계정R2·실제AI·원격003·commit/push·배포는 미실행이다. 추가 문서 링크 확인 통과, 새 파일 후행 공백0·git diff --check 통과. 이번 임시 PostgreSQL은 소유 경로/프로세스를 확인한 뒤 정상 종료했고 기존 서버는 종료하지 않았다. 임시 클러스터 폴더 삭제는 자동 승인 검토에서 blocked by policy로 거부되어 미실행이다. 복원 사본은 접근 권한을 현재 사용자/SYSTEM으로 제한한 도구 폴더에 남겨 두었고 제한 ACL 백업 archive/manifest도 보존했다. 이 잔여 사본은 수동 정리 대상으로 남는다.
