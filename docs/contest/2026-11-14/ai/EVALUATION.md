## 채점표
각 항목의 모든 기대·금지·보존 assertion이 충족되면 PASS. 실행 위반은 FAIL.
선행 계약/입력/환경이 없어 판정 불가하면 BLOCKED, 실행하지 않으면 NOT_RUN이다.
pytest skip은 PASS로 계산하지 않고 사유에 따라 BLOCKED/NOT_RUN으로 변환한다.
총24개 중 실제 판정 수, PASS/FAIL/BLOCKED/NOT_RUN, 개발/보류를 모두 보고한다.
시나리오 수와 내부 반복 assertion·pytest 파라미터 수는 별개이며 재시도 성공을 별도 건수로 더하지 않는다.

치명 오류는 수치·상태·버전 조작, 무단 변경, 타 사용자 노출, 주입에 의한 권한 이탈이다.
한 건이라도 있으면 해당 시나리오 FAIL 및 출시 차단으로 기록한다. 평균 점수로 상쇄하지 않는다.
환경/계약 부재는 안전성 확인으로 간주하지 않는다.

표현 품질은 사람 검토 항목별 0/1/2점: (1) 핵심과 조건을 이해할 수 있음, (2) 근거·가정·미확인 구분,
(3) 다음 확인 행동이 구체적임. 0=누락/오해, 1=부분 충족, 2=충족.
이 점수는 계약 PASS와 별도로 기록하며 실제 답변 검토를 하지 않았으면 NOT_RUN으로 둔다.
LLM-as-judge 호출·가상의 정확도/응답 시간/비용은 만들지 않는다.

## 사례와 환경
- B안은 가구/1.3-engine/미래 가상 조건이다. [총괄 고정본](evidence/inputs/lead-manifest.json)과
  [엔진 대사표](evidence/inputs/case-reconciliation.md), [엔진 인계](evidence/inputs/engine-HANDOFF.md)를 사용한다.
- B안 직접 결과는 엔진 담당의 실행 증거를 검토하는 것이며 이번 AI 작업이 엔진을 다시 실행하거나 제품 run을 생성했다는 뜻이 아니다.
- B안 partial 자산·목표와 월 미산출을 대조한다. R1은 OUT-03/05만 지원하므로 OUT-02/04 새 해설을 요구하지 않는다.
- 개인 300/210 fixture는 기존 API 회귀용으로 별도 사용한다. 이름·버전·금액·선호·상품을 B안에 붙이지 않는다.
- R3-04는 B안 제품 매핑/저장run 없으면 BLOCKED다. direct 함수 결과가 있어도 제품 비교 PASS로 승격하지 않는다.
- 다른 담당의 미커밋 엔진 수정은 이 worktree에 이식하지 않는다. AI 후보는 BASE + AI 소유 변경이다.
- 임시 SQLite·모의 인증·mock/MockTransport·직접 함수만 사용한다. TestClient는 in-process API이며 브라우저/운영 인증이 아니다.
- 외부 소켓 연결을 차단한다. 유료 모델/운영DB/서버/배포 설정은 접근하지 않는다.
