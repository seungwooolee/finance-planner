# 계산 기준의 근거와 검토 상태

## 2026-11-10 배정정책1.0 보완

사용자가 남은 네 정책의 비교·확정을 위임했다. 대안·선택 이유·수치 영향·정확한 산식은 [중심 명세7.3절](financial-engine-spec.md)에 기록했다. `DION-ALLOCATION-1.0`은 서비스 정책이며 법령·최적 투자비중·고객 채택과 구분한다. 독립 기대값과 실행 결과는 [이번 기록](integration/2026-11-10-allocation-rules.md)을 따른다. 아래 Iteration1의 수식·사용자 지정 정답은 바꾸지 않았다.

금융 계산의 현재 계약은 [Iteration 1 명세](iteration-1-spec.md), 실행 구현은 `backend/app/engine.py`이다. 이 문서는 새 계산식을 정하지 않고 **사용자 지정 기준과 기존 구현 선택의 출처**를 기록한다. 테스트 통과는 입력에 대한 구현의 일관성을 뜻하며 경제적 가정의 적절성이나 미래 수익을 검증하지 않는다.

| 정수 원, 금액 상한 1조 원, 기간 1~600개월, 나이 18~100 | 기존 입력 경계, 검증됨 | 서비스 대상 및 상품 한도로 확정한 규정이 아님 |
| 목표 달성 = 목표재원 충족 + 미충당 적자 없음 | 기존 결과 판정 규칙, 회귀 검증됨 | 달성률만 보고 계획의 실행 가능성을 판단하지 않음 |

## 해석상의 한계

- `current_liquid_housing_funds`는 **현재 주거목적으로 사용할 저축**이다. 비상자금 등 모든 유동자산을 뜻하지 않는다.
- `goal_funds`는 목표월 이전에는 주거 저축만, 목표월에는 조건을 충족한 반환 보증금을 포함한다. 현재 순자산과 다르다.
- `unfunded_shortfall`는 실제 신규 대출 잔액이 아니다. 기존 엔진은 이를 순자산에서 자동 부채로 차감하지 않는다. 미충당 적자가 있으면 경고와 실행 불가능 상태를 함께 해석해야 한다.
- `projected_net_worth`는 기존 가정에 따른 잔액이며 원리금 상환·세금·자산 처분 비용 등을 반영한 종합 재무계획이 아니다.
- 금액은 Decimal로 계산하고 JSON 문자열로 반환한다. 차트 좌표와 표시 형식을 제외하고 JavaScript Number로 금융 공식을 다시 계산하지 않는다.

## 새 계산 기준을 정할 때

다음 내용을 작은 변경 제안에 기록하고, 핵심 기준 변경은 구현 전 승인을 받는다.

1. 해결할 사용자 문제, 입력·출력, 적용 시점과 단위.
2. 근거 또는 사용자 가정, 미확정 사항과 가능한 대안.
3. 기존 기준 고객에 미치는 영향과 독립적으로 계산한 정답 예제.
4. 기간·반올림·오류·경계값 규칙과 회귀 검증 범위.
5. 승인 상태, 결정 날짜와 관련 명세/테스트.

물가 적용 주기, 지출 분류, 연율→월율 변환, 이직 공백, 대출 상환 방식, AI 제안의 검증 규칙은 아직 결정하지 않았다. 이번 정비에서 계산 코드와 기존 정답은 변경하지 않았다.
