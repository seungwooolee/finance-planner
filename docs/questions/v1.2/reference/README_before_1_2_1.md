# DION 질문 설계 v1.2 — 생애단계·목표별 최소 입력

사용자 요청일 2026-11-10 · Asia/Seoul. 현행 Google 시트에 직접 반영한 질문·분기·결과 연결 설계다. 금융 계산식·법령·앱 어댑터 구현과 구분한다.

## 적용 기준

- 현행 질문은 기존40개를 보존·보완하고15개를 추가한55개다. 설계 ID와 기존 영속 Q-ID60개는 별개이며 자동 이관하지 않는다.
- 빠른진단은 기본11개(목표금액1개는 선택)+부동산·채무 해당상세0~2개다. 만 나이는 첫현황의 필수 카드에서 빼고 생애단계를 넣었다. 나이는 필요한 후속 결과에서 확인한다.
- 대표 생애단계1개+겹치는 단계+고객이 확인한 실제 목표로 질문을 고른다. 나이로 단계를 확정하거나 단계로 목표·위험등급·투자비중을 만들지 않는다.
- 정밀진단은 직접 시작할 수 있다. 이미 확인한 답변은 소유자·기간·정의·출처가 맞을 때 재사용하고 필요한 부족 항목만 펼친다.
- 질문 카드 수와 실제 입력칸·반복 대상·자료찾기 부담은 별도다. 최대55개를 모든 고객에게 질문하거나 상세를 한 카드에 숨겨 최소질문으로 표시하지 않는다.

생애단계별 별도 설문6개를 복제하지 않는다. 소득변화는 NEW-02, 예정 지출·가족지원은 NEW-05, 목표는 F11~13을 재사용한다. 학령기·독립기 지원이 실제 목표이면 EDU-01을 확장한다. 투자 미요청이면 투자선호·파생 질문은 생략한다.

## 엔진 연결

`DION_Adaptive_Question_Contract_v1_2.json`에55개 질문의 원문·제안 필드·결과 의존성과14개 결과 게이트를 기록했다. 기존40의 영속ID 부분참조는 이력으로 보존하며 새 문구·enum의 자동 이관 허가는 아니다. 실제 새 API/DB 바인딩은 null이다.

결과는 필요한 사실→지원 산식/법령/정책→현재 구현상태를 각각 확인한다. 입력이 부족하면 영향받는 결과만 NEEDS_INPUT으로 남기고 확인된 현황을 제공한다. 모듈 미구현은 NOT_IMPLEMENTED, 구현된 범위 밖은 NOT_SUPPORTED로 구분한다. 현재 세금·연금·상속 법령 활성 규칙은0개다. 미지원·미구현이면 민감한 상세자료를 더 받기 전에 안내한다.

## 중복·시점 규칙

- 가구현황은 동의한 지분범위로 집계하고 세금·연금은 개인별 귀속을 확인한다.
- 세후소득의 원천세·급여공제 연금과 기존 생활비 포함액을 재차감하지 않는다.
- 연금 계좌잔액·납입·현재수령·미래예상을 분리한다. 국민연금 보험료 누계나 DB 예상급여를 현재 현금자산으로 만들지 않는다.
- 받을 상속은 이미수령/발생후절차중/미래예상으로 나눈다. 미확정 미래상속은 현재자산·확정투자재원에 넣지 않는다.
- 알려진 본인 세후수령액을 확인하는 경우 전체 피상속인 재산을 요구하지 않는다. 상속세 자체를 계산하려는 경우에만 전체 재산·채무·과거증여·공제 등의 추가자료와 법령 검증을 요구한다.
- 이미 자산에 반영한 상속을 다시 더하지 않는다. 가구 내부 상속은 집계범위 내부 이전이고 세금·비용은 관련 경제사건으로1회 반영한다.
- 사건일·상속개시·분할확정·수령·현금화·세금납부일은 별개다.

## 공모전6단계

상담범위 확인 → 정보·목표 수집 → 상황 분석 → 대안 제시 → 실행 지원 → 경과·상황 점검을 유지한다. 생애단계 분기는 정보·목표 수집의 일부다. PLAN-01은 검증된 안의 명시 선택·일정, REV-01은 채택버전의 실적과 변경분을 다룬다. 계획채택과 실제 금융거래는 구분한다.

근거: [주최 협회6단계 설명](https://www.ifpk.org/?data_usn=182167&mnu_usn=362&mode=view&page_no=1). 세금·상속·연금의 공식 구조 출처는 JSON의 sources에 있다. 출처조회는 법령 산식 활성화를 뜻하지 않는다.
