# 상품 설명 RAG 등록 1.0

2026-11-15 사용자 후속 위임으로 자료를 찾아 확인하고 설명 등록·푸시·PR까지 진행한다. 초기 [미연결 감사](REVIEW.md)는 당시 상태로 보존한다. **이번 통과 범위는 상품별 설명·인용 연결이다. 신규 24개를 개인화 배분 대상으로 승인한 것이 아니다.**

## 등록과 판정

- PRD 30개(기존 6 + 신규 24)·CON-16~21을 추가한다. 기존 공개 corpus 29개와 합쳐 **65개 자료·199개 주장**이다. 상품 29개와 개념 6개는 명시된 일반 설명 범위로 등록하고, **PRD-0091C0은 CONFLICTING**으로 등록해 설명·인용 노출을 보류한다.
- 원문을 그대로 옮긴 자료와 요약을 혼동하지 않도록 `REVIEWED_SUMMARY`를 추가했다. 출처 제목·발행 주체·응답 안내·citation의 source_kind에 AI 내부 검토 요약임을 표시한다. 독립된 전문가 검증이나 금융회사 적합성 인증으로 표시하지 않는다.
- [수집 문서](../../../../data/rag/source/product-expansion-20261115/documents.json)의 고객 질문 예시·작성 지시·AI 답변 지시는 검색하지 않는다. 새 CON의 정의·쉬운 설명·주의와 PRD의 확인값/미확인/상충만 구조화했다. 모든 새 주장에 자료 시점 조건과 보장·개인 추천 금지의 예외를 필수 연결한다.
- 등록 요약의 확인일·적용 시작은 2026-11-15, 재검토 기한은 2026-12-31이다. 이는 자료 관리 기한이며 법령/상품 설명서의 효력일을 새로 정한 것이 아니다. 과거 자료의 기준일·효력일·조회일은 분리한다. 새 요약으로 과거 run의 공시값을 덮어쓰지 않으며, 요약 확인일 이전 진단 기준에는 fallback한다.

## 실제 연결과 보존

- 기본 서버는 별도 `data/rag/registry/corpus-products-20261115.json`을 사용한다. 명시적인 `DION_RAG_REGISTRY_PATH` 설정과 `none`은 계속 우선한다. 과거 `data/rag/registry/corpus.json`과 고정 AI 평가 자료는 바이트 단위로 보존한다. `python -m tools.product_rag_ingest`로 같은 입력에서 동일 corpus를 생성한다.
- 기존 `DION-PORTFOLIO-EVIDENCE-1.0`에 `topic=product`를 추가했다. 인증·소유권·현재 run·입력버전/hash를 확인하고 **그 run의 OUT-06에 실제 있는 코드**만 `PRD-{code}`로 조회한다. 기존 위험/비용/환율/현금화 주제는 기존 후보 제한과 CON 매핑을 유지한다.
- 참고 전용 상품도 `product` 주제의 설명만 조회할 수 있다. 이것이 추천 대상 승격을 의미하지 않는다. 없는 PRD는 fallback, 타인 run·임의 코드·오래된 입력은 거부한다. 개인 적용 `NOT_ASSESSED`, 결과 변경 false, 거래/채택 미실행을 유지한다.
- 결과 화면의 기존 설명 주제에 ‘상품별 확인 자료’를 추가하고, 조사 상품 목록 아래의 접힌 영역에서 참고 상품 설명을 연다. 클릭 전 호출은 없고 유료 모델 설정을 활성화하지 않는다. 엔진의 과거 수치와 현재 조회 요약을 문구로 구분한다.
- 카탈로그·기본 슬롯·원응답·질문·Decimal·원/만원·배정정책을 변경하지 않았다. 기존 활성 후보 6개·기본 슬롯 3개, 배분/미배분 독립 기대값을 유지한다. 위험등급 확인만으로 안정 선호의 한도 숫자 6을 낮추거나 제외 금액을 재분배하지 않는다.

## 검증과 전달

관련 pytest **102 passed (82.15s)**, TypeScript 및 변경 FE 2파일 ESLint·변경 Python 8파일 Ruff 통과다. 검사 범위는 36개 새 등록 항목의 인용/조건/예외, 0091C0 상충, 미확인·과거 자료 유지, 날짜/연도/기한, 재현 생성, 원본 corpus/평가 보존, 실제 SQLite/API의 소유권·입력버전·금융 결과 불변, 기존 금액 정답이다. 빌더의 초기 Python 엄격 tuple 검증 오류는 기존 로더와 같은 JSON 검증 경로로 한 번 수정했으며 스키마를 느슨하게 만들지 않았다. 최종 정적 검토에서 참고 상품 패널에도 기존 후보와 같은 run/hash/token 초기화 key를 추가해 이전 결과가 남지 않도록 했고 해당 파일의 lint도 통과했다.

브라우저 E2E·전체 로컬 Core/Build·유료 실모델·운영 DB·배포는 미실행이다. PR에서 자동 실행하는 Core 결과는 로컬 관련 검증과 구분한다. 이 자료가 개인 추천 전수 검증, 실시간 계좌 취급·유동성/최저 비용 검증을 뜻하지 않는다.

작업 브랜치 `codex/product-rag-review-20261115`의 Vercel 자동 배포를 false로 추가했다. Render는 사용자의 기존 차단 설정 완료 확인을 따르며 설정을 바꾸지 않는다. 푸시·PR까지만 진행하고 병합은 사용자가 수행한다.
