## 범위와 완료 조건

사용자 요청은 미지원 반복 지출 질문 제거와 F04/NEW-06의 쉬운 표현이다. 입력 계약·질문 원문·영속 식별자·정의 버전·원응답·금액 단위·Decimal 엔진·배정 정책은 변경하지 않는다. 신규 질문이나 필수 필드를 추가하지 않는다.

- `backend/app/planning/question_v12.py`의 F13 어댑터는 명시적인 `ONE_OFF`/`ONCE`와 같은 시작·종료일만 지원한다. 기존 화면의 `RECURRING` 선택은 계산에 쓸 수 없는 상세 입력을 추가로 받고 있었다. 별도 ‘어떻게 쓸 돈인가요?’와 반복 지출 입력을 일반 목표 화면에서 제거했다.
- 신규 목표는 ‘한 번에 필요한 목표 금액’을 입력한다. 기존 예상 금액 확인란을 ‘위 금액은 그때 한 번에 쓸 목돈의 예상 금액이에요’로 합쳤다. 고객이 확인할 때만 `ONE_OFF`/`ONCE`와 입력한 날짜를 기록한다. 단순 렌더링·금액 입력만으로 사용 형태나 미래 명목금액 확인을 생성하지 않는다.
- 날짜 미정은 미정으로 남긴다. 목돈의 목표일을 미정으로 바꾸면 연결된 지급일과 미래 명목금액 기준일을 비워 오래된 날짜로 계산되지 않게 한다. 저장된 현재가치(`CURRENT_VALUE`) 기준일은 별도로 보존한다. 기존 정확한 날짜는 고객이 날짜를 수정하기 전까지 유지한다.
- 기존 반복 지출 목표는 저장된 월 금액/기간을 읽기 전용으로 보여주고 계산 미반영을 알린다. 자동 목돈 변환·금액 환산·삭제는 하지 않는다. 고객의 ‘목표 삭제’는 기존 보관/복구 경로를 사용한다. 검토용 상세 원응답 편집기는 기존 계약을 유지한다.
- 미래 반복 지출 계산·생활비와의 새 중복 정산·상품/AI/채택·DB 변경은 범위 밖이다. 매달 생활비는 기존 F04로 안내하며 미래 반복 지출을 현재 생활비에 자동 합산하지 않는다.

## 문구와 값의 대응

| 기존 표시 | 새 표시 | 유지한 값/의미 |
|---|---|---|
| 생활비만 알아요 | 생활비만 입력할게요 | `LIVING_ONLY`, 상환·저축·투자 이체 제외 |
| 통장에서 나간 돈을 알아요 | 상환·저축까지 합친 전체 금액을 입력할게요 | `TOTAL_OUTFLOW`, 생활비+상환+저축·투자 이체 포함 |
| 한 달에 통장에서 나간 돈 | 한 달 생활비·상환·저축을 합친 전체 금액 | `living` 원응답, 포함 상환/이체를 별도 확인 |
| 고객 유지목표 정의 | 남겨둘 돈은 어떻게 정할까요? | `customer_target_mode` |
| 정책 최소만 검토 | DION의 기본 기준으로 정할게요 | `POLICY_ONLY` |
| 내가 정한 총목표 | 남겨둘 총금액을 직접 정할게요 | `TOTAL_TARGET` |
| 최소액 위 추가목표 (계산 미지원) | 기본 금액에 더 보탤게요 (계산 미지원) | `EXTRA_ABOVE_MINIMUM`, 기존 지원 경계 유지 |
| 미정 | 아직 정하지 못했어요 | `UNKNOWN`, 0으로 채우지 않음 |
| 보호자금 총목표 | 비상자금으로 남겨둘 총금액 | `customer_protection_total` |
| 운영현금 총목표 | 평소 지출을 위해 남겨둘 총금액 | `customer_operating_total` |

NEW-06은 이미 확보한 돈을 포함한 **총목표**이고 추가 납입액이 아님을 설명한다. 두 용도의 중복 입력과 기본 정책보다 낮은 목표의 처리도 안내한다. 정책의 3개월/1개월 기준이나 기존 확보액을 바꾸지 않는다.
