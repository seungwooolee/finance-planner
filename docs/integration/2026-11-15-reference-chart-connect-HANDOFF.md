# 참고 통계 그래프 연결·배포 응답 대조 — 2026-11-15

## 확인한 원인
- 사용자 화면: `https://dion-review.vercel.app/dion`.
- 저장소에 보유자산 그래프와 `run_frontend_questions → attach_peer_reference` 연결은 존재한다. 기존 생활단계 화면은 집단 선택 전에는 지표가 없었고 선택 후에도 숫자 카드만 표시했다.
- 등록된 공개 BE `https://dion-api-review.onrender.com/api/fe/v1/preview`에 가상 fixture를 전송한 실제 응답은 `CALCULATED`지만 `result.peer_reference`가 없었다. `/api/deployment-info`도 404였다. 정확한 배포 SHA는 확인하지 못했다.
- FE 경유 공개 API는 사이트 암호 게이트의 401로 직접 검사하지 못했다. 이 결과만으로 Vercel의 실제 BACKEND_URL 설정까지 확인했다고 주장하지 않는다.
- 로컬 3000은 과거 v6 폴더에서 실행 중이며 8202의 응답에도 통계가 없었다. 사용자가 보고한 배포 화면과 로컬 상태는 분리한다. 기존 서버·설정은 변경하지 않았다.

## 수정
- 생활단계 통계는 전체 가구(C07)를 기본 참고 집단으로 표시하고, 검토된 KRW 행에 그래프를 연결했다. 다른 집단은 직접 선택한다. 생활단계로 사용자와 통계 집단이 같다고 판정하지 않는다.
- 금액축은 기존 `assetAxis/assetBar`의 좌표 계산만 재사용한다. 범위가 맞고 서버가 제공한 내 값만 함께 표시한다. 모름/미입력을 0으로 바꾸거나 통계로 투자 예산·권장액을 계산하지 않는다.
- 기존 자산 그래프·원문 출처·공표일·평균/중앙값·보류 수치를 유지한다. 저장된 원응답·결과 스냅샷을 바꾸거나 현행 통계를 과거 결과에 주입하지 않는다.
- 새 응답에 통계가 없으면 서버 연결 누락으로 안내하고 무조건 재계산하면 해결된다는 버튼을 제거했다. 과거 저장 결과는 원본 보존과 새 계산 생성을 구분한다. 자산·생활단계의 동일한 누락 안내를 중복 표시하지 않는다.
- BE·엔진·API 계약·통계 원장·금융 계산 변경 없음. FE 작업 브랜치의 자동 배포를 차단한다.

## 실제 검사
- 최초 `npm run typecheck`는 Windows 실행기 오류로 시작하지 못했다. 같은 Next typegen/TypeScript를 설치된 Node로 직접 실행한 1회 보정은 통과했다.
- 변경 TS/TSX ESLint 통과. 검사 준비 코드를 좁힌 후 해당 테스트 파일 ESLint만 추가 확인했다.
- 최초 컴포넌트 브라우저 검사는 전체 BE 앱의 TestClient 준비가 45초를 넘겨 실패했다. 1회 보정으로 공개 preview가 호출하는 기존 `run_frontend_questions`를 직접 사용했다. HTTP/API 종단 검증과 구분한다.
- `DION_PYTHON=<기존 backend venv python>`, `PLAYWRIGHT_BROWSER_CHANNEL=msedge`, `playwright test e2e/dion-reference-connect.spec.ts --workers=1 --reporter=list`: **2 passed (15.8s)**. 실제 기존 엔진이 만든 28행 스냅샷으로 1440×1000/390×844의 자산·생활단계 그래프, 기본 집단, 개인/가구 불일치 시 내 값 비노출, 가로 넘침 없음, 원본 불변을 확인했다. 통계 누락 새 응답과 과거 저장 결과의 다른 안내·동작도 확인했다.
- 새 FE/BE 검증 서버 시작은 자동 승인 검토에서 `blocked by policy`로 거부됐다. 우회해 시작하거나 기존 서버를 종료하지 않았다.
- 전체 Build/E2E, 실제 로그인·DB·배포 사이트의 인증된 UI, 실제 FE 프록시 설정, 유료 AI 호출·운영 배포는 미실행이다. 컴포넌트 브라우저 검사와 실제 배포 연결 성공은 별개다.

## 배포 담당에게 필요한 조치
1. FE가 실제 연결하는 BE의 실행 소스가 `attach_peer_reference`를 포함하는 통합본인지 확인한다. 합성 fixture의 새 preview 응답에서 `peer_reference.version=DION-PEER-REFERENCE-1.0`, records 28행, 표시 허용 15행을 확인한다.
2. 별도 배포 승인 후 BE의 최신 통합본을 반영하고 FE의 실제 프록시 경유 새 계산을 확인한다. 기존 저장 결과를 덮어쓰거나 과거 스냅샷을 최신 통계로 바꾸지 않는다.
3. FE PR 반영 후 새 계산의 자산 그래프·기본 생활단계 그래프와 출처를 배포 사이트에서 확인한다. 오래된 저장 결과는 새 결과 생성으로 분리한다.

후보 SHA/PR은 이 문서가 포함된 작업 브랜치/PR에 기록한다. 원격 병합·배포·운영 DB 변경은 수행하지 않는다.

## 최신 통합 동기화
PR #71 생성 후 integration `6d57f9c`(PR #69 로그인 복구)가 반영되어 문서 2개와 Vercel 설정이 충돌했다. 양쪽 기록과 브랜치별 배포 차단을 모두 유지했고 로그인/선행 연결 변경을 보존했다. 그래프 코드의 추가 변경은 없으므로 기존 통과 브라우저·로컬 타입 검사를 반복하지 않았다. 충돌/공백 및 Vercel JSON을 확인하고 최신 조합의 필수 CI는 PR #71에서 확인한다.
