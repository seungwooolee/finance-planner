## 구현과 확정 정책

[권위 필드·상태·실패·FE 계약](2026-11-15-checkin-followup-contract.md), FastAPI `checkin_followup_contract.py`와 OpenAPI를 따른다. plan_id/plan_version을 새로 만들지 않는다. 월 기록은 처음 명시한 adoption_id 또는 일반 기록(null)에 고정하며, 현재 선택이 달라져도 원래 run/input_version/strategy와 같은 기록월로 비교한다.

사용자의 미확정 정책 검증·확정 위임으로 생활비·원금+이자 상환·기존 INVESTMENT/NONCASH 월 납입·신규 월 투자 후보금/실제 납입·추가 현금 보유분의 동등 조건을 확정했다. 서버 KST에서 월이 끝난 CLOSED 기록의 개별 항목에 같은 범위·월전체·금액 의미 확인이 있어야만 실제−계획을 정확한 원 문자열로 계산한다. 다른 항목이 null이어도 확인된 항목만 점검하고 부분 기록 전체를 평가하지 않는다. 0원과 null은 다르다.

소득/예산 자원, 목표 목적배정/실제 이체, 비상금/보호보충은 **현 입력으로 비교 불가**로 확정했다. 의미가 다른 금액의 차액·성공/실패 기준을 만들지 않는다. 전자는 실제 수입과 예산 자원의 동일 정의, 나머지는 목표별 배정/거래·보호 목적별 내역과 이체 중복 구분이 추가돼야 확장할 수 있다. 기존 혼합 A/B 연결은 격리·거절하고 자동 정정/backfill하지 않는다. 따라서 이번 지원 범위에 남은 임의 POLICY_REQUIRED 결정은 없고, 구1.1의 POLICY_REQUIRED/null은 호환 의미로 보존한다.

새 scope는 기존 JSON에 저장하되 구1.1 HTTP record에는 노출하지 않는다. 새 FE는 revision이 일치하는 `/review.scope`를 복원한다. 구형 FE 저장 뒤에는 범위 확인을 승계하지 않는다. 새 초안은 현재 raw HEAD를 사용하고 금액/기존 가정을 고객이 재확인한 경우만 새 답변 revision·input_version·snapshot·run·연결 receipt를 한 트랜잭션으로 만든다. 실패·지원 월계획 부재는 모두 롤백한다. 같은 요청은 같은 receipt로 재생하고 기존 채택·기록·run은 바꾸지 않는다.

FE는 월 선택·과거 채택 선택·월전체 항목 확인·서버 차액·막힌 이유·새 초안 비교·같은 run의 답변 열기를 연결했다. 최신 HEAD가 따로 있으면 선택한 run의 답변은 편집 초안으로만 열며 저장 시 새 이력을 만든다. 신규 초안 때문에 구결과가 stale로 바뀌어도 선택 월을 유지한다. 미저장 기록은 점검에 섞지 않으며 설명/새 초안을 비활성화한다. 기존 월기록 코치·초점 이동·원응답 보존·현재 채택을 유지했다.

AI는 서버 사실/등록 근거의 ID만 선택하고 자유 문장·금액·도구를 실행하지 않는다. 서버 기본 점검이 우선이며 AI/RAG 장애에도 기록·차액·새 초안은 동작한다. 별도 RAG2자료는 CFPB 현금흐름/목표 도구의 내부 검토 요약이며 공식 원문 인용·독립 전문가 검증·국내 법령 계산이 아니다. 기존 코치는 다음 확인, 새 review-explanation은 정확한 항목 차이와 일반 근거를 설명한다.
