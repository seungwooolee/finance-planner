# RAG 근거자료 점검·보완 조사 준비

기준일: 2026-11-12. 이번 범위는 공유 자료 점검, 기존 조사표의 보완 탭 추가, 개발 준비사항 기록이다. 재무·세법 산식이나 앱/API/DB는 변경하지 않았다.

## 1. 판단

**기존 조사 양식의 범위는 유용하다. 다만 조사 결과 입력과 근거의 버전·검토 상태·질문 연결·검증 사례가 준비돼야 RAG에 사용할 수 있다.** 라이브러리나 자료 개수를 늘리는 작업보다 이 연결을 먼저 만든다.

현재 확인한 결과 입력칸은 아래와 같이 공란이었다. 상품 공시의 기존 참고값까지 없다는 뜻은 아니다. 기존 값의 정확성·최신성은 이번에 재검증하지 않았다.

| 기존 탭 | 조사 대상 | 확인 범위 | 결과 입력 상태 |
| --- | --- | --- | --- |
| 1_세금 조건 | 8개 제도 × 5개 항목 = 40행 | A1:Z46, 결과 D2:O41 | 결과 입력 0/40행 |

따라서 **조사표를 바로 색인하거나 시작 링크만으로 법령·상품 근거가 확인됐다고 처리하지 않는다.** 설계·mock 개발은 병행할 수 있다. 모든 40개 조건·21개 상품 조사가 끝나야 첫 개발을 시작할 수 있다는 의미는 아니다.

`START-*`는 조사 준비용 참조 키다. 승인된 `source_id`, 실제 수집 버전/hash나 법적 근거 ID를 발급한 것이 아니다. 원문 하나에 여러 조항·연도·개정본이 있으면 필요한 만큼 행을 추가해 각각 연결한다. `MAP-*`, `QA-*`, `GAP-*`, `DEV-*` 역시 이 준비표의 행 식별자다.

새 근거의 상태는 ‘미조사’, 질문 연결은 ‘매핑 검토 필요’, 사례는 ‘자료 연결 필요’로 시작한다. 검토자와 실제 근거·실행 결과는 채우지 않았다. 조사 완료와 정책 검토 승인, 검증 통과는 구분한다.

## 4. 먼저 준비할 자료

### 자료 조사 담당

1. 기존 조사표에 공식 원문, 정확한 문서 위치, 실제 URL, 적용 귀속연도·효력, 확인일을 채운다. 못 찾거나 상충하면 해당 상태와 자료를 함께 남긴다.
2. 첫 지원 제도를 하나 선택해 관련 조건·예외·표의 각주까지 조사하고 원문 사본을 보존한다. 시작 링크는 실제 원문·현재 적용 연도가 확인된 링크로 연결한다.
3. 상품 개념은 답변에 사용할 설명과 예외를 공식 자료에서 확보한다. 상품 공시는 종목코드·지표명·단위·기준일·문서 쪽수를 맞춰 비교한다. 총보수와 총보수·비용을 같은 값으로 치환하지 않는다.
4. 출처별 검토자와 다음 검토일을 정한다. 조사 안내의 2026-12-11 재검토 일정은 서비스의 검토 기한이며 법령 효력 종료일과 구분한다.

### 기획·정책 검토 담당

1. 첫 기능을 ‘일반 제도 안내’, ‘추가 조건 확인’, ‘개인 계산’으로 구분하고 지원/미지원 범위를 명시한다. 계산 계약이 없으면 개인 적용 확정이나 절세액을 출력하지 않는다.
2. 근거별로 허용할 주장, 반드시 함께 알릴 제한·예외, 판단 보류 문구를 정한다. 개별 출처의 검토 완료만으로 금융 정책 승인을 대신하지 않는다.
3. 원문 개정·상충·철회·재검토 기한 경과 시 검색 제외와 안내 기준을 정한다. 과거 문서는 과거 연도 질의에 필요한 이력으로 보존한다.

### 개발 담당

1. AI·질문·엔진·상품·절세 작업본의 브랜치/커밋·정의/API를 같은 기준으로 맞춘다. R2 저장·재개·타사용자 차단의 원격 검증은 자료 조사와 별도 작업이다.
2. `item_id`와 Q라벨은 기존 설계에서 확인한 **매핑 후보**다. 실제 필드·정의 버전·대상·기간·단위를 대조한 뒤 연결한다. 설계라벨을 영속 Q-ID로 만들거나 원응답을 덮어쓰지 않는다.
3. `source` → 원문 버전/hash → `chunk` → 허용 주장 → 실제 인용을 추적할 수 있게 한다. chunk 분할은 조항의 예외·단서·표 각주를 유지한다. 개인 원응답·상담 기억은 공개 근거 색인에 넣지 않는다.
4. LangChain의 채택 버전과 기존 Pydantic/HTTPX/OnePort 구조화 출력·timeout·비용 검사의 연결을 확인한다. 기존 R1/R2 서버 권한과 검증기를 우회하지 않는다.
5. embedding/pgvector는 모델·차원·토큰 및 저장 비용·보관 정책·DB 확장 지원을 확인한 뒤 별도로 채택한다. 첫 등록 자료 조회는 메타데이터/SQL 필터로 시작할 수 있다. 실제 embedding·모델 호출은 준비표 작성만으로 승인된 것이 아니다.

## 5. 첫 연결 순서와 완료 조건

1. **계약·mock:** 첫 제도/귀속연도/지원 출력 범위를 고정하고 합성 근거로 조회·미확인·검증 실패·fallback 흐름을 연결한다. 합성 근거를 운영 자료로 올리지 않는다.
2. **작은 실제 근거 묶음:** 선택 제도 한 개에 필요한 조건·예외·공식 원문을 조사하고 검토한다. 원문 버전과 실제 조항을 허용 주장에 연결한다.
3. **질문 연결:** 기존 확인 사실을 대상·기간·단위·정의 버전과 함께 재사용하고, 필요한 조건만 추가 질문한다. 새 답변·가상 조건은 기존 사실을 자동 변경하지 않는다.
4. **등록 자료 검색:** 선택 제도·귀속연도·효력·검토 상태로 필터링해 허용된 근거만 반환한다. 근거 없음·상충이면 결론을 보류한다.
5. **검증·확장:** 아래 사례의 실제 기대 근거와 결과를 기록한 뒤 LangChain 연결을 검증하고 다른 제도로 확장한다. 의미 검색 필요성이 확인되면 embedding/pgvector를 비교한다.

첫 연결의 완료 조건은 다음과 같다.

- 유효한 근거를 정확히 인용하고 필수 조건·예외가 누락되지 않는다.
- 귀속연도·대상·기간이 없거나 맞지 않으면 확인하거나 보류한다.
- 이미 확인한 질문 반복, 새 답변 자동 덮어쓰기, 가상 조건의 실제 사실 승격이 없다.
- 다른 사용자/다른 run, 문서 내 지시문, 가짜 인용, 원장 밖 상품·단위가 다른 비용 지표를 차단한다.
- 근거의 상충·철회·갱신·재검토 기한 경과와 API 지연·실패에서도 기존 결과와 정해진 안내를 유지한다.
- 개인 계산·채택/실행은 별도 서버 계약과 사용자 확인을 거친다. 검색 성공을 계산 가능·추천 가능으로 올리지 않는다.

20개 사례는 기대 행동을 작성한 **미실행 명세**다. 실제 근거 ID가 채워진 뒤 평가한다. 이번에 검색 정확도나 금융 산식이 검증됐다고 보고하지 않는다.

## 6. 이번 작업 검증

- 원격 저장 후 새 탭의 셀 803개를 작성 행렬과 대조해 일치 확인. native Table 범위와 상태 선택 목록을 확인했다.
- 기존 3개 탭의 읽은 범위에서 값·입력 규칙·주석·서식·탭 속성을 수정 전후 대조해 동일함을 확인했다. 원래 조사 내용·기존 상품 참고값은 수정하지 않았다.
- 신규 탭은 기존 회색 헤더와 읽기 쉬운 열 너비·줄바꿈·고정 헤더를 적용했다. 브라우저 사용이 꺼져 있어 Google Sheets 화면 검증은 미실행이다. XLSX 내보내기와 5개 신규 탭의 첫 두 행 미리보기를 확인했지만, 미리보기 도구가 빈 shared-string을 인덱스 `377`로 표시하는 문제가 있어 시각 검증 완료로 판정하지 않았다. 원격 셀과 XLSX 원문의 해당 값은 공란임을 별도 확인했다.
- 저장소 문서 상대 링크 28개에서 누락 0, 후행 공백 0, `git diff --check` 통과를 확인했다. 기존 다른 작업의 CRLF→LF 안내 3건은 오류 없이 출력됐다. 새 문서는 미추적 파일이므로 별도 공백 검사에 포함했다. 이번 앱 테스트·실계정·모델/embedding 호출·라이브러리 설치·DB migration·커밋/푸시·배포는 수행하지 않았다.

다음 작은 작업은 **첫 지원 제도·귀속연도·허용 출력 범위를 결정하고 해당 근거 묶음을 조사·검토하는 것**이다. 자료 조사와 병행해 합성 데이터 기반 검색 계약·검증기 설계를 진행할 수 있다.
