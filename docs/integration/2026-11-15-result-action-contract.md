# 현재 결과의 다음 행동 상담 1.0

사용자 승인: 2026-11-15 기능 1 구현·관련 실모델 검증·PR 작성. 기능 2 자연어 입력 반영과 기능 3 월 코치는 비범위다.

## 입력과 경계

- 새 POST `cases/{case_id}/analyses/{run_id}/result-action`은 인증된 저장 결과만 읽는다.
- `DION-RESULT-ACTION-1.0`: request_key, expected_input_version, input_hash, strategy_id, portfolio_type(null 또는 STABLE/BALANCED/RETURN), comparison_revision, question, allow_model_question.
- run/원응답/정규화 hash는 기존 해설 검증기를 재사용한다. 구성은 같은 run의 서버 저장 revision과 대조한다. null 구성은 명시한 재무안의 원래 기본 구성이다.
- 응답 후에도 소유권·입력 버전·구성 revision을 재확인한다. 변경 시 409로 폐기한다. 미리보기·오래된 결과는 저장/재계산으로 안내한다.
- 고객 발화 전송 동의와 서버 saved-result 허용이 모두 있어야 실제 모델을 호출한다. 금액·원응답·상품 공시 본문은 모델에 보내지 않는다. 모델은 질문의 의미에 맞는 지원 주제와 설명 길이를 선택한다. 실제 문장은 같은 결과의 검증된 사실·사유로 서버에서 구성한다.
- 금액 생성, 신규 금융 계산, 입력 수정, 비교 선택 저장, 채택·월 기록 변경, 금융 거래 없음. 기존 R1/R2 계약 유지.

## 응답과 고객 흐름

현재 결과/선택 구성 표시 → 질문 또는 예시 질문 → 확인된 사실 최대 2개 → 관련 사유 → 다음 확인 1개. 금액에는 기간·result path, 사유에는 reason code를 보존한다. 정책과 상품 일반 개념은 구분하며 기존 등록 근거 조회로 연결한다. 출처 부족/미지원 질문/모델 실패를 정상 답변과 구분한다.

모델 모드는 `DION_RESULT_ACTION_PROVIDER`가 있으면 사용하고, 없으면 기존 `DION_EXPLANATION_PROVIDER`를 따른다. mock/deterministic에서는 명시적인 기본 안내를 제공한다. 기존 OnePort 전송·비용 원장·중복 방지·설정 경계를 재사용한다. 원발화를 로그·분석 이벤트에 복제하지 않는다.

## 완료 기준

1. 실제 SQLite/엔진의 양 재무안과 저장 구성별 금액·입력/선택 버전 일치.
2. 권한·해시/버전·구성 충돌, 응답 중 변경, 미확인/실제 0, 결과 gate, 모델 오류·변조·미지원 질문에서 거짓 확정/쓰기 없음.
3. 질문을 달리하면 관련 주제·다음 행동도 달라진다. 모델 검증은 별도 합성 질문으로 수행하고 모의 검사와 구분한다.
4. 브라우저에서 질문 → 설명 → 근거/입력 확인, 선택 변경 후 답변 초기화, 모바일·키보드·오류 안내 확인.
5. 최소 검사 결과, 실모델 사용 여부, 남은 제한을 인계에 기록. 배포와 원격 병합은 수행하지 않는다.

## 근거 점검

`ecc:research-ops`에 따라 실제 코드·저장 결과를 우선한다. 개인별 이유의 출처는 캡처된 OUT-03/05/06, 상품 일반 개념은 검토 기간이 유효한 등록 corpus다. 등록 문서의 내부 시연 검토를 독립 금융 검증으로 표시하지 않는다. 새 세율·상품 정책·추천 기준은 조사/도입하지 않는다. RAG URL 추출의 Markdown 오염은 원본 링크와 대조하여 주소만 교정하고 인용 원문·효력일·검토 승인 이력은 보존한다.
