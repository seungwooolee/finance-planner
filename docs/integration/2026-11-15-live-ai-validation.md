## 차단 원인과 수정

[원포트 공식 계약](https://oneport.kr/docs/reference/key)은 `day.limit_credits=null`을 하루 한도 없음으로 정의한다. 기존 앱은 이 정상 응답도 확인 불가로 차단했다. `DION_ONEPORT_ALLOW_UNCAPPED_GATEWAY_KEY=true`라는 명시적인 서버 설정에서만 이 값의 사용을 허용한다. 기본 false, 누락/잘못된 타입/0/설정 예산보다 큰 유한 한도 차단은 유지한다. 영속 원장의 예산·건당 예약·호출 횟수·만료·동일 요청 중복 차단·전송 동의·출력 검증은 그대로다. 사용자 비용 위임은 원포트 관리 키의 권한이나 운영 배포 승인으로 확대하지 않았다.

관련 Python `test_oneport_ledger_guard.py` + `test_input_preview.py` **67 passed / 28.39초**, 변경 Ruff·신규 live E2E ESLint 통과. 새 경로에서도 두 번째 호출의 예산 차단과 잘못된 키 메타데이터 거부를 검사했다. FE 제품 코드가 같으므로 이전 성공 빌드는 반복하지 않았다.

## 제출 환경 적용 시 필요한 설정

이번 로컬 검증에는 같은 날 만료되는 단일 영속 원장에 총35,000크레딧/건당2,500/최대14호출을 부여했다. 실제 사용 11회 이후의 예약도 해제하거나 0으로 돌리지 않았다. 기존 운영 원장은 조회/변경하지 않았다.

운영 반영 시 검토할 서버 설정은 아래와 같다. 이것은 **적용되지 않은 구성안**이며 배포 승인과 운영 원장 확인이 필요하다.

```dotenv
DION_ONEPORT_ALLOW_UNCAPPED_GATEWAY_KEY=true
DION_ONEPORT_MAX_OUTPUT_TOKENS=2048
DION_ONEPORT_TIMEOUT_SECONDS=18
```

운영의 현재 예산4,000/예약3,000은 보수적 예약을 반환하지 않는 구조에서 하루 1회 수준이다. 제출 시연에 필요한 횟수와 총예산에 맞는 새 승인 grant/scope를 기존 중앙 원장의 절차로 준비해야 한다. 이번 로컬 검증 예산을 운영 grant로 복사하거나 기존 영수증을 지워 호출 수를 초기화하지 않는다. 입력 도우미는 기존 oneport provider 설정을 상속하며 고객이 문장 전송에 동의해야 실제 AI를 호출한다.

원격 병합·운영 배포·실제 계정/원격 DB 검증은 남아 있다. 기능 3 월 점검 코치는 이 문서의 11회 검증 범위에 포함하지 않는다.
