## 범위와 완료 조건

1. 화면 문구 버전과 immutable 질문 정의를 분리한다. 과거 DION-DESIGN 1.2/1.2.1의 알려진 `ui_presentation_version=DION-FE-COPY-1.1` 유무만 호환 비교한다. 또한 NEW-01/F04/F09+F10+D08/NEW-06의1.2.1 원본 ZIP 경로와 정확히 같은 압축 해제 경로를 명시적으로 호환 비교한다. 다른 문구·선택지·참조 변경은409다. 등록 정의·기존 원응답·revision·run은 수정/삭제하지 않는다.
2. 실제 계정으로 작성한 전체 원응답 저장, 새로고침, 내 상담 재개, 수정·저장 계산, 이전 run 조회·입력 복원을 검증한다. 복원은 편집 초안이며 기존 run/현재 저장본을 자동 덮어쓰지 않는다.
3. 동일 커밋 FE/BE 배포 URL과 배포 ID를 기록하고 공개 주소에서 확인한다. 합성 계정/입력 검증과 팀원의 실제 기기 확인은 구분한다.

로그인 access token은 만료시각과 함께 탭의 sessionStorage에만 보관한다. 비밀번호·refresh token·재무 원응답은 브라우저 저장소에 추가하지 않는다. 만료/로그아웃 시 제거하며 서버는 모든 요청의 소유권을 기존 Supabase 인증으로 확인한다. 장기 자동 로그인/토큰 자동갱신은 이번 범위 밖이다.

금융 산식·질문 의미·정의버전·기존 정답·채택·거래는 변경하지 않는다. 검사와 배포 결과는 실행 후 기록한다.

## 실제 원인과 구현

원격 DB 질문 정의14개를 읽기 전용으로 현행 FE catalog와 대조했다. F03 등은 화면 버전 삽입만 충돌 원인이었고, 1.2.1 추가질문4개는 원본 ZIP 접두어 유무가 달랐다. LIFE-01에는 과거 표시 버전이 이미 등록돼 있었다. 허용한 두 호환 차이 외의 정의 변경은 계속 거부한다. 등록 hash/json과 기존 revision/run을 재작성하는 마이그레이션은 없다.

- `model.ts`: 화면 표시 버전은 별도 상수로 분리. 이미 읽은 원응답 정의를 편집할 때 그대로 보존한다.
- `raw_store.py`: 위 두 차이에만 제한된 비교. 해시·JSON·원문 불변 저장은 유지한다.
- `session.ts`: 탭 범위 로그인 유지, 만료·로그아웃·인증401 시 제거. refresh token은 수집하지 않는다.
- `planner.tsx`: 홈에서도 내 상담 열기, 자동 상담 ID, 답변 저장·계산, 같은 입력버전 run의 기준·추가 확인 복원, 과거 결과 읽기와 명시적 입력 초안 복원. 과거 결과를 열 때 현재 편집값은 바꾸지 않는다. 초안을 다시 저장할 때만 새로운 revision/run을 만든다.
- 브라우저 회귀는 실제 임시 SQLite/API/Decimal 엔진을 사용하고 인증만 MOCK이다. 로그인·원격 DB 성공과 구분한다. 기존 구형 저장 테스트의 삭제된 UI 경로는 새 회귀로 대체했다.

동일 질문의 여러 소유자·기간 원응답 그룹은 임의 최신값으로 합치지 않으며 기존 명시 선택 필요 오류를 유지한다. 별도 그룹 통합·삭제/법정 계산·상품 추천·고객 채택·거래를 이번 수정으로 활성화하지 않는다.
