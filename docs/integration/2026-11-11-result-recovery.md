2. 신규 일반 입력에는 엔진이 요구하는 진단 범위의 자산 확인 상태가 빠질 수 있었다. 현재 계약의 명시 선택을 ‘나의 상황’에도 표시하고 부족한 입력·수정 경로를 안내한다. 미래 가정이나 저장·로그인으로 현재 계산을 막지 않는다. 실제 엔진의 계산된 부분 값만 표시한다.
3. 요청은 20초 제한, 입력 변경 시 취소/요청 순서 검사, 실패 시 로딩 종료·입력과 기존 결과 보존·재시도를 사용한다. 저장 오류는 계산 오류와 분리한다. 성공 후 현재 계산 오류를 비운다. 입력 서명이 달라지거나 서버 `is_current=false`이면 이전 입력 기준으로 표시한다.
4. 자산별 소유자·계좌와 계좌 소유자를 일반 화면에서 연결하며 미완성 연결을 안내한다. 지분/독립 자산 여부와 전체 확인은 사용자가 명시 확인한다. 계산 가정 패널, 초안 저장·복원을 일반 화면으로 이동했다. 스키마 정의 상수만 기존 버전에서 재사용하고 금액·미래 가정을 자동 채우지 않는다.
5. ‘목표 없음’/선택 해제는 목표의 원래 ID·금액·날짜를 비활성 원응답으로 보존한다. 같은 목표 재선택 시 복구하고 계산에서는 제외한다. 즉시 되돌리기에서도 저장된 필드를 삭제하지 않도록 보완했다.
6. 기존 검산 사례와 신규 사례를 같은 격리 경로로 처리한다. 현재 입력이 있으면 교체 전에 확인하고 원래 입력/결과를 탭 메모리에 보관한다. 사례 저장·저장 계산·서버 복원은 차단하며 사례 전환 시 이전 결과/이력을 비운다. 새로고침 후 임시 복원은 제공하지 않는다.
7. `1,000` 등 지원하지 않는 금액 원문은 즉시 오류를 표시하고 기존 입력을 유지한다. 승인된 숫자는 앞의 0/소수 원문을 유지하며 미입력·0·모름을 구분한다.
8. 저장 검사에서 질문 정의의 `option_labels` 변경이 `DEFINITION_VERSION_CONFLICT`를 일으키는 것도 재현했다. 기존 질문 정의는 편집 중 수정하지 않으며 투자 선택의 출처 코드는 응답 보조필드에 기록한다. 과거 정의/선택 이력은 지우지 않는다.
