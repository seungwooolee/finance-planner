# 2026년 절세 시나리오와 최종안

서버의 `planning/tax_scenarios.py` Pydantic 모델이 계산 계약이다. 저장한 현재 결과의 run ID·입력 해시·개인 범위를 확인하고, 귀속연도와 근거가 유효할 때만 계산한다. 2026년 한국 거주 본인, 일용 제외 근로소득만 있는 경우의 국세 시나리오를 지원한다. 기입한 원 단위 연간 확정값만 사용한다. 빈칸, 0, 요건 미확인을 구별한다.

- 연금저축·IRP 추가 납입과 ISA 만기금의 같은 해 IRP 1회 전환은 소득세법 제59조의3과 국세청 안내에 따른다. 월세는 조세특례제한법 제95조의2의 기본 무주택 세대주 사례만 계산한다. 배우자 분리 임차, 복수 과세기간 전환, 다른 소득이 있는 케이스는 근거와 확인 항목을 제공한다.
- 공제 추정과 예상 국세 감소액, 예상 국세 환급액을 구분한다. 납부할 기준 국세와 기납부 국세는 고객이 입력하며, 다른 조건이 같다는 가정을 표시한다. 한 시나리오만 비교하며 공제를 합산하지 않는다.
- 확인한 시나리오는 최종 생성 시 같은 근거와 입력으로 서버에서 재검산해 당시 결과의 해시와 같이 저장한다. 예상 절세액은 단발성 참고값이다. 수령이 확인된 환급금을 사용하는 경우 기존 보유 현금 입력으로 대조하고 중복 수입을 차단한다.

## 사전 판정 기준

1. 같은 저장 결과에서 ISA·연금저축/IRP·월세 일반 질문에 각각 해당 연도의 공식 근거와 필요한 확인 항목을 반환한다. 모호한 귀속연도, 복수 주제, 만료 및 근거 부족은 숫자 대신 확인할 것을 알린다. 세무 시나리오 원자료를 모델에 전송하지 않는다.
2. 공식 경계값과 독립 기대값을 사용한다. 총급여 5,500만원 연금 납입 100만원의 명목 국세공제 15만원, 직후 초과는 12만원. ISA 1,000만원 단일 전환에 기존 공제 대상 900만원을 채운 경우 추가 공제 대상 100만원. 월세 한도와 15%/17%, 국세 여력과 원천징수에 따른 예상 환급을 각각 검사한다.
3. 명시 확인을 거친 동일 run의 계산만 최종 생성에 첨부한다. 타 계정, 현재 버전 불일치, 결과 해시 변경, 누락 데이터는 숨김이나 추정 없이 차단한다. 예전 생성본, 기존 계획 수치, 채택과 월 기록이 유지된다.
4. 결과 화면에서 키보드로 출처와 계산 폼을 열고 오류·계산 상태를 읽으며, 명시 선택 후 생성본을 다시 열어 저장한 시나리오를 확인한다.

## 연결한 경로

- 결과의 절세 카드에서 조건을 입력해 국세를 비교한다. 인증된 현재 결과 전용 `POST /api/be/v1/cases/{case_id}/analyses/{run_id}/tax-scenario`은 원응답을 저장하지 않으며, 비교 결과는 `no-store`로 반환한다.
- `finalizations`는 같은 결과의 원 단위 입력과 계산 지문을 함께 받는다. 서버가 조건과 근거를 다시 계산해 선택한 비교 결과만 생성본에 고정한다. 이전 최종안은 보존하며, 기존 생성 이후 고른 절세안을 포함하려면 같은 결과로 새 검토를 시작한다.
- 채팅은 선택 가능한 등록 세금 주제를 검색해 같은 결과의 확인 항목과 출처를 답한다. 세금 안내와 시나리오 계산은 모델을 호출하지 않는다.
- 확인한 실제 환급액은 현재 금융자산으로 이동한 뒤 잔액과 대조한다. 미래 또는 추정 환급액을 자동 유입으로 등록하지 않는다.

관련 Python 49건과 실제 로컬 채팅 HTTP 연결 검사 1건 통과. 소유권, 적용 귀속연도, 미확인값, 작성 중 시나리오와 최종 생성본, 공급자 호출 0을 확인했다. 전체 신고액·지방세·복합소득, 유료 OnePort, 운영 DB와 배포는 검사 범위에 포함하지 않았다.

로컬 Edge에서 저장한 결과, 연금 공제 근거 링크, 키보드로 조건 입력과 포함 선택, 최종 생성, 저장 결과 재조회를 1건 확인했다. 공식 링크의 표시명이 자료 제목인 것을 반영해 첫 검사의 로케이터를 공식 URL 기준으로 고쳐 한 번 재검증했다. TypeScript, 변경 ESLint, Ruff와 공백 검사를 통과했다.
