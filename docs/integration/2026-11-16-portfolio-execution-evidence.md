# 첫 실행과 채택 이후의 공시 확인

- 첫 실행은 서버 최종 생성본의 첫 계획 월과 실제 배정 상품에 연결한다. 계좌가 명확할 때만 보유 유형을 안내하고, 그 외에는 실행에 사용할 계좌 유형을 한 번 받는다. 입력은 이 조회에만 사용한다.
- 등록 자료의 검토 범위와 효력일, 인용 출처를 그대로 전달한다. 계획 금액은 엔진이 기록한 정확한 원 문자열이다. 거래 조건은 확인할 항목으로 안내한다.
- 월 점검은 기존 월 기록의 채택 ID로 원 분석 run과 등록 공시를 읽는다. 새로 등록된 동일 종목·항목의 공식 자료를 채택일 및 기존 출처 기준일과 비교한다. 기준일·값·출처 중 하나라도 없으면 확인 보류다. 자료의 기준일을 효력일로 바꾸지 않는다.
- 공시 대조는 등록된 최신 자료 기준이다. 새 공시는 공식 근거를 검토해 기존 상품 원장에 반영한 후 조회된다. PR #118의 검토 완료 ETF 공시 23종을 같은 날짜 적용 계약으로 읽는다. 저장된 분석·채택·월 기록과 계산 정책은 그대로 조회된다.

## 판정 기준

첫 월 배정 없음, 계좌 미확인·알려진 계좌, 공식 출처, 기한이 지난 근거, 신규 공시 변경·동일·기준일 미확인, A 기준 옛 월과 B 현재 채택의 분리, 다른 계정 조회 차단을 검사한다.

## 검사와 운영 범위

- 실행 조건과 공시 비교 API는 인증된 읽기 전용이다. 재무안 선택, 계산, 채택, 월 기록에 쓰기 요청을 보내지 않는다.
- 등록 공시는 발행자와 거래소 자료의 승인된 날짜·링크만 조회한다. 실시간 DART 수집, 증권사 계좌나 거래 연결, 외부 AI 전송은 사용하지 않는다.
- 기존 월의 A안, 이후 현재 채택 B안, 날짜가 지나기 전 보류하는 합성 공시, 적용 가능한 공식 등록 ETF 공시를 로컬 API에서 검증했다. 관련 Python 5건과 Ruff 검사 통과.
- Edge 대표 경로 1건 통과. 로컬 FastAPI·임시 SQLite의 저장 최종안을 열고 키보드로 첫 달 상품 보수, 계좌 조건, KRX 결제 근거를 확인한 뒤 명시적으로 채택해 월 점검의 공시 기준을 확인했다.
