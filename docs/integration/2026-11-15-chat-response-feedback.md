# 채팅 응답·재시도 개선: 구현 전 기준

- 사용자 요청: 전송 즉시 내 말풍선, AI 대기 말풍선 `…`, 긴 응답 지연과 반복 오류 해결.
- 운영 원장 확인: 실패는 CHAT_REPLY_UNGROUNDED / RESPONSE_RECEIVED. 생성은 됐으나 엄격한 출력 검증에서 거부됐다. 고객 원문/거부 답변은 조회하지 않았다.
- 기대: 전송 즉시 입력창 비우기, 새로 작성 중인 다음 문장 보존, 실패한 문장은 대화 안에서 보존/명시 재시도, 실패한 문장을 다음 요청/저장에 중복 포함하지 않기.
- 재시도: 네트워크 유실은 동일 request key로 조회/재사용, 검증 거부처럼 확정 실패만 명시 새 요청으로 재생성. 자동 유료 반복 없음. 서버 operation에 request key를 포함해 확정 실패의 영구 재사용을 방지한다.
- 지연: 검증된 GPT-6.1 Terra에 낮은 reasoning effort 지정, 짧은 답변 지시. 금융 엔진 계산·구조/금액/주입 검증은 유지한다. 실제 속도는 호출 결과로만 보고한다.
- 검사: 지연 중 즉시 말풍선/점/작성 보존, 실패 후 재시도 중복 없음, 확정 실패 새 시도/네트워크 같은 시도, 금액·주입 검증 회귀. 기존 도구만 사용한다.

## 변경·계약 인계

- 사용자 문장을 전송 즉시 표시하고 입력창을 비운다. 응답 대기 중에도 다음 문장을 작성할 수 있으며 응답/실패가 다음 작성 내용을 지우지 않는다.
- DION 대기 말풍선에 점 세 개와 접근성 상태를 표시하고 6초 뒤 지연 안내를 추가한다. 동작 줄이기 설정에서는 애니메이션을 정지한다.
- 실패 문장은 대화 안에 남기고 `다시 요청` 버튼으로 재요청한다. 실패/대기 문장은 후속 모델 history와 결과 저장 history에 포함하지 않는다.
- 기존 DION-CHAT-2.0 성공 DTO는 유지한다. HTTP 503 detail에 `code`/`retryable`을 제공한다. CHAT_REPLY_REJECTED는 명시 재시도 시 새 request_key, CHAT_REQUEST_UNCERTAIN은 같은 key를 사용한다. 요청 내용이 달라지면 기존 fingerprint 규칙에 따라 별도 요청이다.
- durable operation digest에 request_key를 추가하여 이미 거부된 응답의 영구 재생을 방지한다. 같은 key 재전송은 계속 같은 operation이며 자동 유료 반복은 없다.
- 기존 GPT-6.1 Terra에 reasoning_effort=low와 짧은 응답 지시를 적용했다. 공식 OnePort chat 문서와 인증된 models의 supports_effort=true를 확인했다. 다른 모델에는 이 옵션을 강제하지 않는다.
- 출력 구조·금액 grounding·확인 전 입력 불변·금융 엔진/채택 경계는 유지한다. 모델 응답은 여전히 검증에서 거부될 수 있다.

## 실제 검사

- `pytest -q tests/be/test_chat_only.py`: 17 passed. 확정 실패의 동일 key 재사용/새 key 재시도, 불확실 실행, 기존 금액·주입·소유권 검사를 포함한다.
- 변경 Python Ruff: fixture import 이름 충돌 1회 수정 후 통과. TypeScript와 변경 FE ESLint 통과.
- 실제 OnePort 합성 질문 3건: 서비스 소개, 월급/생활비, 현금 선호+채택 완료 주입. 모두 구조/근거 검증 통과, 6.625 / 6.188 / 4.782초. 4,325 tokens / 3.0175 credits. 기존 운영 승인 scope의 원장을 사용하고 고객 실데이터를 보내지 않았다.
- 금액 사례에서는 후보 1개만 반환했다. 두 사실을 모두 추출했다거나 모든 문장에 대해 성공한다고 주장하지 않는다. 기존 결과/채택 변경 없음.
- 로컬 브라우저 최초 실행은 Next 캐시 manifest 오류와 페이지 load 90초 초과로 본문 assertion 전에 실패했다. 소유한 서버만 재시작하고 기존 캐시는 로컬 백업으로 보존했다. 번들 브라우저가 없어 설치된 Edge 채널을 사용한다.
- Edge 재실행도 가용 메모리 약 200MB인 환경에서 완료되지 않아 소유한 Playwright/서버 프로세스만 종료했다. 새 E2E 시나리오는 미통과/미검증으로 인계한다. 테스트가 통과했다고 보고하지 않으며 로컬 캐시 백업은 커밋에서 제외한다.
- 전체 E2E, production build, 이번 수정의 운영 화면 검증은 미실행. 실제 모델 측정은 현재 로컬 코드에서 운영 공급자를 호출한 결과이며 배포본 UI 확인과 다르다.
