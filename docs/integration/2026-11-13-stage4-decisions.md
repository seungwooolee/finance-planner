# 4단계 결정 사항 (2026-11-13, 사용자 위임)

사용자가 남은 결정을 Claude 의견대로 진행하도록 맡겼다. 아래가 그 결정과 적용 위치다.

## 1. 비교 점수 — 그대로 확정

가중치 총보수·비용 40 / 거래비용 10 / 공시 신선도 20 / 추적오차 15 / 유동성 15, 순위 확정 기준은 완성도 85% 이상이다. `product_scoring.py`의 상태를 `REVIEWED_FOR_PREVIEW`로 올렸다.

- 비용 비중을 가장 크게 둔 이유: 같은 지수를 추종하는 ETF끼리 장기 성과 차이를 가장 확실하게 만드는 공시 값이 비용이다.
- 85%를 유지한 이유: 추적오차·유동성(30점)이 비어 있는 지금 상태로는 순위를 '확정'으로 보여주면 안 된다. 두 값을 카탈로그에 넣으면 자동으로 COMPLETE가 된다.
- 점수는 화면 비교용이고 배분 금액을 바꾸지 않는다.

## 2. 3유형 대표 슬롯 — 제안대로 확정

안정형 = PREF_LEAN_STABILITY, 중립형 = PREF_BALANCED, 위험추구형 = PREF_LEAN_RETURN. `portfolio_types.py` 상태를 `REVIEWED_FOR_PREVIEW`로 올렸다.

- 안정형을 PREF_STABILITY로 하면 슬롯이 비어 카드가 항상 0원이다. 비교 정보가 없어서 '다소 안정' 슬롯(단기채 30%)을 쓴다.
- 위험추구형은 더 공격적인 PREF_RETURN 대신 PREF_LEAN_RETURN을 쓴다. 비교 화면이 고객을 더 높은 위험으로 끌지 않게 보수적인 쪽을 골랐다.
- 고객 본인의 위험 한도는 그대로 적용된다. 화면(`portfolio-choice.tsx`)은 다른 유형 카드에 "같은 위험 한도에서 이 유형이면 얼마 검토·얼마 미배분"을 보여주고, 선택은 본인 유형만 가능하다.

## 3. 절세 계산 — 원 미만 절사, 다른 공제 먼저, 팀원 외부 대조

[TAX-01 계약](../tax-engine/TAX-01-contract.md) '결정' 절 참조. 정답 10건은 엔진과 별개인 산술 검산을 통과했다. 외부 대조(국세청 모의계산)는 RAG 조사 팀원 담당이고, 끝나야 엔진을 시작한다.

## 4. 실제 모델 — 예산·원장 위치 (권장 설정, 아직 적용 안 함)

운영 설정 변경과 유료 호출은 이 결정으로 실행하지 않았다. 켤 때 아래 값으로 시작한다.

| 항목 | 값 | 이유 |
| --- | --- | --- |
| 원장 위치 | Render 영속 디스크 `/var/data/dion/oneport-ledger.sqlite3` | 지금 인스턴스는 디스크가 없어 재시작하면 원장이 사라진다. P0 보호가 그 상태의 호출을 막는다 |
| `LEDGER_PERSISTENT` / `LEDGER_ID` / `LEDGER_SCOPE` | `true` / `dion-oneport-prod-1` / `RENDER_DISK_SINGLE_WORKER` | 원장 파일이 바뀌면 ID 불일치로 차단돼 예산이 초기화되지 않는다 |
| worker | 1개, 인스턴스 1개 | SQLite 원장은 여러 호스트에서 공유되지 않는다. 늘리려면 중앙 PG 원장 승인 필요 |
| `MAX_CALLS` | 하루 100회 | 공모전 시연·내부 테스트 규모. R1·R2·RAG 선택이 같은 예산을 쓴다 |
| `BUDGET_CREDITS` | 게이트웨이 단가 × 100회, 일일 하드캡을 같은 값으로 | 단가를 아직 모른다. 게이트웨이 하드캡이 확인돼야 `gateway_daily_cap_verified`를 켠다 |
| `EXPIRES_AT` | 매일 23:59 KST | 하루 단위로 다시 승인 |
| `ALLOW_MESSAGES` | 시연 계정만 `1` | 고객 원문 전송은 동의 화면 연결 후 |

적용 순서는 [4단계 기록](2026-11-13-stage4.md) 1절이다.
