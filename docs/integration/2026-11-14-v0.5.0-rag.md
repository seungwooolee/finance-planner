# v0.5.0 — 저장 결과의 상품·절세 근거 설명

기준: PR #37 추가진단 완료 `9a706f3`. 사용자가 두 버전을 함께 요청하여 v0.3.0에서 별도 브랜치/PR로 진행한다. PR #37은 검토 준비이며 병합은 사용자에게 남긴다. v0.4.0 후보 확대를 전제하지 않고 현행 상품 후보·정책을 사용한다.

## 계약·완료 조건

- 기존 explanation router의 `POST /cases/{case_id}/analyses/{run_id}/portfolio-evidence`를 추가한다. 요청은 `DION-PORTFOLIO-EVIDENCE-1.0`, request_key, expected_input_version, kind, target_id, topic, tax_year뿐이다. 자유문장·수치·외부 URL·고객 추가 사실은 받지 않는다.
- 저장 run 소유권, 현재 입력버전, 원응답/normalized/hash 연결을 기존 R1 검증으로 확인한다. 상품은 저장 OUT-06의 기본/비교 후보 코드만 받는다. 개인 적용 판정은 `NOT_ASSESSED`, 금융 결과 변경은 false다. 응답에는 run/version/hash/target/topic/조회시각과 기존 `DION-SCHEME-EVIDENCE-1.0`이 포함된다.
- 기존 SchemeEvidenceService·RegisteredCorpus·ID-only selector·인용 검증기를 재사용한다. CON-01/03/05/07은 위험/비용/환율/현금화 일반 설명이고 개별 상품 추천 근거로 과장하지 않는다. 상품 선정 이유와 값은 캡처된 엔진 결과에서 온다. 신규 계산에 공시 문서 ID/URL/위치/공시일/수집일과 현금화 기록을 부가 전달하며 수치·비중·선정·원정책은 바꾸지 않는다. 구버전 snapshot에 없는 메타데이터는 현재 catalog로 채우지 않는다.
- 세금 8개 카드와 TAX-01~08의 명시 매핑이다. 고객 관련 이유는 기존 taxCards의 확인된 원응답/정의버전 기준을 재사용한다. 귀속연도는 사용자가 선택하고 개인 적용 자격·절세액을 생성하지 않는다. 세금 카드는 빠른/정밀 최종 탭에만 한 번, 상위3개와 나머지5개로 중복 없이 표시한다. 미확인 정보의 반복 목록은 제거한다.
- 클릭 때만 근거 POST를 실행하며 진행 중 중복 제출 방지, timeout/취소/재시도, 잘못된 run/hash/대상/인용 거부를 제공한다. 패널 열기·렌더·상품 비교만으로 모델 호출하지 않는다. 근거 실패에도 진단 결과는 보존한다.

## 고정 평가 기준

정상: 문장→인용→source/chunk/hash/버전/공식 URL/효력일과 조회시각을 추적하고 현재 금융 결과가 동일해야 한다. 근거 없음·상충·만료·공급자 장애·허위 인용·문서 지시문 주입은 기존 fixture/기대값을 유지하여 설명 보류·비노출을 검사한다. 타인 case, 다른 run의 버전, 오래된 run과 요청 중 입력 변경은 거부한다. 실모델 품질은 mock/등록 템플릿 검사로 증명하지 않는다.

## 비범위

새 상품·세법·세율·비중 정책·개인 자격 판정·실제 주문·운영 DB·배포·유료 호출·신규 의존성 없음. 기존 운영 corpus의 승인/유효기간도 변경하지 않는다. 등록된 자료가 유효하지 않으면 설명을 보류한다.

## 검증

- 관련 pytest: `tests/be/test_portfolio_evidence.py tests/be/test_rag.py tests/planning/test_product_allocation.py` **82 passed** (8.90초). 기존 금융 정답·배분 보존, 새 조회 권한/run/hash/버전/대상 검증, 근거 부족/상충/만료, 기존 공급자 오류·인용 불일치·주입 차단을 검사했다. 실제 법령 타당성/실모델 품질 검증은 아니다.
- TypeScript와 변경 FE/E2E 파일 ESLint **통과**. Ruff는 import 순서와 fixture 참조를 정리한 뒤 통과했으며, fixture alias 도입 때 생긴 빈 줄 1개는 해당 파일만 수정·검사했다. 전체 검사는 반복하지 않았다.
- 첫 Edge 실행 **3 passed / 2 failed**. 통과: 서비스 장애→인용 불일치 차단→명시 재시도와 저장 진단 보존, 미확인 금액을 보존하는 모바일 제도 안내, 자격4상태 표시와 다른 case/버전 거부 fixture.
- 실패1은 제품 테스트 입력에 OUT-06 요청이 없어 카드가 없는 상태였다. 원 fixture를 바꾸지 않고 테스트 헬퍼에 해당 출력만 요청하는 옵션을 추가했다. 실제 엔진 조회로 상품78개/후보2개 출력을 확인했다. 실패2는 dialog 제거 전에 opener.focus가 실행되어 초점 복귀가 막혔다. dialog.close 후 복귀하도록 수정했다.
- 실패2건만 재검증했으나 모두 기능에 진입하기 전 Next 개발 서버의 HTTP500으로 실패했다. 로그: `.next/dev/static/chunks/app/layout.js` open `UNKNOWN (-4094)`. 이 실행으로 위 두 수정의 브라우저 성공을 주장하지 않는다.
- 작업에서 시작한 FE3340 PID39168의 소유권을 확인하고 자식 프로세스와 함께 재시작하려 했으나 자동 승인 검토가 명령 전체를 `blocked by policy`로 거부했다. 구체 이유는 제공되지 않았고 종료/재시작은 실행되지 않았다. 반복 우회하지 않았다. FE3340과 테스트 BE8340(launcher20472/server29444)은 이 시점 남겨 두었다. 기존 다른 서버는 건드리지 않았다.
- 모바일 미확인 안내·상태 표시 fixture의 스크린샷을 직접 확인했다. 정상 상품/등록 세금 근거의 최종 스크린샷은 위 서버 오류로 미확인이다. 실패 trace는 `artifacts/v0.5.0-ui/recheck/`에 로컬 보존하며 커밋하지 않는다.
- 전체 Build/Core/E2E·실계정·원격 DB·유료 모델 호출·배포 **미실행**. GitHub PR의 기존 Core workflow는 별도 자동 실행 결과로 구분한다.
