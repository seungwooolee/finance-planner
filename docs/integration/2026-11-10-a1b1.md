# 2026-11-10 A1·B1 결정 반영·실제 검사

승인 근거: 사용자가 앞선 선택표에 대해 “A1·B1으로 진행”을 명시했다. 보호부족 우선 보충과 허용 유연납입 우선 검토만 확정됐다. 고객별 감액 실행·세율·서비스 보호최소·H·최종 투자벡터·두안 전체 생성은 일괄 승인되지 않았다.

## 이번 구현

중심 명세 `docs/financial-engine-spec.md` 7절에 확정 상태·규칙·입출력·독립 사례를 기록했다. 새 `docs/dion/09_UPDATED_FILES/tools/allocation_policy.py`는 기존 funding_ledger의 원천/월/현금 검사를 직접 재사용한다. 원장·옛 고정정답은 변경하지 않았다.

- A1: 단일 고객설정 보호목표의 가용 CASH 확보액과 부족을 계산한다. 기존 보호납입은 한 번만 인정하고 남은 예산에서 추가 보충한다. 기초 보호부족이 있으면 신규 월투자 상한0, 신규 일시투자도 차단한다. 기존 유지투자는 임의 중단하지 않는다.
- 월 모델에서는 보호금 완성 당월의 입출금 순서를 모르므로 잔여는 현금으로 둔다. 다음 기간 기초부족0인 새 입력에서 투자 예산상한을 계산한다. 권장투자액은 null이다.
- B1: 목표부담과 기존납입이 충돌하면 허용 유연납입 검토와 부족액을 먼저 반환한다. 항목·금액이 명시되고 고객허용/계약/세금·비용 영향/프로필버전/최소유지/감액한도가 맞는 시나리오만 재계산한다. 자동 항목 선정·감액 실행은 없다.
- 목표/보호 연결 납입의 감액·비용/세금 영향이 있는 감액·비현금 보호 적격성·복수보호목표는 이번 작은 단위에서 지원하지 않는다. 보호/목표 동시부족의 전체 우선순위도 미정이다.
- `financial_contract.py`의 전체생성 보류 사유를 DEC02_NOT_APPROVED에서 DEC02_FULL_GENERATION_POLICY_INCOMPLETE로 바꿨다. A1/B1 부분 승인과 전체 미완성을 구분한다. 산술은 동일하며 엔진 버전은 DION-CURRENT-0.1.1이다.
