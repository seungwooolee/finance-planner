# v0.11.0 — 미리보기 결과 상담과 로그인·저장 연결

## 사용자 흐름

`내 결과, 다음에는 무엇을 확인할까요?`에서 저장 전에도 질문한다. 비로그인 상태는 엔진 근거의 기본 안내이며, `저장 없이 로그인하고 AI 질문 해석 이용`으로 로그인하면 문장 전송 동의를 선택할 수 있다. 실제 AI 사용 여부와 기본 안내/fallback은 응답 출처로 표시한다.

`로그인 → 결과 저장 → 상담 시작`은 사용자가 누른 저장 의도에만 연결한다. 로그인 취소 시 저장하지 않는다. 로그인 후 현재 캡처 입력으로 새 상담을 만들고 원응답·계산·선택 구성을 저장한 뒤 질문 입력으로 돌아온다. 기존 고객 상담을 덮어쓰지 않으며 예시는 `test-preview-` 상담으로 분리한다. 질문과 선택한 구성은 유지한다. 질문의 전송·AI 호출은 별도 답변 버튼으로 실행한다.

부분 저장이나 응답 유실은 동일 상담 ID·요청 키로 재개한다. 입력이 바뀌면 캡처 저장본을 편집 중 입력에 적용하지 않는다. 다른 로그인 세션에 기존 저장 의도를 재사용하지 않는다. 자동 계획 채택·금융 실행·기존 기록 변경은 없다.

## API 계약과 보안 경계

- 기존 `POST /api/fe/v1/preview` 응답에 `input_hash`, `result_sha256`을 추가한다.
- 공개 `POST /api/fe/v1/preview/result-action`: 기본 안내 전용. AI 전송 요청은 401.
- 인증 `POST /api/be/v1/preview/result-action`: 기존 bearer 검증과 AI 제공자·예산 원장을 사용한다. 동의 없이는 기본 안내.
- 요청 `DION-PREVIEW-ACTION-1.0`: request_key, 캡처 document, input_hash, result_sha256, strategy_id, portfolio_type, question(1~600자), allow_model_question. 추가 필드·모호한 타입·공백 질문 거부.
- 서버가 기존 순수 엔진으로 캡처 입력을 다시 계산해 두 해시를 대조한다. 클라이언트가 만든 결과나 금액을 받지 않는다. 계산·정책이 달라진 결과는 409로 거부한다.
- 결과 설명은 기존 검증된 사실/문구와 연결된 질문·결과 이동만 사용한다. AI는 질문의 주제·설명 길이만 선택하며 수치·금융정책·도구 실행 권한이 없다. AI에는 질문 문장과 주제 목록·문맥 해시만 전달한다.
- `storage=NOT_SAVED`, `PREVIEW_RESULT`로 근거를 구분한다. 실제0·모름·미입력·부분 결과 구분과 기존 엔진 정책을 유지한다. 저장 결과가 필요한 공식자료 요청은 상품 결과 화면으로 안내한다.
- 미리보기 원응답·질문·결과는 DB에 저장하지 않는다. 인증 요청의 응답 중복 방지 캐시는 기존 상한128/5분 방식이며 공개 요청은 해당 캐시를 점유하지 않는다. 외부 AI 사용 영수증은 기존 중앙 원장에 남는다. 응답은 no-store.

## 검증

- Python 관련 API/결과 상담: 47 passed. 실제 엔진과 일회용 SQLite, 합성 인증/모델로 검증.
- TypeScript, 변경 파일 ESLint, 변경 Python Ruff 통과. 최종 Webpack production build 통과.
- Edge 6 passed: 미리보기3 + 기존 저장 결과 상담3. 키보드 초점, 390px 가로 넘침/캡처 육안 확인, 로그인 취소/질문 유지, 저장 응답 유실 후 동일 키 재시도, 별도 테스트 상담1건 생성, 선택 구성 유지, 저장 없는 인증 질문과 동의 전달, 기존 오류/근거 이동을 확인했다.
- 최초 정적 검사에서 렌더 중 ref 접근을 state로 바꿨다. 최초 Edge의 미리보기 답변 초점1건 실패는 렌더 완료 후 effect로 옮겨 1회 수정·재검증했다. 최종6건 모두 통과했다. 엔진 정답·검사 조건은 변경하지 않았다.
- 새 미리보기 경로의 실제 유료 모델 호출, 실제 운영 로그인/원격 DB, 스크린리더 음성 출력은 미실행이다. 기존 모델 연결을 재사용하지만 이번 합성 제공자 검사와 실제 모델 사용 확인을 구분한다.
- 운영 로그인/원격 DB·운영 배포는 이 검증 범위가 아니다. 기존 실모델 결과를 새 경로의 실제 호출 결과로 간주하지 않는다.
