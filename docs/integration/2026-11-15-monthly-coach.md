# v0.10.0 채택 계획에 연결된 월 점검 코치

채택 계획과 실제 월 기록을 불러와 다음에 확인할 한 가지를 안내한다. `ecc:api-design`, `ecc:react-patterns`, `ecc:security-review`, `ecc:e2e-testing`, `ecc:frontend-a11y`를 적용했다. [계약](2026-11-15-monthly-coach-contract.md).

## 고객 흐름

로그인한 저장 결과 → 6. 실적·사후점검 → 실제 기록 임시저장/점검 완료 → 저장한 월 점검 기준 보기 → 선택 질문·AI 전송 동의 → 다음 점검 안내 → 기록 필드/연결 기준/할 일로 이동 또는 변화가 있는 답변에서 새 초안 준비.

화면은 기록 당시의 채택·입력버전·기록월·revision을 표시한다. 이후 다른 계획을 채택해도 과거 달의 기준을 바꾸지 않는다. 채택 없는 일반 기록, 아직 기록 없음, 일부 기록, 실제0, 미입력, 계획 월 불일치, 연결 충돌을 구분한다. 저장하지 않은 편집값은 AI 근거로 쓰지 않고 저장을 안내한다. 계정/채택/기록 변경과 요청 종료에 따른 오래된 응답을 폐기한다.

계획과 실제 금액을 별도 목록으로 함께 보이되 **차액·달성률 비교는 기존 계약의 POLICY_REQUIRED로 보류**한다. 같은 의미라고 승인되지 않은 계획/실적 항목을 자동 대응시키지 않으며 첫 계획 월을 다른 달의 대체값으로 쓰지 않는다. 추가 계산·배정·수익률·세액·금융 실행은 없다.

## AI와 보안

GET은 인증된 저장 사실만 읽고 외부 호출하지 않는다. POST는 서버가 허용한 행동 ID 하나를 선택한다. 응답의 hash·ID·추가 필드를 검증하며 서버 문구로 안내한다. 모델은 금액/새 정책/자유 문장/임의 도구를 생성할 수 없다. 요청 전후 저장 기준 hash가 다르면409로 폐기한다. 소유권, 엄격한 입력 형식, 최대700자, 같은 요청 키 충돌409, 프로세스별12회/분·최대128개 진행/완료 요청, 완료5분 이후 지연 정리를 적용한다. 기존 영속 모델 원장·예산·예약·만료·중복 전송 방지가 유지된다.

명시 동의 시 질문과 최소 기록 상태·허용 행동만 전송한다. 저장 금액·메모·보류 사유·할 일의 사용자 문구·고객 식별자는 모델에 보내지 않는다. 질문에 사용자가 직접 쓴 내용은 전송되므로 입력란에서 이를 안내한다. 미동의/연결 실패는 기본 안내, 검증된 실호출은 AI 안내로 구분한다. AI 선택은 기록/채택/원응답/재계산/거래를 쓰지 않는다.

운영 설정 `DION_MONTHLY_COACH_PROVIDER=oneport` 또는 기존 `DION_EXPLANATION_PROVIDER=oneport` 상속과 기존 허용된 grant가 필요하다. 예제의 기본값은 deterministic이다. 이 변경에는 설정 적용·배포가 포함되지 않는다. [실호출 설정과 기존 운영 제한](2026-11-15-live-ai-validation.md)을 함께 확인한다.

- 관련 Python: 월 코치 + 기존 월 기록 + OnePort 예산 경계 **73 passed / 48 deselected**, 111.10초. 제외한 항목은 명시적 로컬 PostgreSQL 검증용 매개변수다. 타인 접근, stale/race, 악성 모델 출력, 동의/중복, 0/미입력, 원장·채택 불변, 원래 채택 고정, 데이터 최소화를 포함한다.
- TypeScript·변경 ESLint 통과. Ruff import 정리 후 재검증 통과. 초기 안내 초점 처리 보완을 반영한 최종 Webpack 생산 빌드 통과.
- 합성 실모델 probe **2/2 통과**: 누락 금액 기록/보류 할 일 확인. 실제 `ONEPORT` 응답과 기록 불변 확인. 실제 Edge 상황 변화 안내1건도 통과해 월 코치 실호출은 **3/3**이다. 총1,576토큰·2.2077크레딧(약4.42원), 관찰4.344~5.389초. [안전한 영수증 요약](2026-11-15-monthly-coach-live-evidence.json). 앞선 입력/결과 상담과 합쳐14회·9,328토큰·13.6173크레딧(약27.23원)이며 기존 로컬 grant의14호출을 모두 사용했다. 원장을 초기화하거나 예산을 갱신하지 않았다.

- Edge 화면 고유 **9경로 통과**: 월 코치3개(실호출 포함), 기존 자연어 입력3개, 결과 행동 상담3개. 키보드 초점·레이블/상태 안내·390px 모바일·0/미입력·저장 전 편집·stale 응답·오류 후 동일 키 재시도·원래 채택/기록 불변을 확인했다. 모바일 캡처도 육안 확인했다.
- 최초 월 코치 경로의 버튼명 공백 선택자를1회 수정했으며, 해당 재검증은 page fixture 시작45초 초과로 중단됐다. 기존 통합 검사와 같은120초로 조정한 환경 재검증에서 통과했다. 기존 결과 상담의 오류 주입 테스트는 prepare의 routing을 건너뛰어 기본 포트로 향하는 문제가 있어 명시적 검증 서버 주소와 응답 상태 보존으로1회 수정·재검증했다. 제품 계산/정답을 바꿔 통과시키지 않았다.
- 변경 ESLint 최종 통과. 최초 추가 ESLint 명령이 루트에서 실행돼 설정을 못 찾은 것은 frontend 작업 폴더에서 바로잡았다. 무인증 HTTP401 거부도 확인했다. 실제 운영 인증/원격 DB/금융기관/스크린리더 음성 출력은 이 검증 범위 밖이다. 키보드·DOM 상태 안내와 모바일 검증은 수동 스크린리더 적합성 인증을 뜻하지 않는다.
