# 공개 가상 사례 2개

시작 화면과 진단 하단의 공개 사례 선택에는 사회초년생과 은퇴기만 있다. 사례 선택은 같은 미리보기 API로 새 답변 묶음을 계산하며, 원래 작성값과 결과는 그 탭에서 복원할 수 있다. 다른 생애단계 질문 선택지는 제품에 유지한다.

첨부 `통합 문서1.xlsx` SHA-256 `7af1ed3bfb763f523af69688780286f3c29c391dd9099b246bb0daa95b5c5bc6`의 전체 워크북은 Sheet1 한 개, A1:B42 문답이다. 은퇴기 답변만 있어 사회초년생은 기존 가상 입력을 유지했다. 은퇴기 원응답에는 Sheet1 셀 범위를 기록한다. 원본 워크북은 커밋하지 않는다.

- 가구 범위(본인·배우자·자녀)와 동의 미선택, 월 500/300/10만원, 금융자산 총 5억원과 세부 미입력, 본인 100% 주택 10억원, 대출 잔액 1억원/월 원금 0원/이자 50만원/별도 비용 없음, 투자 관련 응답을 보존한다.
- 11월 13일에는 작업 기준 연도 2026을 명시했다. 목표 시점·금액, 대출 소유자·납부일·잔액 기준, 납입 계좌, 공란인 예정 지출은 추정하지 않는다. 현재 보호자금 1,000만원은 보관 자산 참조가 없어 사례 설명에 표시한다. 비상자금 총목표 1,000만원과 운영 목표 실제 0원은 답변에 반영한다.
- 동의·세부 정보가 없는 만큼 관련 결과는 엔진의 확인 대기 상태를 유지한다. 임의 연금 소득, 현금 계좌, 목표 준비금, 승인 기록을 만들지 않는다. 계산 산식, API, 운영 DB를 변경하지 않는다.
- 종전 사례는 기존 고정 정답과 스냅샷 자료로 보존하고 공개 목록에서는 제거했다. 기존 Playwright는 `NEXT_PUBLIC_SHOW_REVIEW_TOOLS=true`의 검토 도구 안에서 같은 고정 자료를 연다. 검토 도구를 공개 환경에서 활성화할 필요는 없다.

로컬 타입·변경 파일 ESLint 통과. 실제 미리보기 어댑터에 은퇴기 변환 입력을 전달했다. 최초에 목표 소유 범위와 납입자 계약의 키가 누락되어 INVALID_INPUT이었던 부분을 빈 값으로 한 번 보완했다. 최종 응답은 PARTIAL, INVALID_INPUT 이슈 0건(OUT-02/06 NEEDS_INPUT, OUT-03/04/05 NOT_SUPPORTED)이다. 동의 미입력·금융자산 상세 미입력·대출 원금 실제 0원 상태를 확인했다.

Edge의 실제 브라우저·Next·FastAPI 검사에서 공개 목록 2개, 사례 전환 시 실제 입력 분리, 첨부 숫자와 미입력 전송, 390px에서 전환 및 원래 작성값 복원 1건 통과. 첫 브라우저 실행은 Next의 캐시 파일 읽기 오류로 중단했다. 작업 서버를 정지하고 캐시를 ignored artifacts에 보관한 뒤 1회 재확인했다. 이때 기존 상품 자료로 검증하는 연관 투자 전망 경로는 초기 페이지 로딩이 시간 초과되어 본문 미실행이다. 이를 더 반복하지 않았다. 백엔드/DB 변경, 배포 없음.
