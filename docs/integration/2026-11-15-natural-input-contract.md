# 자연어 입력 확인 도우미 1.0

사용자 2026-11-15 기능 2 개발·검증·PR 위임. `ecc:api-design`, `ecc:security-review`, `ecc:frontend-a11y` 적용.

- 새 POST `cases/{case_id}/agent-sessions/{sid}/input-previews`, `DION-INPUT-PREVIEW-1.0`: 요청 키·예상 상담 버전·1500자 이하 문장·AI 전송 동의. 기존 11개 필드에서 선택 결과가 지원하는 최대 5개 후보만 조회한다.
- 기존 bearer 인증/상담 소유권·진단 hash·상담 버전·만료·일시 중지·확인 대기 상태를 호출 전후 검사한다. 422는 계약/입력 오류, 409는 기준/동일 키 충돌, 429는 60초 재시도 안내다. 응답은 no-store.
- 모델은 허용 필드와 원문 안의 정확한 문장/값 표현만 선택한다. 서버가 span과 완전한 값 토큰을 대조하고 기존 Decimal 정규화·필드 enum을 사용한다. 출력에 임의 도구·URL·SQL·금융 계산/반영 지시를 받지 않는다.
- 단위를 생략하면 추정하지 않고 선택을 요구한다. 실제0/모름/미입력/보류/거절/해당없음을 분리한다. 다른 사람·가구·세전·가정·상대 증감·정정/부정 표현은 최종 실제 답변을 다시 묻는다. 소득 300→350 같은 정정은 최종 350만원 문장으로 다시 제안하고 기존 답변 충돌 화면에서 확인한다.
- 원문과 후보는 임시 미리보기이며 로그/분석/DB에 새로 저장하지 않는다. 중복 방지 결과는 프로세스 메모리 최대 128건, 재사용 만료 기준 5분(다음 요청에서 만료 정리), 상담별 분당12건이다. 다중 인스턴스의 전역 제한은 아니다. OnePort에는 명시 동의한 문장과 필드 정의만 보내며 durable ledger에 draft를 보존하지 않는다. 서버 saved-result 전송 허용도 필요하다.
- 고객은 후보별 필드·값·단위·기간·본인 여부를 검토/수정하고 기존 Turn으로 제출한다. 기존 확인 화면에서 충돌을 확인하고 CONFIRM/REJECT한다. 이 제출부터 기존 상담 기억 정책(임시30분/명시 저장7일)이 적용된다. 최종 기록은 고객이 직접 검토한 구조화 응답이며 원문 span은 미리보기에서만 제공한다.
- 확인은 CONSULTATION_ONLY/NOT_APPLIED다. 원응답 저장/재계산/채택/거래는 호출하지 않는다. 진단 자동 반영, OCR/계좌 연결, 고객/기간 추론, 기능3 월 코치는 제외한다.
- FE는 명시 label·error 연결·원문 escape·키보드 버튼·후보/확인 제목 초점을 사용한다. 네트워크 실패는 문장을 유지하고 같은 키 재시도, 기준 변경은 응답 폐기. 입력/계정 변경 시 소유 컴포넌트를 초기화한다.
- 모델 모드는 `DION_INPUT_ASSISTANT_PROVIDER`, 없으면 기존 `DION_EXPLANATION_PROVIDER`. 미설정/실패 또는 미동의는 제한된 표현의 기본 후보와 구분해 표시한다. 기존 원포트 비용·동의·게이트웨이 방어를 유지한다.

완료 기준: 원문 span/단위·0/미확인·복수 후보·정정 되묻기, 권한/버전/만료/반복/모델 변조·미동의 전송 차단, 고객 확인 전후 원응답 불변, 키보드/모바일/오류/정정·취소 브라우저 경로. 실제 모델은 별도 합성 문장으로 검증하고 모의 결과와 분리한다.
