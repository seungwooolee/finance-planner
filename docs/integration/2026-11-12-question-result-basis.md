# 질문 흐름 점검과 결과 근거 표시

## 범위

사용자 확인에 따라 다른 작업에서 해결한 F03 저장 충돌은 제외했다. F03 저장 코드·질문 정의·DB·BE·엔진·API 계약을 수정하지 않았다. 3번 투자구성·상품 / 4번 절세·AI 상담 재배치는 제안 상태로 유지한다.

## 질문 점검

- 현행 계약의 빠른 기본11개는 NEW-01, LIFE-01, F11, F03, F04, F06, N01, N02, NEW-04, F12, F13이다. 관계/생활과 목표/날짜/금액을 묶어 기본8개 카드로 표시한다.
- 부동산 보유 true일 때 F08을 활성화하고 N01 카드 안에서 시세·지분을 입력한다. 채무 보유 true일 때 채무 상세 카드1개를 추가한다. 없음/미입력에 상세를 강제로 펼치지 않는다.
- 정밀 경로는 기본13개 카드, 채무 상세 해당 시14개다. 빠른 완료를 진입 조건으로 사용하지 않는다. 확인된 답변 객체를 공유하며 전환 때 새 답변을 생성하지 않는다.
- F15, NEW-08, F16, NEW-10, F18, F17은 기존 투자 검토 단계에 유지한다. 응답 완료와 최종 상품 적합성 승인을 구분한다.
- 실제0(KNOWN/문자열0), 모름(UNKNOWN/null), 미입력(NOT_ENTERED/null)의 복원·정규화 구분을 확인한다.

## 구현

`result-basis.tsx`와 `results.tsx`에 현재 현금흐름·자산/채무·목표·두 후보의 펼쳐보기 근거를 추가했다. 현재 편집 문서가 아닌 `ViewResult.source` 및 엔진이 반환한 normalization/source_refs를 사용한다. 계산 당시 기준일·답변 기간·질문 정의·입력 버전·정책 버전을 표시하며 현재 답변 수정으로 돌아갈 수 있다.

현금흐름에는 세후소득, 입력 지출, 지출에 포함된 상환/이체, 별도 확인한 상환액을 엔진이 정규화한 정수 원 문자열로 표시한다. 화면은 금액을 다시 계산하지 않는다. 정보가 없으면 추가 확인/원상태를 표시하고 0으로 보충하지 않는다. 예시300/210은 엔진에서 생활비160·납입 반영 월 잔여90으로 계산됨을 대조했다.

두 월 후보의 기존 원장 및 상품/절세의 조건부 안내를 유지한다. 이전 입력 결과를 보고 있으면 근거도 이전 계산 기준임을 표시한다. 미래 가정은 해당 결과에 캡처된 confirmation의 설명과 적용기간을 표시한다.

## 검증

- TypeScript 통과. 전체 ESLint 오류0, 새 테스트의 불필요한 disable 경고를 제거한 뒤 해당 파일 ESLint 통과.
- 기존 원응답 저장 검사6개 통과(임시 SQLite): 상태 구분·부분 응답·원문/단위 왕복·스냅샷 보존·명시 지우기·빈 상담.
- 기존 overlap 실제 Edge 경로1개 통과14.7초: 모바일, 정밀 진입 버튼, 빠른/정밀 전환, 답변 재사용, 사례 격리/원래 입력 복원. 사례를 불러오면 기존 구현상 빠른 모드로 전환하므로 정밀 직접 진입 후 전체 수동 작성 경로의 완주와 동일한 검사는 아니다.
- 새 API/컴포넌트 검사1개 통과: 질문11/카드8·조건부9·정밀13/14, 실제 엔진에서0/모름/미입력, 저장 스냅샷 형태의 복원(signature 동일), 현재 편집값999와 이전 결과의 소득300을 분리. 컴포넌트 정적 렌더 검사이며 실제 계정/원격DB 저장 검증이 아니다.
- 격리 production build 통과: logs/question-basis-build/frontend에서 webpack, 검사용 복사본의 cpus=1·webpackMemoryOptimizations=true·NODE_OPTIONS=--max-old-space-size=512 사용. 실행 중인 원본 서버와 앱 설정은 보존했다.
- 새 근거 패널 실제 Edge 검사1개 통과(전체17.5초, 경로9.7초): 사용자 실행 FE3103 → BE8202 실제 계산 → 사회초년생 결과 → 월 현금흐름 근거 펼치기 → 요청 입력 버전·소득300·기준기간 표시 → 소득 질문 복귀/기존300 유지. 스크린샷도 확인했다. 이 새 패널 검사는 데스크톱이며 별도 모바일 근거 패널 검사는 미실행이다.
- 확인 주소: http://127.0.0.1:3103/dion. 기존3102는 이전 상품 통합 빌드이며 새 근거 화면은3103에서 확인한다.

실계정·원격DB와 F03 충돌 해결 여부는 이번 검증 범위에 포함하지 않는다. 최신 BE 환경에 DB 설정이 없어 실DB 검사는 실행하지 않았다. 이미 통과한 전체 엔진·상품 검사와 대규모 E2E를 반복하지 않는다.
