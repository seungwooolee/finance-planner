# 채택 계획 월 점검 코치 1.0

사용자 기능 3 개발·PR 및 api-design/react-patterns/security-review/e2e-testing/frontend-a11y 적용 위임. 기존 DION-PLAN-CHECKIN-1.1의 원기록 채택 고정·원 단위 문자열·부분기록·비교 정책 보류를 유지한다.

- GET `cases/{case_id}/checkins/{month}/coach`: 인증/소유권을 확인해 저장된 기록 revision, 최초 채택, 현재 채택, 채택 run/input hash, 동일 월 계획 행을 함께 읽는다. 저장 전 편집값은 포함하지 않는다. 월/항목이 다른 금액을 억지로 대응시키지 않고 차액/달성률은 null이다.
- POST 같은 경로, `DION-MONTHLY-COACH-1.0`: request_key, expected_context_sha256, question(최대700자), allow_model_context. 전후 hash 대조·동일 요청 재사용·키 충돌409·프로세스별 제한429·no-store. 새로운 기록/채택/재계산/거래를 쓰는 도구가 아니다.
- AI는 서버가 허용한 다음 점검 ID 하나만 선택한다. 값/문장/도구/새 정책은 생성하지 않는다. 명시 동의 시 질문과 최소 상태/허용 행동만 공유하고 메모·보류 사유·고객 ID·원 금액은 전송하지 않는다. 사용자 문장은 지시 권한이 없는 데이터다. 실패/미동의는 기본 안내와 구분한다.
- 계획 없는 일반 기록, 미기록, 부분/DRAFT, CLOSED, 0/미입력, 소득 초과 기록, 보류 할 일, 상황 변화, 채택 변경·오래된 진단·다른 계획 월을 구분한다. 부분 기록을 성공/실패/수익률로 판단하지 않는다. 완료 체크와 금액은 독립이다.
- 고객이 다음 행동을 선택하면 기존 기록 필드/계획 기준으로 초점을 옮기거나, 변화가 확인된 경우 기존 답변 편집 경로에서 새 초안을 준비한다. 기존 채택을 자동 변경하지 않는다. 알림·장기 대화 저장·금융기관 연동은 제외한다.
- FE는 저장된 월 기록 기준을 표시하며 편집값을 저장하지 않은 경우 안내한다. 계정/월/채택/revision 변경 시 기존 응답을 폐기한다. 버튼·질문/동의 label·loading/error/status·키보드 초점을 제공한다.

검증: 기존 실제 엔진/SQLite/Playwright를 재사용한다. 원장 불변, 기존 채택 유지, 타인/버전/변조/동의/중복/오류·재시도, 일반/부분/완료/채택 변경/월 불일치, 키보드/모바일을 확인한다. 실모델과 모의 검사를 구분하며 운영 계정/원격 DB/배포는 별도다.
