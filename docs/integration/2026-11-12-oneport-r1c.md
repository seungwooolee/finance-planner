## 원포트 요청·검증

POST /chat/completions, Bearer 인증, 지정 모델, `stream=false`, `max_tokens`, `response_format=json_schema`/`strict=true`를 사용한다. transport schema는 엄격 객체 구조를 유지하고 일부 공급자가 거부하는 길이 제약만 뺀다. 서버에서는 기존 Pydantic 길이 제한과 **동일한 validate_and_render**를 모두 적용한다. 라이브러리·HTTP 자동 재시도, 모델 자동 교체, 도구 호출, 자유 상담을 추가하지 않았다.

`x-gateway-ignored-params`에서 구조화 출력·출력 제한이 무시되거나 구조화 출력이 단순 힌트로 변환되면 차단한다. max_tokens→max_completion_tokens 변환은 허용한다. 다른 모델·잘린 출력·도구/거절·중복 JSON 키·NaN·크기 초과·잘못된 run/금액/의미는 기본 설명으로 대체한다. 기본 설명도 기존 검증기를 통과한다.

GET /models의 지정 모델·chat endpoint·단가를 확인하지만 이 목록만으로 구조화 출력 지원을 선언하지 않는다. 실제 응답의 계약/의미 통과는 `OBSERVED_VALID`로 기록하며 **그 요청의 관찰**이다. 공급자 내부의 모든 JSON schema keyword 집행, 다른 모델·모든 입력·상세 모드의 실호출까지 증명하지 않는다.

## 중복·오류·관측

actor/case/run의 hash, 요청 본문, 모델·주소·prompt/provider/validator 버전으로 영속 operation을 만든다. 새 UI request_key라도 같은 operation이면 검증된 ID 선택을 재사용하고 다시 검증한다. request_key에 연결된 본문이 바뀌면 재시작 후에도409다. 생성 POST에는 같은 operation의 Idempotency-Key를 사용한다.

PENDING/실행불명/실패는 새 키로 자동 재생성하지 않는다. 원포트 status URL은 응답 헤더를 받은 즉시 영수증에 저장한다. /v1/requests/안전한ID 형태만 기록하며 임의 Location/절대URL로 키를 전송하지 않는다. **상태 GET 자동 대사·실패 재시도·관리자 재생성은 이번에 구현하지 않았다.** 미확인 건은 공식 상태 조회 절차로 운영자가 확인한 뒤 후속 작업에서 처리한다.

오류는 인증·권한·잔액·키한도·속도제한·모델·schema/본문·이미 접수·실행불명·연결/응답시간초과·네트워크·서버·출력한도·검증실패·로컬 예산/저장 실패로 나눈다. 응답의 오류 문장·키·고객 값은 로그에 싣지 않는다. 로그/영수증은 모델·상태·request ID·status path·소요시간·사용량·정산 상태를 기록한다. 클라이언트에는 민감한 운영 식별자 없이 provider_usage 요약만 추가한다.

금액은 Decimal/십진문자열이다. `usage.cost_credits`가 없으면 null/UNKNOWN이다. 과금 출력 토큰은 total_tokens-prompt_tokens로 별도 기록하며 completion_tokens와 혼동하지 않는다. httpx의 기존 의존성을 재사용하고 신규 SDK/의존성/엔진 계산 변경은 없다.
