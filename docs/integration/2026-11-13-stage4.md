## 1. R2 자연어 후보 추출 — 실제 모델 연결

코드는 이미 연결돼 있다(`OnePortProposalProvider`, `DION_R2_ONEPORT_PROPOSAL=1`). 이번에 mock transport로 관련 53개 테스트를 다시 확인했다. **실제 유료 호출은 하지 않았다**: 이 환경에는 키가 없고, 비용 발생 호출과 운영 원장 전환은 별도 승인 대상이다(AGENTS.md).

켜는 순서 (운영자):

1. `DION_ONEPORT_ENABLED=true`, `API_KEY`·`MODEL`(gpt-6.1-terra) 설정
2. 원장: `LEDGER_PATH`(영속 디스크), `LEDGER_PERSISTENT=true`, `LEDGER_ID`, `LEDGER_SCOPE` 확정 — 없으면 P0 보호로 호출이 막힌다
3. 예산: `BUDGET_SCOPE`·`BUDGET_CREDITS`·`MAX_CALLS`·`EXPIRES_AT`, 게이트웨이 일일 하드캡 확인
4. `DION_R2_ONEPORT_PROPOSAL=1` (고객 원문 메시지를 보낼 때만 `DION_R2_ONEPORT_ALLOW_MESSAGES=1`)
5. worker 1개로 시작, 합성 계정으로 1회 호출 후 원장 대사

## 2. 상품 포함·보류·제외 사유

OUT-06의 모든 상품에 `explanation`(DION-PRODUCT-EXPLANATION-0.1)을 붙였다. 모델 없이 고정 문구·사유 코드·공시값(기준일 포함)만 쓴다.

| decision | 뜻 |
| --- | --- |
| INCLUDED | 기본 배분 후보 |
| ALTERNATIVE | 조건 통과 비교 대안, 자동 대체 없음 |
| HELD | 공시 근거 부족(보류 15개) |
| EXCLUDED_POLICY | 정책 범위 밖 |
| EXCLUDED_FOR_PROFILE | 고객 답변·자료 기준으로 제외 |

사유마다 `changes_with`(QUESTION / NEW_DISCLOSURE_OR_POLICY / POLICY_DECISION)와, 답을 바꾸면 결과가 달라지는 질문 ID를 준다. 후보 6개는 `evidence_doc`으로 Drive PRD 문서를 가리킨다. 화면(`product-allocation.tsx`)이 이 설명을 표시한다(TypeScript·ESLint 통과, 브라우저 미확인).

## 3. 제도 13개·개념 15개 등록, embedding·pgvector 결정

등록은 0절과 같다. **embedding·pgvector는 지금 도입하지 않는다.**

- 현재 조회는 화면에서 고른 제도·연도로 정확히 찾는다. 자유 문장 검색이 없어서 벡터가 할 일이 없다.
- 29개 문서·99 chunk라 정확 조회로 충분하다. 벡터를 쓰면 질의 전송(개인정보), 비용, 결과 비결정성이 생긴다.
- 다시 검토할 조건: ① 자유 질문을 제도로 자동 연결해야 할 때(먼저 29개 라벨 분류를 R2 모델 후보 추출로 시도), ② 문서가 200개를 넘을 때, ③ Supabase pgvector 확장·권한이 확인됐을 때.

## 4. 후보 순위 점수화·독립 포트폴리오 3유형

둘 다 기준을 먼저 고정했고, 같은 날 사용자 위임으로 확정했다([결정](2026-11-13-stage4-decisions.md)). 돈의 배분은 바꾸지 않는다.

- **점수 (`product_scoring.py`, DION-PRODUCT-SCORING-0.1)**: 같은 역할 안에서 총보수·비용 40, 거래비용 10, 공시 신선도 20, 추적오차 15, 유동성 15점. 같은 입력이면 같은 점수다. 추적오차·유동성은 카탈로그에 공식 값이 없어서 점수에 넣지 않았고, 완성도 70% < 85%라 `INCOMPLETE`로 표시한다. 결과는 OUT-06 `comparison_scores`.
- **3유형 (`portfolio_types.py`, DION-PORTFOLIO-TYPES-0.1)**: 안정형=PREF_LEAN_STABILITY, 중립형=PREF_BALANCED, 위험추구형=PREF_LEAN_RETURN의 기존 검토 슬롯을 쓴다. 고객 본인의 위험등급 한도·손실 구간·필수지출·제한·자금일·공시 신선도는 그대로 적용한다(`limits_relaxed: false`). 예: 균형형 고객 30만원 → 안정형 9만, 중립형 18만, 위험추구형 13만9,230원(손실 시나리오 축소). 결과는 월별 `portfolio_type_views`. 화면 카드 연결은 아직 안 했다.
- 승인할 것: 가중치·완성도 기준(85%), 유형별 대표 슬롯 3개.
