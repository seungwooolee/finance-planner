# OnePort 후보 추출과 R3 첫 비교 계약

## OnePort 재사용 범위

기존 R1의 HTTP 전송·요청/응답 크기 및 시간 제한·모델/가격 사전 확인·단일 호스트 영속 원장·비용 예약·중복 키·오류 코드를 공통 전송에서 사용한다. R1의 해설 프롬프트, 응답 스키마 이름, run/fact 검증과 기존 영수증 키 계산은 R1 어댑터에 유지한다. R2는 ModelProposal 스키마와 같은 서버 의미 검증기를 사용한다. R2 응답에는 발화와 추출값이 포함되므로 원장에는 처리 상태와 운영 메타데이터만 남긴다. 정상 후보를 원장에서 재구성하거나 중복 전송하지 않는다.

## R3 구현 전 범위

- 입력은 기존 R2에서 명시 확인한 `SCENARIO` evidence ID다. 현재 `DION-QUESTION12-ADAPTER-1.0` 개인 진단의 본인 `F03/monthly_net_income_krw`(정의 1.2, 월평균 세후소득) 하나를 지원한다. 기존 질문 어댑터가 이 값을 월평균 소득으로 정규화하며 엔진의 OUT-03에 연결한다. 원값과 가정의 대상·기간은 같아야 하고 원값은 저장 run의 확인된 값이어야 한다.
- 연산은 월 총액 `SET`이다. 입력은 기존 원/만원 십진문자열이며 비교는 정수 원 문자열로 반환한다. 일회성 소득이 제외된 동일 기준기간에 나머지 진단 입력을 그대로 사용한다. 월 저축, 증감 연산, 다중 필드, 일회성 소득·미래 소득에 의존하는 가정, 다른 어댑터 버전, 자동 진단 반영·채택은 이번 계약 범위 밖이다.
- 상담 `/scenario-proposals`에 evidence ID를 제출하면 기준 run, 대상, 기간, 변경 전후 값, 단위·가정과 만료가 담긴 proposal을 받는다. `/scenario-confirmations`에 현재 세션 버전, proposal ID/hash, 명시 `CONFIRM`을 제출한 경우에만 기존 질문 어댑터와 전체 엔진을 실행한다. 상담 기억 확인에는 별도 계약을 사용한다.
- 결과는 OUT-03의 기존 납입 후 월 잔여액의 기준/가정/차이와 별도 scenario ID를 반환한다. 상담에 최신 비교 요약 하나를 보관하며 기존 상담 저장 동의에 따라 임시 또는 저장 상담에서 읽는다. 진단 run·원응답·채택에는 연결하지 않는다.
- 완료 조건은 합성 자료에서 300만→350만원 가정 후 기존 90만원이 비교 결과 140만원으로 나타나고, 50만원 차이를 독립 검산하는 것이다. 확인 전에는 엔진을 실행하지 않는다. 만료·중복·낡은 버전·다른 run·미확인 원값·실패에서도 기존 진단을 보존한다.

## 서버 설정과 실제 연결 준비

기본 상담은 기존 규칙으로 동작한다. 합성 mock은 `DION_R2_MOCK_PROPOSAL=1`로 실행한다. 실제 후보 어댑터는 `DION_R2_ONEPORT_PROPOSAL=1`을 선택하고 `DION_R2_ONEPORT_ALLOW_MESSAGES=1`을 별도로 설정해야 발화를 전송할 수 있다. 둘 다 선택하면 OnePort 모드가 우선한다. R1의 저장 결과 전송 설정은 별도로 유지한다.

실제 연결 전에는 기존 OnePort의 허용 게이트웨이·지정 모델·키, 같은 영속 SQLite 원장 절대 경로와 예산 범위, 호출 상한·예약 크레딧·당일 만료를 준비해야 한다. 배포 대상의 영속 디스크와 발화 전송 허용 범위를 확인해야 한다. 현재 후보 어댑터는 저장 run이나 원응답 대신 지원 문장 하나만 전달한다. 실제 모델의 구조화 출력 수용 여부는 아직 검증하지 않았다. [기존 OnePort 설정과 영수증 정책](2026-11-12-oneport-r1c.md)

R2의 중복 키는 서버의 actor/case/session/run 및 발화에 묶인다. 같은 발화는 모델·설정·요청 키가 바뀌어도 같은 상담에서 새 전송을 일으키지 않는다. 저장된 상담 응답은 기존 요청 키로 재조회할 수 있다. 원장에 검증 완료 기록만 있고 상담 반영이 실패했다면 같은 발화를 다시 전송할 수 없으므로 명시 입력을 사용한다. 외부 호출 동안 상담 DB 트랜잭션을 닫고, 결과를 반영할 때 권한·버전·저장 run을 다시 확인한다.

## 사용 흐름과 보관

월 현황 상담에서 월평균 세후소득 가상 조건을 먼저 확인하고 ‘월 잔여액 비교 조건 보기’를 선택한다. 화면에 나타난 전후 값·기간·대상·가정을 확인한 다음 ‘이 가정으로 월 잔여액 비교’를 선택한다. 서버는 15분 내 proposal과 현재 세션·run·입력·엔진 버전을 확인하고 동일한 전체 입력의 복사본에서 F03 소득만 교체해 실행한다. 이미 확정한 요청 키를 재전송하면 기존 상담 응답을 반환한다. 새 키로 소비된 proposal을 보내면 거부한다.

비교 요약은 `EPHEMERAL` 또는 `SAVED_WITH_SESSION`으로 표시한다. 저장 상담 전환 시 비교 요약도 상담에 보관된다. `application_status=NOT_APPLIED`는 원응답·현재 진단·채택과의 관계를 나타낸다. 엔진 전체 결과와 새 진단 run을 영속화하는 API는 이 계약에 포함하지 않는다.
