# FE 두 번째 피드백 — 구현 계약

기존 로컬 dion에 직접 반영한다. 질문 1.2 원문·버전과 기존 계산 정책은 유지한다.

- 공통: 금액 환산 표시, 빈 입력창, 숫자 제한, 즉시 선택 취소와 되돌리기, 지출 카드, 개인 범위 중복 확인 제거.
- 고양이: 사용자 첨부 이미지와 기존 브랜드 원본을 로컬 에셋으로 사용한다. 우측 하단은 선택형 입력 도움말이며 AI·상담원 연결로 표시하지 않는다.
- 로그인: 기존 Supabase 인증의 이메일/비밀번호 로그인을 연결한다. 비밀번호는 인증 요청에만 사용하고 토큰은 탭 메모리에만 보관한다. 회원가입·비밀번호 재설정·소셜 로그인은 이번 범위 밖이다. 서버 저장의 기존 접근권한 검증을 유지한다.
- F03 추가 필드 `one_off_income_krw` / `one_off_definition_version=DION-ONE-OFF-INPUT-1.0`: 한 달 총소득에 이미 포함한 일회성 금액. 원 상태·단위·표기를 보존하고 재합산하지 않는다. 미래 반복소득 자동 추정은 하지 않는다.
- F08 추가 실행 계약 `real_estate_definition_version=DION-REAL-ESTATE-INPUT-1.0`: `real_estate_assets`에 asset_id, type, market_value_krw(원응답 금액 필드), valuation_status(CONFIRMED/ESTIMATED), valuation_on, owner_refs, ownership_share.percent(선택 범위의 소유 지분 문자열)을 저장한다. `real_estate_coverage=complete/partial`을 별도 확인한다. 기존 1.2의 상세 실행 계약 없는 응답을 자동 승격하지 않는다.
- F08 전체 시세 × 확인한 지분을 기존 정수 원·지분 검산에 연결한다. 기준일·소유 범위·금액·누락·중복을 검증한다. 반올림 정책이 필요한 원 미만 지분은 보류한다. 대출은 기존 채무 원장만 차감한다. 매각·유동화·목표 배정·추정 수익은 추가하지 않는다.

완료 조건: 기존 고정 정답 유지, 부동산 포함 전체 자산/순자산 독립 검산, 현금·월 투자금 불변 확인, 일회성 초과액 거절, 인증 성공/실패/토큰 비노출 검증, 실제 PC·모바일 조작 확인. 라이브 계정 인증과 미실행 검사는 별도 표시한다.

인증 계약 참고: [Supabase Auth 공식 REST 문서](https://github.com/supabase/auth/blob/master/README.md#post-token).

## 반영 및 검증 결과

- 실행 주소: http://localhost:3000/dion / BE 8001. 같은 checkout의 자체 실행 서버만 갱신했다. 테스트 전용 8002는 종료했다.
- 보유 부동산 여부와 상세 입력을 같은 화면으로 묶었다. F08 원질문·필드 상태는 별도로 보존한다. 원응답에 명시한 지분과 기준일이 확인된 경우만 기존 엔진에서 합산한다. 추정 시세 포함 여부를 결과에도 표시한다.
- 개인 범위는 ‘나 혼자’ 선택 자체를 범위 확인 근거로 기록한다. 가족 동의는 유지한다. 목표 취소는 즉시 반영하고 되돌리기를 제공한다. 예시/복원 교체도 팝업 없이 실행하고 바로 이전 작성값으로 되돌릴 수 있다. 미래 가정은 버튼 옆 설명을 확인하고 명시적으로 재확인한다.
- 새 고양이는 홈·로그인, 기존 코치 고양이는 질문 안내·상담 도움말에 사용한다. 이미지 원본을 수정하지 않고 public/dion에 복사했다. 진단 중에는 상담 버튼을 작게 표시한다.
- 로그인 설정 읽기 HTTP200/configured=true. 실제 계정 로그인은 미검증이다. 인증 성공/실패/세션 만료 코드와 로그아웃을 구현했다. 회원가입·소셜 로그인·AI 대화·상담원 연결은 추가하지 않았다. 도움말은 고정 FAQ이며 재무정보를 외부 AI에 전송하지 않는다.
- `.env`와 사용자 `requirements-be.txt`는 작업 시작/종료 SHA256이 같다. 새 ZIP은 만들지 않았다. 종전 v2 ZIP은 이번 로컬 후속 변경을 포함하지 않는 이력이다.

### 실행 검사

1. `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/verify.ps1 -Mode Core`: pytest **388 passed / 7 skipped**, Ruff·pip check·TypeScript·ESLint 완료. skip은 기존 선택 pgserver 의존성 미설치다. 처음 실행은 Windows 서명 정책으로 시작하지 못해 프로세스 단위 Bypass로 실행했다. 처음 ESLint의 dialog ref cleanup 경고 1건은 수정했고 후속 `npm.cmd run lint`는 경고/오류 0이다.
2. 추가한 부동산 저장 왕복 검사 포함 `pytest tests/be/test_question_frontend.py tests/planning/test_property_input.py -q`: **23 passed**. 고정 순자산 252,000,000원 단언을 보완한 뒤 property 파일 **10 passed**, Ruff 통과. 전체 Core 이후 추가된 테스트는 저장 왕복 1개다.
3. `scripts/verify.ps1 -Mode Build`: **통과**. dialog 정리·로그인 안내·상담 버튼 크기 보완 후 최종 Build도 통과했다. 최종 빌드로 FE3000을 재시작했다.
4. `scripts/verify.ps1 -Mode E2E -BrowserChannel msedge`: **28 passed / 1 skipped**. 저장 하네스 URL 환경값을 누락한 항목이 skip이었다. 이후 `DION_TEST_BE_URL=http://127.0.0.1:8002`, `PLAYWRIGHT_BROWSER_CHANNEL=msedge`로 변경 화면과 저장 항목을 골라 **5 passed / 0 skipped**를 확인했다. 이번 턴에 총 29개 서로 다른 브라우저 시나리오가 통과했다. 저장 성공은 모의 인증·임시 SQLite 검증이며 원격 DB 검증을 뜻하지 않는다.
5. 실제 브라우저: 새 이미지 로드, 390px 모바일 가로 넘침 없음, 도움말 열기/닫기·포커스 복귀, 로그인 실패→성공 UI 및 토큰의 JSON/브라우저 저장소 비노출 확인. 입력 중 문자 거절, 금액 원 단위 표시, 일회성 금액 중복 합산 방지, 부동산 포함 총자산과 월 투자금 불변 확인. 두 지출 구역의 computed background는 모두 rgb(255,255,255).
6. 독립 검산: 금융자산 12,000,000원 + 부동산 500,000,000원 × 지분 50% = 자산 262,000,000원. 채무 10,000,000원은 별도 차감해 순자산 252,000,000원. 기존 월 투자 후보 300,000/480,000원과 현금 잔고는 유지한다. 누락·다른 기준일·범위 밖 소유자·중복·원 미만 지분은 확정 전체 합계로 표시하지 않는다.
