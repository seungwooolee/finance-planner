# FE·BE 화면 연결 — 2026-11-11

기준: 통합 브랜치 `903b160`, FE 브랜치 `50c800c`, BE 브랜치 `433f571`. FE와 BE 변경 경로에는 공통 수정 파일이 없어 두 브랜치의 내용을 유지해 병합한다. `main`은 변경하지 않는다.

## 연결 범위

- 가입 창은 `POST /api/be/v1/auth/signup`으로 이메일과 비밀번호만 보낸다. `SIGNED_IN`은 제공된 access token으로 로그인하고, `CHECK_EMAIL_OR_SIGN_IN`은 계정·메일 발송 완료로 해석하지 않고 확인 후 로그인을 안내한다.
- 로그인한 계정의 `GET /api/be/v1/cases` 목록과 다음 페이지를 보여준다. 상담을 선택하면 `GET /api/be/v1/cases/{case_id}`의 원응답·입력 버전·최근 계산 참조를 함께 읽는다. 과거 계산은 현재 입력과 구분하고 조회 자체로 재계산하지 않는다.
- 기존 `/question-analyses` 저장 계산을 유지한다. 별도 버튼은 저장된 원응답에 대한 `/analyses/question-v12` 어댑터 1.1 계산을 호출하며 OUT-02~05만 요청한다. 날짜별 지급 달력은 아직 FE에서 작성하지 않으므로 전송하지 않는다.
- 기존 미저장 미리보기 `/api/fe/v1/preview`는 어댑터 1.0 그대로다. 투자 질문 원응답과 상품 미구현 표시도 유지한다. 가상 사례는 실제 상담 저장 API에 보내지 않는다.

## 검사와 제한

- 로컬 격리본에서 BE 계정·저장·질문 v2 관련 pytest **43개 통과**, Ruff 통과.
- FE TypeScript, ESLint, production Build 통과. 계정·가입 화면의 Playwright 검사는 이 실행 환경에서 Chromium 소켓 생성이 거부되어 완료하지 못했다. 해당 검사는 Windows Codex 또는 브라우저가 허용된 환경에서 실행해야 한다.
- 실제 Supabase 이메일 가입·로그인, 원격 PostgreSQL 소유권과 저장·재열기, Vercel·Render 배포 동작은 이 검사의 범위에 포함되지 않았다. `CHECK_EMAIL_OR_SIGN_IN`은 이메일 수신 보증이 아니다.
- 새 FE는 로그인 토큰을 탭 메모리에만 둔다. 새로고침 후 재로그인하고 내 상담을 다시 조회한다. 복원 시 미래 가정과 확인값은 자동으로 되살리지 않으며 저장된 실행을 읽어 이전 가정을 확인한다.
