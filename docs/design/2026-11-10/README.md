## 앱 적용 전 수정사항

| 위치 | 확인한 내용 | 처리할 내용 |
| --- | --- | --- |
| 대시보드 할일 | 3/4인데67% | 75%로 고치고 숫자·게이지를 같은 완료 데이터로 연결 |
| 채택안/초안 | 채택안은 기존월40+신규30+목표20, 초안에는 월110 | FAST-DEMO-02와 UI-INV-01 전제·입력/계획버전 구분. 기존40·목표20을 유지하며 신규110이면 월60만원 초과. 초안 표시만으로 전제차이가 해결되지는 않음 |
| PC 미입력 | 신규투자·추가현금 빈칸인데 차이-30/-20 | 미입력일 때 차이도 미확정. 실제0일 때만 차이를 계산 |
| 기록 요약 | 소득300·기록배분195·차액105 | 105는 현재 입력만의 차액. 최종잉여·통장잔액·미입력 금액으로 단정하지 않음 |
| 모바일 생활비 | 10일95를 월150과 비교해55만 절약 | 월계획 대비 현재55만 남음으로 표시. 중간기록을 월말 절약성과로 평가하지 않음 |
| 일시금 상태 | PC 투자400 대기, 모바일400 완료 | 같은 고객·계획버전·기준일인지 확인 후 한 실행기록 사용. 여기서는 임의 확정하지 않음 |
| 모바일 주거400 | 보증금 증액 분할 실행 | 주거목표 전용자금 분리와 실제 보증금 지급을 구분. 사건·원천 확인 |
| 성과·연동·저장 | 확률95%, 계좌연동 정상, 자동저장/암호화/인증, 엔진v4.2 | 실제 구현·검증 근거 확인 전 데모 문구로 분리하거나 제거 |
| 법적·세제·사업자 정보 | 자격·세제혜택·사업자/고객센터 문구 | 실제 확인한 서비스 정보로 교체할 때 검토. 이번에 사실로 확인/채택하지 않음 |
| 보험·연금 범위 | 연금저축·청약 등 납입 예시 | MVP 제외범위와 상품/계좌 역할 검토. 질문·추천으로 자동 활성화하지 않음 |
| 차트 | 가로 집행 막대 | 기존 명세에 맞춰 도넛/세로 비교로 적용하거나 시각 규칙 별도 결정 |
| PC/모바일 입력 | 일부 readonly, 저장/완료 정적 | 실제 입력·검증·저장·실패·중복저장·월말마감 구현 필요 |

만원 단위 검산: 월계획150+20+20+40+30+20+20=300. 중간기록95+20+20+40+20=195. 300−195=105 중 미입력 두 항목의 계획합은50, 생활비 월계획 잔여는55다. 산술 일치가 미입력 실적을0으로 확정하는 근거는 아니다.

월간 기록 동작 실험은 [기존 독립 시제품](../../dion/10_UI_PROTOTYPES/DION_Monthly_Checkin_PROTOTYPE.html)과 [요구사항](../../dion/10_UI_PROTOTYPES/MONTHLY_CHECKIN_REQUIREMENTS.md)을 재사용한다. localStorage와 서버DB·권한·계획버전 연결을 구분한다. 상황변화 재검토는 새 초안이며 기존 채택계획을 자동 변경하지 않는다.
